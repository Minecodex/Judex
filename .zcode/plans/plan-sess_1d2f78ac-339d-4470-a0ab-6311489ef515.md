## 1. 技术底座选型（P0 锁定，写入 go.mod/tools 与 LICENSE 记录）

- **PG 访问**：pgx/v5 + 显式 SQL；**sqlc** 生成基础仓储（复杂查询仍手写 SQL）；**Goose v3** SQL 迁移（embed 进二进制，`--mode=migrate` + K8s migration Job 双入口，PG advisory lock）
- **队列**：按 E02 自研——PG `background_jobs` 表 + `FOR UPDATE SKIP LOCKED` + 租约心跳 + fencing_token + 指数退避，**不用 River/Redis**
- **API 契约**：`api/openapi.yaml`（OpenAPI 3.1）为唯一契约源；**oapi-codegen** 生成 Go DTO/server 接口；**openapi-typescript** 生成 TS 类型 + 手写约 300 行 auth/CSRF/幂等/SSE 感知的 fetch client；CLI 的 `pkg/client` 复用生成的 Go 类型
- **密码**：x/crypto Argon2id（memory=64MiB/iters=3/par=1 编码式存储，渐进 rehash）
- **S3**：aws-sdk-go-v2 S3 客户端（自定义 endpoint + path-style，兼容 SeaweedFS/MinIO/外部 S3）
- **CLI**：Cobra；设备授权（RFC 8628 风格 pending/slow_down）+ 浏览器一次确认意图
- **前端**：React Router（顶层路由 /login /register /recover /device /confirm/:intentId /invite/:token /settings + `/` 工作区沿用 query 导航）；TanStack Query（服务器状态）+ Zustand（仅 UI 态）；HeroUI 唯一组件库不变
- **ID/时间**：google/uuid（倾向 v7）；timestamptz；API 层 RFC3339 UTC
- **测试基座**：Go 测试 helper 直接 `docker run` 起 PostgreSQL 17-alpine / MinIO（每测试独立容器、随机端口、结束清理，沿用容器命名 `judex-test-p<kind>` 模式）；不用生产数据
- 工具全部用 go.mod `tool` 指令锁定（go 1.25），`make generate` 统一入口，CI 检查生成物无 diff

## 2. 新后端目录结构（在现有骨架上扩展）

```
api/openapi.yaml                    # 契约源
migrations/                         # Goose SQL（M001–M005 分批，每文件 <2000 行）
internal/platform/{database,clock,idempotency,events,errors}   # Tx/锁序/幂等/事件
internal/infrastructure/{postgres,s3,opensandbox,model}        # 适配器
internal/transport/http/            # 中间件(auth/csrf/principal/project-scope) + 分模块 handler
internal/{identity,project,workflow,discussion,material,work,decision,handoff,agent,job,audit}/  # 领域+应用服务
internal/cli/  pkg/client/          # CLI 命令树 + 共享客户端
skills/judex/                       # 发行 Skill（SKILL.md + references + 宿主适配）
cmd/judex-server (--mode=all|api|worker|migrate + account 运维子命令)
cmd/judex          # 小入口，命令在 internal/cli
tests/{integration,contract,cli,agent,agent/live,e2e,k8s}     # 按计划 10 分层
```

事务纪律贯穿全程：user 行 FOR SHARE → project 行 FOR UPDATE（固定锁序）→ 幂等记录 → expectedVersion/资格校验 → 状态更新+审计+event_seq+outbox 同事务；模型/S3/沙箱调用一律在短事务之外。

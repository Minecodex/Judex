# 会话工作区：UI 与功能整合

状态：用户已选择标签会话台，并要求重新调整整体 UI、梳理全部功能如何进入这一交互。本轮实现可操作的本地前端 Demo，不代表真实 Agent、CLI、生产授权或全部业务模块已完成。

打开当前工作区（历史地址：`http://127.0.0.1:4173/?design=chat`）。原 `/chatbox/index.html` 转到这个入口；早期可直接打开文件的静态草图保留在 `/chatbox/demo-tabs.html`。

## 1. 界面组织

以项目和会话为中心，保持三个区域：

- 左侧：项目、项目主会场、交接讨论、议题列表、搜索、待处理入口、演示身份。创建项目后先配置流程和职位，再安排工作。
- 中间：浏览器式讨论标签、机器人与成员消息、交接卡、材料上传与消息输入。切换标签保留本页草稿和阅读位置；新建讨论不自动改变工作状态。
- 右侧：工作对象和配置。常用入口为计划任务、待处理、资料、团队、流程；切换菜单另包含个人提示词、业务知识、本地 AI 接入说明和项目记录。查看任务或修改配置时，当前聊天不离开。

保留左右分隔线、最小可用宽度、收起恢复、布局记忆、双击恢复、键盘调整和快捷布局。新工作区布局使用 `judex.workspace.layout.v1`，业务复用已有 `judex.work.demo.v4`。不覆盖原静态草图的模拟操作记录。

视觉统一采用浅灰绿导航、白色会话面板、低对比的资料区、绿色操作强调和明确的卡片层级；深色使用对应 token。导航与动作字号、间距、圆角、图标、表单、弹窗统一。新页面 i18n 使用 `src/i18n/chat.ts`，样式使用 `src/styles/chat-workspace.css`。

## 2. 功能放在哪里

| 内容 | 入口与交互 | 本轮实现范围 |
| --- | --- | --- |
| 项目 | 左侧加号创建，点击项目打开主会场 | 创建独立项目、目标与场景；创建人获得管理身份，不自动获得其他人的审批权 |
| 讨论与主 Agent | 中间标签、消息和底部输入框 | 新建讨论、关联计划 / 任务、普通消息、附件、关闭 / 重开讨论；AI 回复为明确标记的演示内容 |
| 计划 | 右侧“计划与任务”切换计划；查看目标与整体验收 | 草稿创建、负责人明确确认、计划范围与条件、任务证据汇总、整体验收入口 |
| 任务 | 卡片树点任务进入右侧详情 | 正式安排草稿、本人上报、交接建议、硬条件、任务最终验收、重开、关联讨论和历史 |
| 卡片树与依赖 | 一张图内显示归属实线和前置虚线箭头 | 从当前模型生成卡片及父子连接；任务依赖和交接来源连到接续任务；无需独立依赖 Tab |
| 交接与退回 | 左侧打开交接为会话标签；卡片在中间 | 逐来源发送、明确接收、带原因拒收、补交和再发送；其他已接收来源保留；接收不是最终验收 |
| 待我处理 | 左侧快捷入口或右侧“需要我处理” | 交接、待确认工作草稿、本人有权的最终任务验收和计划验收入口；引用同一份记录 |
| 成员、职位、机器人 | 右侧团队与职位 | 自定义职位及提示词、绑定具体流程节点、同岗多人、邀请多职位、接受邀请、替换关联人、查看组合提示词 |
| 已有成员任职 | 管理者的“分配职位” | 可为创建人或其他现有成员创建任职身份；不替换已有身份，不改变成员管理角色；拒绝跨项目岗位和重复任职 |
| 个人项目提示词 | 左下设置或右侧切换菜单 | 本人编辑保存；与职位职责区分，私人设置不随换人自动转交 |
| 协作流程 | 右侧流程 | 规则说明、实际 Mermaid 图、节点及岗位挂载、编辑草稿、人工发布、受影响在途卡复核；对话生成图仍为模拟 |
| 资料与依据 | 右侧项目资料、消息附件、任务证据 | 汇集任务、交接、讨论的材料；上传登记形成明确的资料讨论，保留作者和时间，不自动成为正式结论 |
| 业务知识 | 右侧菜单中的业务知识 | 展示“AI 归纳、待验证”的示例和权限原则；真实记忆存储、检索及知识批准尚未接入 |
| 本地 AI / CLI | 左下连接入口或右侧菜单 | 展示主动获取 → 本地工作 → 上报 → 明确确认的路径及未接入状态；不会安装或执行本地工具 |
| 操作记录 | 右侧项目记录、任务详情和交接历史 | 查看现有模型产生的操作者、时间与业务事件；不是生产审计系统 |

管理员、普通成员和受邀人共用同一外壳，按钮按权限出现。邀请未接受前进入受邀界面；接受后进入个人设置。管理职位本身不直接赋予对任意任务的验收权限。

## 3. 尚需深化的内容如何进入

以下明确为下一步设计 / 实现范围，不能因为入口出现就宣称已经完成：

- 多人共同审批：在中间使用带审阅版本、审批位、首人同意后的截止时间与退回原因的提案卡；待处理入口引用同一卡片。现有新模型仅覆盖工作草稿确认及逐来源交接，未把旧模型会签计时机制整体迁入。
- 通用 Bug / 问题反馈：从任务卡或输入框发起问题讨论，保留复现材料、影响任务及修复工作引用；正式新增 / 调整工作继续走提案确认。当前未新增专门 Bug 类型、计划多分支编辑或修复批次界面。
- 仓库、分支、环境与发布上报：放在右侧任务 / 计划的资料引用区。保持用户自定分支和本地执行边界；当前只显示已有任务分支文本与回传资料，未连接仓库或部署状态。
- 任意复杂任务图：当前图按所属计划排列任务与父子缩进，绘制显式前置引用；大规模图的展开收起、跨计划连线、画布缩放和平移、循环依赖诊断需要另行实现。
- 真实平台 AI：在现有消息位置接入讨论流、参与者与依据；当前主子 Agent 并行、OpenSandbox、SQLite 会话、记忆权限、成本和运行恢复均未实现。
- 资料级私密访问、跨项目共享授权、知识批准、CLI 本人授权和并发事务需要服务端支持。本地 Demo 的身份切换用于体验，不构成安全隔离。

以上边界沿用已确认原则，本轮没有自行更改审批主规则或平台 / 本地工作的分工。

## 4. 实现组织与验证

新 `src/workspace` 只负责布局、标签、对话呈现、右侧导航和资料入口，复用 `src/work` 的业务动作及对象。`WorkNavigationScope` 将原详情跳转映射为侧栏更新，讨论跳转映射为会话标签，不复制一份任务状态。

本轮补了新建空项目的流程空态与“先有流程再创建挂载职位”的路径，并新增受管理权限约束的已有成员任职分配。当时保留的工作原型与 legacy 原型现已删除。

验证命令：`npm run build`、`npm test`、`npm run test:e2e`。工作区新增 11 项 E2E，覆盖旧入口跳转、所有面板、草稿保持、交接补交全程、普通聊天边界、邀请与提示词、计划任务草稿、资料登记、新项目配置、主题布局、任务验收和创建人任职。新增任职分配状态测试覆盖权限、重复和跨项目边界。

本轮结果：构建通过，43 项状态测试通过，64 项浏览器测试通过（包含旧原型与静态草图回归）。已查看主会场、交接、团队、流程、个人设置及英文深色截图。构建仍有 Mermaid 相关大分块提示，不影响本地预览，但正式交付前需要评估资源体积。

截图脚本：`node scripts/capture-workspace.mjs`，产物位于 `.runtime/screenshots/workspace-*.png`。当前是前端原型，无生产服务或 Kubernetes 部署，因此本轮不运行 Kubernetes 验收。

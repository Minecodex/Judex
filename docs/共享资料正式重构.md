## 工作关联与资料来源

资料库从后台材料索引分页读取，覆盖单独上传、CLI、任务上报、讨论和平台产物。任务上报的 `taskId`、固定 `materialVersionIds` 与报告说明形成来源记录，服务端解析所属计划并保存当次计划，不要求客户端推送整份任务／计划内容。上传人、时间和来源来自授权主体及服务端时间。

普通资料登记使用 material submission，可选择 `planId` 或 `taskId`。任务与显式计划不匹配、跨项目、不可读版本及已移出资料库的新引用被拒绝。登记留在资料视图，报告留在任务原记录，会话由人明确发起；分享已有资料引用原版本，保留原上传人。

使用记录由 `material_usage_records` 汇总任务报告、提交附件和已确认材料关联，报告与 backing submission 去重。分叉共享原消息，不为继承重新登记使用。上传用途优先，否则展示首次正式提交的说明；后续使用保留当次说明。无法确定的历史来源显示未记录，不伪造来源。

首次正式提交说明取最早非空的 material 登记或 progress／delivery 报告，不让空历史关联或早期聊天替代。讨论草稿保存明确的项目／计划／任务用途上下文，标签切换、右栏收起及最大化恢复它；“当前工作”资料过滤使用同一上下文。会话标签与右栏工具独立恢复，不用入口任务覆盖用户选择。

讨论内浏览器上传表单也使用这一明确上下文。登记失败而原件已上传时，提示重试复用版本和提交；文件、用途与对象在重试期间保持。操作失败按统一语言映射显示。

## 读取与删除

- 项目成员统一可读项目共享资料；计划／任务过滤表示用途，不建立文件读取白名单。私有提示词、凭据和私有运行上下文保持独立。
- 材料首次登记人及当前项目 owner／manager 可以从资料库移除材料。界面展示服务端 `canDelete`，服务端再次校验；删除是浏览器动作，要求当前版本、幂等键和确认。
- 删除记录操作者与时间，移除资料库及新附件选择器中的条目。固定版本原件继续可读，历史消息显示已删除标记，交付、审批和验收引用保持原依据。
- 同名文件不覆盖原版本；派生发布检查来源版本和材料可见状态。原件读流提供真正的单范围 Range、后缀范围及 416，所有读取仍先检查项目成员资格。

## 真实预览

原件 `ready` 表示原件可读。预览另有 `not_requested/pending/ready/failed/unsupported` 状态，由固定版本识别格式，异步生成只读缓存；失败显示原因、重试和下载。

| 格式 | 阅读方式 |
| --- | --- |
| PDF | PDF.js 分页、缩放及实际第一页缩略图 |
| 图片 | 原图缩放及缩略图 |
| Markdown | 安全文本、标题、列表和代码块，不执行文件内 HTML |
| JSON／纯文本 | 格式化源码／原始文本 |
| ZIP | 实际目录，不解压到应用文件系统，非法路径被拒绝 |
| DOCX／PPTX | Office 格式校验后，由独立 LibreOffice 容器生成 PDF |
| XLSX | 导出全部工作表，各表一页，保留原表数据并按页缩放 |
| HTML 包 | 复用既有独立 origin、短时版本能力和 sandbox 预览；未配置时提供原件下载 |

转换容器仅提供内部服务，不持有平台认证、数据库或对象存储密钥；禁止外网出口和文档宏，使用独立临时目录、输入大小、解压总量及运行时间限制。持久预览任务复用既有队列，以 job ID 与 fencing token 防止旧执行覆盖新结果。缓存不会修改原件、共享任务绑定或审批状态。

PDF（含 Office 产物）先做只读结构校验，图片实际解码并限制像素；解析支持取消与资源上限。迁移 26 增加内部缓存校验代次，旧 PDF／图片预览按固定版本重新准备。浏览器读取失败同时反映到卡片和弹窗，重试后恢复；临时网络故障不改写服务端文件状态。

## API 与 CLI

项目材料列表新增当前版本、格式、来源、用途、关联摘要与权限，支持 q、formatGroup、sort，以及既有 linkedObjectType／linkedObjectId 过滤。固定版本详情增加 library 元信息；同版本提供分页 usages、预览状态／准备及预览内容。删除材料要求 expectedCurrentVersionId。OpenAPI、Go 与 TypeScript 类型同步生成。

后续完善补齐原件状态、与相同过滤条件一致的 totalCount、鉴权 contentUrl 和 thumbnail 读取描述；PDF.js 从固定 PDF 第 1 页生成缩略图，文本／目录封面读取相同版本内容。预览缓存完成使用 material.preview.changed，避免与资料用途／删除业务事件混合刷新分页。具体实现与验收见[完善记录](./共享资料完善-20261009.md)。

```powershell
judex material upload .\evidence.md --purpose "用于登录回调核对" --task <任务ID>
judex material upload .\review.pdf --purpose "计划评审依据" --plan <计划ID>
judex report --task <任务ID> --file .\report.json
```

`--task` 与 `--plan` 互斥。未指定工作对象时仍为项目资料。任务报告的 `report.json` 携带 text、identityId（需要明确职责时）、expectedTaskVersion 和 materialVersionIds，进度不代替交付或验收。

上传成功而用途登记失败时，CLI 退出非零并返回 versionId、uploadStatus=ready、registrationStatus=failed；本地持久收据冻结源摘要、版本及原提交键，重试复用版本和关联提交，成功回报 committed。收据按服务器、用户、项目及文件上下文隔离，不包含模型凭据。

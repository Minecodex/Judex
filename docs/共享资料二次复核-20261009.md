## R07：会话标签切换改变了用户明确选择的附件用途任务

优先级：P1。影响使用事实归属，不改变任务本身的正式计划／流程绑定。

实际流程：一个讨论关联任务 A、B，从任务 A 的讨论入口进入；选择已有共享材料作为待发送附件，明确把输入区的“关联工作”改为任务 B；切到另一讨论标签再返回。文字草稿和附件保留，但用途任务恢复为 A。实际点击发送后，材料的使用记录也归到 A。

本次观察：`chosenTask/before=21060b78-82ef-42f8-b3db-96e0299ca4fb`，`after/recordedTask=b8065b6d-a29d-4db8-8cd9-1c8c6deb1480`，原任务所属计划保持不变。这些 ID 属于已清理的隔离验收数据。

原因：[useConversationTabs.ts](../web/src/features/chat/useConversationTabs.ts) 返回标签时将 taskContextId 设为标签的 scopeTaskId；[Conversation.tsx](../web/src/features/chat/Conversation.tsx) 初始化时优先采用该路由值，再读草稿中的 taskId，导致明确选择被入口范围覆盖。

收尾要求：统一草稿与工作上下文的恢复规则，区分首次从工作对象进入和返回既有会话标签；保留明确的空选择、计划及任务选择。回归覆盖多对象讨论、已有资料选择器／弹窗分享、切换标签、收起／最大化和最终实际使用记录。

## R08：损坏 PDF 读取失败，状态仍显示预览已就绪

优先级：P2。

实际上传 81 字节的截断 PDF，包含 `%PDF-1.7` 文件头但没有可读的页结构。服务端预览返回 `status=ready`、`kind=pdf`、contentUrl 和第一页缩略图描述。PDF.js 实际读取失败，弹窗正文显示“读取文件失败／重试”，同一弹窗状态仍显示“原件可读／预览已就绪”。

原件下载和重试入口存在，问题是预览成功状态不真实；不能把这个问题描述为原文件丢失或没有重试按钮。

原因：[file_preview.go](../internal/material/file_preview.go) 的 PDF 检查只判断前 1024 字节是否有文件头，随后缓存原始字节并设为 ready；[MaterialDialog.tsx](../web/src/features/materials/MaterialDialog.tsx) 的阅读器错误仅影响正文局部状态，未同步上方状态展示。

收尾要求：区分缓存已准备与内容实际可阅读，补足损坏文件检查与统一错误状态；客户端暂时网络错误也应与文件结构错误区分。新增截断 PDF 和损坏图片等实际文件回归，保留原件读取。

## R09：空的历史用途记录阻断首次正式提交说明

优先级：P2。此场景使用隔离数据库的有效历史空值夹具，不表示正常部署已经存在相同数据。

实际流程：上传不带用途的原件；在所属隔离数据库创建较早、说明为空的材料关联历史；再通过真实 API 提交说明“第一份正式材料用途说明”。固定版本详情仍返回 `purpose=""`，没有采用已有正式提交说明。

原因：[library.go](../internal/material/library.go) 的用途回退从全部 usage 记录按时间取第一条，再对说明 NULLIF。第一条为空时，子查询直接返回 null，后面的有效正式提交不再参与回退。

收尾要求：明确首次正式提交的来源集合，并在候选查询中处理空值；上传用途仍优先，后续各次使用说明分别保留，确实缺失的信息显示“未记录”。新增空历史记录在前的回归。

## 与 demo3 的视觉一致性

相同：文件格式封面、文件名称与大小／版本、作者与时间、详情／删除、内容和用途双标签、分享后进入待发送区、右栏和消息使用同一固定版本、已删除历史引用。

差异：

- demo 说明约定宽资料页四列；正式资料页采用 auto-fill 和 232px 最小卡宽。本次 1440px 浏览器、1345px 资料网格实际为五列。右栏按可用宽度和 176px 最小卡宽自动变化，也不是固定两列。
- demo 的 Office 排版和表格是示例内容；正式版为真实文件转换的 PDF，属于已确认方案的合理变化。
- demo 可删除所有示例文件；正式版按服务端权限，并保留已删除固定版本的历史阅读。正式分享还要求选择既有讨论及工作上下文，符合正式计划。

本次稳定截图等待真实 PDF 缩略图产生非空像素后再截取，四类 PDF／Office 封面均已绘制。上轮个别截图中的空白封面属于尚未绘制完成的采样，不能将它们当成所有正常 PDF 封面都无法显示。

状态：用户已接受此视觉基准，正式页面与全部业务模块已按同一套主题和共享控件改造。保留现有完整功能入口、多会话/多详情标签、独立设置页；右侧默认保留功能选择页。根目录 [demo.html](../demo.html) 保留为离线视觉参考，正式实现与组件约定见 [统一界面组件规范](./统一界面组件规范.md)。

## 改造前问题与方案

| 范围 | 当前问题 | 预览方案 |
| --- | --- | --- |
| 登录 | 外层入口与表单卡片重复嵌套；440px 固定宽度置于大面积空白中；主要按钮沿用共享适配层默认 `ghost` | 双栏布局：左侧品牌与协作示意，右侧单一表单；登录采用明确的主按钮；忘记密码、注册、密码可见性按使用顺序排列 |
| 项目列表 | 主内容上限 880px；项目名称被放进一条扁平的次级按钮中；角色标签与项目入口缺少信息层级 | 1160px 内容区、项目卡片、项目级角色、成员与讨论信息；筛选与搜索置于同一工具栏；新建项目在标题区固定为主操作；最近讨论提供快捷入口 |
| 项目内部 | 各区控件与信息密度需要统一；阅读与操作层级不够明确 | 保留左侧会话、中央讨论、右侧工作；标签栏顶齐；统一消息宽度、段落间距、AI 建议与提案卡；发送固定在输入区右下角；工作面板支持收起与最大化 |
| 全局 | 字号、间距、颜色与按钮强调程度需要形成共同规则 | 暖灰底、低饱和森林绿、少量项目识别色；统一 Token、HeroUI 语义按钮与一致的字段样式；中文/英文、浅色/深色共享同一结构 |

预览顶部的三页切换栏属于方案审阅工具，不属于正式产品导航。正式项目内入口仍遵循 [聊天协作前端重构](./聊天协作前端重构.md) 的导航和账户菜单规则。

## 独立视觉参考的交互

- 登录表单校验、密码可见性、注册与找回密码的布局，以及直接进入预览。
- 项目筛选、搜索、无结果状态、新建项目、新项目的空讨论状态。
- 新建讨论、切换与关闭会话标签、按讨论保留草稿、Enter 发送和 Shift + Enter 换行。
- 附件名称预览、任务详情、资料查看、示例提案确认和交接接收。
- 工作面板切换、收起、最大化与恢复；偏好设置、中英文和深浅色切换。

所有项目、人员、任务、消息与审批都使用示例数据。新增内容仅保留在当前预览内存中，刷新会恢复示例；附件只展示本地文件名，不上传文件。示例登录不校验真实账号，找回密码不发邮件，提案与交接不调用正式 API。界面保留 AI 建议、人确认、交接接收与最终验收的区分。

## 源码和生成

独立参考的源码位于 `web/design-preview/`；参考样式与 Token 位于 `web/src/styles/design-preview*.css`。依赖复用唯一的 `web/` 工程，通用控件来自当前已安装的 HeroUI v3，图标复用 lucide-react。正式主题位于 `tokens.css`，共享组件位于 `components/ui/Presentation.tsx`、`Button.tsx` 与 `FormControls.tsx`，认证与项目入口、三栏工作区继续使用原正式组件和数据源，没有新增第二套可部署前端。

在仓库根目录执行：

```powershell
node web/design-preview/build.mjs
node web/node_modules/typescript/bin/tsc --project web/design-preview/tsconfig.json --noEmit
```

第一条命令重新生成 `demo.html`，第二条检查独立参考的源码类型。生成文件为 UTF-8；源码文件和生成文件均低于 2000 行。正式落地没有更换组件库或数据源架构，生产与 demo 继续共用 ChatWorkspace 树。

## 已复现的交互问题

### R01：项目资料详情的关联任务按钮不能打开任务（优先修复）

从项目“共享资料”打开用途详情，点击关联任务，URL 增加 `view=task&item=<taskId>`，但仍处于 `tab=materials`；资料库继续显示，任务详情没有出现。

原因是 MaterialDialog 仅调用 `go({view:"task",id})`，项目总览按 hubTab 决定内容，没有切换到任务所在入口。需要使用统一对象导航，并覆盖资料库、计划右栏和任务右栏三种来源；已打开的讨论、草稿及阅读位置仍应保留。

定位：[MaterialDialog](../web/src/features/materials/MaterialDialog.tsx)、[路由状态](../web/src/features/work/storeBase.ts)、[项目总览](../web/src/features/cooperation/ProjectHub.tsx)。

### R02：任务上下文已选中，所属计划仍显示“仅登记到项目”

从任务讨论右侧资料栏打开上传：任务已预选，但计划选项仍为空。服务端最终会正确解析计划，所以这是登记界面的上下文表达错误，不能据此认定关联数据丢失。

UploadMaterialDialog 只在用户手动改变任务选项时更新计划，初始任务未同步所属计划。计划和任务列表也仅读取 `limit=100` 首批，需要补取当前选中对象并支持后续选择，避免较大项目的对象遗漏。

定位：[UploadMaterialDialog](../web/src/features/materials/UploadMaterialDialog.tsx)。

### R03：缺少 demo 中的弹窗“发送到讨论”入口

正式预览／详情弹窗只有下载和关闭。讨论输入区的“选择共享资料 → 添加到消息 → 发送”已实现，但无法像 demo 一样直接从文件弹窗加入待发送附件。

补齐时应沿用现有明确选择的讨论和工作上下文，只加入草稿；由用户发送后登记固定版本的使用事实。不能从项目资料弹窗任意推断目标任务或自动创建讨论。

定位：[MaterialDialog](../web/src/features/materials/MaterialDialog.tsx)、[Conversation](../web/src/features/chat/Conversation.tsx)。

## 与 demo 的视觉差异及其他收尾项

### R04：封面、选择器及已删除引用未完整对齐

- PDF／Office 使用实际 PDF 首页面，图片使用原图，符合真实文件方案；Markdown、JSON 仍是图标与文件名，没有 demo 的源码式封面。ZIP 没有目录数量等封面摘要。
- 正式已有资料选择器只有名称、上传人及大小，诊断确认缩略图数量为 0；demo 是带文件封面的选择卡片。
- 已删除会话附件仍保留完整卡片的信息区；demo 使用紧凑的历史引用条目。
- 1440 桌面默认讨论右栏的两列卡片明显偏窄，文件名截断及时间换行较多。虽然没有横向溢出，仍需对齐 demo 的阅读密度。

定位：[FileCard](../web/src/features/materials/FileCard.tsx)、[MaterialPicker](../web/src/features/materials/MaterialLibrary.tsx)、[资料样式](../web/src/styles/materials.css)。

### R05：原件与预览状态在卡片上表达不完整

存储和接口已经区分原件 ready 与预览状态；弹窗会显示处理中或失败并提供重试。卡片却仅对 pending 显示处理中，failed / unsupported 的封面仍显示普通“预览”，没有明确的“原件可读”状态。应补齐一致的状态提示，原件 ready 不表示预览成功或 AI 已理解。

### R06：契约及历史显示需要补齐或明确调整

FilePreview DTO 返回 status / kind / mime / size / error；内容入口由前端根据固定路径生成，PDF 缩略图在客户端绘制。原计划要求返回缩略图及内容入口，当前没有相应字段或独立缩略图入口。需要补齐契约，或明确记录经确认的契约调整。

历史详情的上传人信息部分位置有“未记录”兜底，但使用记录中的空 actorName / description 等仍会显示空白；尚未统一满足“历史缺失信息显示未记录”。资料数显示当前加载数量，超过一页时不能当作资料库总数。

此外，Markdown 阅读器目前只支持标题、普通段落、列表和代码块；常见的行内强调、链接、表格未渲染。原文仍可读且不会执行 HTML，应如实说明支持范围。

## 合理变化，不应回退

DOCX、PPTX、XLSX 改用真实转换 PDF 阅读，取代 demo 的示例排版、表格和演示页，这是已确认的正式方案。实际 XLSX 第二张工作表及中文内容已在截图中核对。

删除权限不再像 demo 一样对所有示例可用；正式产品依服务端 canDelete 决定。删除后固定版本继续可读、可用于既有交付／审阅，也是已确认的规则，不能改成原型中“已删除即不可预览”的表现。

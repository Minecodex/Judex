# 对等岗位执行

每个群／人／职位对应稳定 RoleAgent；由 `agent/peer` 独立执行，同岗位串行，不同岗位并行。没有协调 Agent，没有 `call_agent`。执行七工具 `read/bash/edit/write/read_context/send_message/publish_file`，不赋予模型管理群、成员或跨群分享的能力。

每次调用重新读取项目、群目的、参考工作流、职位、个人提示词与共享快照。群公共知识由独立服务维护，所有岗位同一版本读取；私人工具协议和租约分别保存。压缩由知识服务统一租约执行，达到最小有效窗口 70% 压缩至 50%，失败暂停并保留原文。

最小窗口包含启用的额度备用模型并预留输出容量；模型或提示词变化后，只有旧摘要也能重压缩，覆盖序号与原文索引不变。`peer/model_calls.go` 统一处理岗位与摘要请求的容量校验、逐次预留及回退；仅明确额度耗尽且尚未产生文字／工具协议片段时转用下一个目标，普通限流和认证错误暂停。每次真实请求单独记账，未知失败成本继续保留，不重置讨论或技术额度。

持久投递有去重键，因果路径按岗位 ID 闭合计轮，各分支共享同一讨论额度。暂停触发并入原讨论，继续增一档，终止以 fence 拒绝旧发布。模型请求前预留完整可能成本，重启保留未知消耗；累计调用／Token 与当前档预算分开。

成员撤销与任职撤销共用取消、fence 和事务内收束检查；只结束没有待执行、运行中或等待人工分支的讨论。保留成员身份而撤销最后岗位也必须收束，重新任职保留岗位身份，但新触发使用新讨论。

工具调用先登记日志，数据库业务效果与完成日志同事务。未知 shell 结果暂停并由岗位本人核对，不能盲目重放。完整算法、额度与例子见 [V2 合同](../plans/v2/CONTRACTS.md)。

执行期限从持久预算起点计算，所有模型、摘要和工具 I/O 继承该期限；流接收使用 Context 取消选择，不能依赖模型主动发送 finish。统一错误出口把耗尽归类为 technical_budget，发言事务用数据库时钟再次阻止过期发布。正常停止、撤权和 fence 变更继续使用既有恢复边界；未知成本与副作用仍须核对。

## 2. 三层存储与信息组织

| 层 | 内容 | 地位 |
| --- | --- | --- |
| 平台 PostgreSQL | 工作、决定、材料元数据、会话、运行事件、执行期上下文（会话窗口、子运行状态、材料索引、检查点与游标）、恢复记录 | 权威持久事实 |
| 项目对象存储共享区 | 已登记原件、版本和已提交的共享草稿 | 项目内统一可读，Agent 挂载只读 |
| harness 内存与单次模型请求 | 当前有效上下文块、查询缓存与消息组装 | 有限工作集，按版本更新，跨轮从 PostgreSQL 重建 |

不为每个运行复制一份业务表，也不维护第二份持久事实副本；执行期状态以每运行行 / 表直接写在 PostgreSQL，唯一写入方是 harness。同一会话续接按检查点与游标恢复。并行子 Agent 的运行状态按 run_id 隔离；同一主会话串行续接，不并发覆盖上下文。

## 3. 目录与计划文件命名

以下路径为示意，具体命名在实现时固定：

```text
/workspace/                             本次运行整体工作区，AI 自由读写
  project/                              本项目共享资料，只读挂载（EROFS）
    common/                             项目公共资料
    plans/{planId}/{materialId}/v3/
      计划名称-页面方案.html
      assets/                           保留 HTML 包内相对路径
    submissions/{submissionId}/         项目直属 / 尚未归计划的资料
  （其余任意目录）                      派生副本、临时分析、待发布产物，结构由 AI 自定
```

项目是共享单位；计划目录或文件名称只是组织方式，不增加计划级读取授权。可读文件名应标识计划、用途和版本，存储键仍关联稳定 ID，避免计划改名或同名文件造成覆盖。

HTML 等材料包内部文件名和相对路径不能被统一前缀重命名而破坏依赖。计划命名作用于包入口或外层目录。一个原件被多个计划引用时，元数据关联同一版本，不复制多份互相漂移的原件。

执行期上下文存于服务端 PostgreSQL，模型工具（read/write/edit/bash 均在沙箱内）物理上接触不到；平台也从不信沙箱内任何本地状态作为业务事实。write/edit/bash 只能操作沙箱工作目录，不能靠改本地文件取得平台认可。

## 4. 项目共享区与物理 Bucket

逻辑上每个项目只有自己的共享资料区；一计划一桶不作为当前设计。

实现方案：内置 SeaweedFS 可采用一项目一 Bucket；外部 S3 若允许创建 Bucket，可以使用相同模式。若外部服务只提供指定 Bucket，可将项目映射为独立前缀，但凭据、挂载根和查询范围必须限制到项目，不能顺带暴露其他项目内容。

物理 Bucket / 前缀映射方式仍是适配方案，Q073 确认的是项目级共享单位。共享区只保存可向项目公开的业务资料，系统不得把私人提示词、密钥、私有运行上下文、完整私有调试记录或临时工作目录自动打包上传。

项目内不再维护逐文件成员白名单。项目退出、跨项目读取、共享区之外的私人配置访问仍然校验。系统产生的私有信息不能借摘要或派生产物自动公开。

## 5. 执行期上下文的 PostgreSQL 承载

2026-09-25 修订：取消独立执行期 SQLite。原拟 SQLite 承载的内容映射到 PostgreSQL（AI 组表为主）：

| 原 SQLite 表 | PostgreSQL 承载 |
| --- | --- |
| context_blocks（岗位 / 流程 / 偏好块） | 直查 position_templates、workflow_versions、personal_position_preferences 等业务表，个人偏好按当前职位和绑定人读取，不复制 |
| work_snapshot | 直查 plans / tasks 正式状态 |
| decision_refs | proposals / approval_decisions 引用 |
| session_messages | messages、run_events |
| delegations | agent_runs（子运行状态） |
| open_questions | 每运行上下文表或运行状态字段 |
| materials / material_entries | materials、material_versions + 挂载可读状态事件 |
| context_manifests / checkpoints | context_checkpoints |

表名属于工程方案。ContextBuilder 每轮以事务快照从 PostgreSQL 读取有效上下文并在内存工作集组装，不维护跨调用的第二份持久副本；高频流式片段在内存缓冲后按合理粒度合并写入 run_events，不逐 token 提交；大输出存对象存储、PostgreSQL 只存引用。

运行上下文集中在 PostgreSQL 后，Pod 重启与 worker 多副本部署不存在运行粘结在某个 Pod 本地文件的问题；工具登记、事件与检查点可与业务事务同库原子。用户输入、正式决定、会产生副作用的工具执行记录及关键产物必须可靠写入 PostgreSQL 后才向用户确认成功。续接按 context_checkpoints 的游标与工作集恢复，不重放整个项目历史；授权、人员绑定或来源版本失效时丢弃受影响的工作集，不能将旧上下文当作继续操作的许可。

## 6. 动态挂载、缓存与可见性

容器沙箱与 Judex 服务运行在同一 K8s 集群，但不放在同一个业务 Pod 中。项目共享区在创建沙箱时以只读 PVC 挂载为 `/workspace/project`（平台按项目管理 PVC，OpenSandbox BYO 模式：首次自动创建、跨沙箱复用、不随沙箱删除）；运行过程中新增版本经活挂载直接可见，而不是每个附件热加一个 PVC。运行中新增对象在挂载内的动态可见性属于 D15 首期 PoC。

内置 SeaweedFS 的原生 Filer / CSI 路径与外部通用 S3 挂载不是同一种适配。外部 S3 需要独立文件系统或缓存层验证，不能直接将任意 S3 endpoint 当成 SeaweedFS Filer。具体驱动、版本、多节点只读能力和性能待 PoC。

只读要同时落实在挂载与凭据 / 网络边界。Agent 不持有原件写凭据或存储管理权限；使用原生 Filer 路径时也不能假定所有请求都会经过 S3 网关授权。挂载动作由可信基础设施完成，不将挂载管理权限交给 Agent。

OpenSandbox 预热 Pool 的卷来自预先声明的模板，不应假定领取预热沙箱时能追加任意项目 PVC。首期建议先验证按项目按需创建沙箱，再评估受控复用，不能预挂全部项目换取启动速度。

共享挂载不意味着目录缓存即时刷新，也不意味着读取没有网络开销。平台登记材料后发出事件，运行层更新材料索引（PostgreSQL / 内存工作集）、刷新必要目录 / 缓存并核实固定版本路径可读。路径尚不可用时明确标记 preparing / failed，不能忽略附件后继续宣称分析完整。

缓存按项目、材料版本和摘要隔离。默认使用索引发现资料，避免每个 Agent 不断递归扫描整个共享桶。挂载驱动和缓存策略未验证前，不承诺具体用户数或并发提升。

## 7. “HTML + 文字”是一份输入

提交记录同时保存用户文字、附件及材料包的 ID / 版本。原件写入对象存储，平台校验后登记，不能把文字和附件拆成彼此无法追溯的记录。

运行上下文（PostgreSQL）记录材料清单和状态；模型每轮输入明确列出本轮附件、用途和可读路径。任务要求检查页面时，不得只分析文字或 HTML 源码后宣称已经检查了视觉和交互。

HTML 的 CSS、图片、脚本保持相对路径；包内缺失资源、外部资源、后端接口或登录态未提供时，展示相应限制。Q072 允许按分析需要在容器沙箱使用浏览器，浏览器不继承生产登录态或额外项目权限。

文件存在、挂载可读、工具返回内容、页面已渲染和交互已测试分别记录。读取日志只能证明工具返回了内容，不能证明模型正确理解；普通 bash 日志也不能自动证明已读完某个目录。

## 8. 派生、编辑与发布

```text
项目共享区固定版本原件（/workspace/project 内，只读）
  → AI 在沙箱内自行复制需要的文件 / 完整材料包到工作区自由目录
  → 修改、分析、Playwright 浏览器检查（全部自由操作，平台不逐文件管控）
  → 调用 publish 工具（声明来源路径、产物路径、说明）
  → 服务端取回产物并校验来源版本：落后即报错，要求取最新版重做；通过则写新版本并登记来源链
  → 作为共享草稿出现在活挂载中，项目内即刻可读
  → 正式采纳 / 接受交付仍按既有决定规则执行
```

首版采用显式复制派生，不引入透明 OverlayFS。工作区对模型的全部契约只有三条：`project` 只读、一切工作在 `workspace` 自由完成、发布调用 publish 工具。发布目标路径由 AI 以项目内相对路径指定（模型可看到挂载结构），平台校验项目归属与路径边界并分配新版本号，AI 不接触全局存储键。未发布的工作区不实时公开，也不自动同步回原件路径。

发布记录至少包含新材料 ID / 版本、来源材料 ID / 版本（来自 publish 的来源声明，全新文件为空）、作者或代表身份、run_id、修改说明、文件清单与摘要。内容完整登记后才发出 available 事件；幂等提交不产生重复版本；来源版本落后返回冲突错误而非静默线性化。

共享草稿不等于正式成果。删除、覆盖原件和修改任务正式状态不是文件挂载授予的权限。原件版本保持可追溯，不以同名覆盖方式吞掉上一次审阅依据。

## 9. 动态上下文构建

每次模型调用前，ContextBuilder 核验身份 / 当前绑定，消费相关持久事件并以事务快照从 PostgreSQL 读取有效上下文（内存工作集复用，无第二份持久副本）组装本轮输入。

逻辑层次：平台执行契约 → 项目已发布流程与节点职责 → 岗位要求 → 当前人的个人偏好 → 工作约定与正式决定 → 异议 / 缺口 / 未返回结果 → 会话摘要与近期消息 → 本轮文字、材料和工具结果。

不同层次按系统指令、状态、用户消息、工具结果等来源保留结构，不把共享文件内容都当作高权限 system prompt。项目流程必须按既定要求在每轮提供有效规则表示，不能只有文件路径而没有必要约束。

- **必带**：目标、身份、硬约束、正式决定、未决异议与仍缺的必要结果。
- **必查**：用户指定附件、当前交付版本、正式约定明确要求核对的材料；标记实际范围和缺口。
- **按需**：本项目共享区其他背景、历史案例与代码细节，可自主搜索 / 读取，不需逐文件授权。

主 Agent 附带的材料清单是子 Agent 的起点，不是其项目共享资料访问上限。共享可读不等于每轮全量加载；选择相关性与读取范围属于分析过程，不能改写业务权限或新增硬条件。

本轮 context_manifest 记录绑定、流程、工作与决定版本、材料版本、消息覆盖、子结果集合、事件游标和模型配置。预算不足时压缩探索或分段分析，不静默截掉硬规则。模型压缩主要处理探索历史，正式事实每轮从权威状态重建。

## 10. 主子协作与连续性

主 Agent 的委派包含目标、工作版本、问题、材料引用、预算和返回要求。子 Agent 的岗位、个人偏好和同议题历史由平台另行组装，不复制主 Agent 的全部会话。

返回包区分结论、依据、异议、缺失项、部分 / 最终 / 失败状态和已登记产物。平台维护预期参与者与执行状态；未返回不是没有意见，失败不是通过。Q067 允许已返回结果先被处理，同一主会话串行消费事件。

Q075 的已提交产物成为项目共享草稿后，其他项目内 Agent 可自行查阅；这不是未经主 Agent 决定就主动发消息、拉人或扩展分工。

恢复依靠平台持久事件和检查点；等子结果期间沙箱保活，等人决定期间 pause 保留工作区现场（不可用时回收重建）。更换绑定人保留业务历史，但前任的私人偏好和私有运行上下文不自动交接。项目成员关系或执行授权撤回时停止 / 隔离旧运行、撤销继续读取的能力；已经提供给模型的内容不能被声称技术上撤回。

## 11. 验收与性能验证

必须验证：

1. 两个本项目身份可读取同一共享文件，不需逐文件授权；其他项目身份不能读取或列出其内容。
2. 私人提示词、密钥、私有运行上下文和临时输出不会自动出现在共享区。
3. 写 / 删除原件失败，派生编辑成功，明确提交后生成可追溯的新共享草稿。
4. HTML 与依赖文件完整，文字和附件保持提交关联；未渲染 / 未测试部分不伪记为已检查。
5. 运行中上传新版本，材料索引、挂载缓存、可读状态与模型输入不混用版本。
6. 子 Agent 部分返回、失败和压缩后续接仍保留异议与未完成事项。
7. 多 Agent 并行运行的上下文按 run_id 隔离互不阻塞；冷启动、上下文读写、目录缓存、实际下载量、PostgreSQL 写入压力和并发内存均有测量。
8. 内置 SeaweedFS 和外部 S3 分别通过挂载、只读、动态可见性和回收测试；沙箱销毁不删除项目共享数据。

不能以挂载成功、上下文入库或模型声称已读完作为性能 / 理解正确的保证。本章采用的挂载适配和具体缓存策略仍须验证。

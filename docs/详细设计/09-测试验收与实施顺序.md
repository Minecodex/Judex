# 09 测试验收与实施顺序

## 1. 实施顺序方案

阶段是交付组织建议，不把完成文档或搭建界面视为业务已验收。

| 阶段 | 交付范围 | 出口条件 |
| --- | --- | --- |
| A 基础工程 | HeroUI 工程、Go/Gin、迁移、接口骨架、Helm 基础组合 | 本地与临时 K8s 能启动并完成依赖检查 |
| B 注册与项目 | 注册登录、自由创建项目、项目成员和邀请、岗位身份 | 平级账号与项目权限的正反例通过 |
| C 工作与决定 | 计划任务、草稿、审阅版本、正式命令、交接与验收 | 状态机、并发、幂等与异常闭环通过 |
| D 讨论与资料 | 会话分页、附件、对象存储、来源引用、事件推送 | 原件登记与正式采纳分离，权限与上传恢复通过 |
| E Agent 执行 | Go harness、四工具、业务工具、上下文、OpenSandbox | 真实模型与沙箱下的调度、隔离、失败恢复通过 |
| F 生产交付 | dev/prod 配置、四种存储组合、备份恢复、升级 | 按确定的可用性和数据目标完成环境验收 |

阶段可有不冲突的并行工作，但业务授权、接口和持久化边界先于依赖这些规则的 Agent 自动化。

## 2. 身份与权限验收

- 两个新账号均可独立创建项目，不存在首个用户自动获得全部项目的业务权限。
- A 创建项目 P，B 注册后不自动成为 P 成员；B 可以独立创建 Q。
- B 接受 P 的岗位邀请后获得明确身份；在 P、Q 中权限分别生效。
- 一人多岗、多人同岗、已有成员任职分配、替换关联人均保持预期身份数量与记录归属。
- 项目外用户不能通过猜测 ID、列表分页、SSE、下载地址或 Agent 工具读取该项目共享资料。项目内不同岗位读取同一共享文件无需逐文件授权。
- 私人提示词、密钥、私有执行上下文和未提交临时产物不出现在项目共享区，不能通过挂载或发布动作自动泄露。
- 项目管理者不能仅凭管理身份验收任意任务；负责人 / 显式代批权限按各自范围验证。
- 替换绑定后旧人的过期操作被拒绝，历史操作者、会话与决定记录不被重写，私人提示词不随替换公开。

## 3. 工作与审批验收

| 场景 | 必须结果 |
| --- | --- |
| 创建计划 / 子任务 | 工作草稿、单一所属计划、正确父任务与明确负责人 |
| 不同计划或项目的错误父任务 | 拒绝或进入显式范围变更，不静默归属 |
| 草稿未经有权人确认 | 不成为正式承诺 |
| 普通聊天说同意 / 完成 | 不写正式决定 |
| 多人同题审批 | 全部审批位满足既定规则才生效 |
| 同题任一人明确退回 | 要求原因，取消该提议，结束剩余待批和计时 |
| 连续同意 | 首次计时不重置，超时与人工决定并发不重复生效 |
| 审阅中依据变化 | 拒绝旧版本批准新内容，展示需复核差异 |
| 部分来源拒收和补交 | 保留未受影响接收，新版本重新确认发送 |
| 交接未回应 | 保持待接收，仅提醒 / 协调，不自动接收 |
| 前置硬条件未满足 | 阻止对应开始 / 验收，展示具体缺口 |
| 全部任务验收 | 生成负责人可处理的计划验收入口，不自动完成计划 |
| 任务重开 | 保留原验收；提醒计划负责人，不自动撤销计划历史 |
| 双击、CLI 重试、队列重试 | 同一幂等请求返回同一结果，不产生多次决定 |

## 4. Agent 验收

使用至少研发、设计两个场景的中文材料验证，不只验证模型能输出文字或调用 echo。

- 主 Agent 发现与调用合法身份，拒绝不允许的节点 / 身份、跨项目材料和私有数据访问；不把共享项目文件再次限为只允许某个岗位读取。
- 子调用并行且上下文独立，局部失败不丢弃其他已完成结果。
- 同一会话并发输入按协议排队 / 合并，避免相互覆盖。
- 上下文压缩前后保留当前目标、反对意见、待决事项和依据引用；原始记录仍可追溯。
- 权限撤回、绑定替换或流程更新后，后续调用不能继续沿用失效授权。
- 工具超时、模型断流、沙箱销毁、Server 重启和网络抖动均有可解释状态；未知执行结果不能当成成功或盲目重做。
- 资料不能通过路径穿越、符号链接、宽泛挂载或过度网络权限被越权读取。
- 递归元数据操作（chmod -R、构建工具向上遍历写元数据等）触及 `/workspace/project` 只读挂载时行为可预期：失败可解释、不影响共享区内容与运行其余部分。
- 平台运行不会唤醒成员本地 AI；本地工作获取必须由用户主动调用。

工作目录与上下文覆盖专项用例见 [11 工作目录与动态上下文](./11-工作目录与动态上下文.md)：覆盖运行上下文的 PostgreSQL 读写、项目共享挂载、版本缓存、截断 / 部分读取、异议保留、未返回参与者和恢复。另验证原件不可写、派生可写、临时输出不共享、明确提交后新草稿可读，以及 HTML + 文字 + 依赖资源的完整读取和浏览器检查。验收不以“模型声称已阅读全部”作为唯一证据。

## 5. 前端验收

HeroUI 通用组件来源统一；中英文、深浅色、桌面布局、键盘与焦点行为覆盖。

任务树验证多子节点、跨层依赖、折叠与定位，画布操作不修改正式关系。审批卡、待办列表和对象详情同步到同一记录。过期内容、权限变化和断线重连可见且不丢未提交草稿。

对大型列表、长会话、复杂任务图和流式消息设置实际测量目标。当前不擅自填写并发人数、节点数量或响应时间承诺；在容量目标确定后将其转成可执行基准。

## 6. K8s 端到端验收

为 Judex 创建明确归属的临时 Namespace / Helm Release，至少验证：

1. dev 全量内置安装与重启持久化。
2. prod 的四种 PostgreSQL / 对象存储组合。
3. 注册两个账号、创建独立项目、邀请与接受、岗位分配。
4. 从工作草稿、上报、退回补交到任务和计划验收。
5. 真实沙箱创建、执行、取消、超时回收与持久事件恢复。
6. 数据库 / 对象服务暂时不可用时的状态、重试与恢复。
7. 升级、迁移失败、备份恢复及卸载保留数据行为。
8. 多环境同集群时 CRD / Controller 资源归属与 Namespace 隔离。

测试资源用固定标签标记并记录清单；清理前核对 Namespace、Release、PVC 和对象前缀归属。不得清理其他项目或生产数据。若资源压力需要临时停止正常部署服务，先核对范围与已有授权，保留恢复步骤；不默认执行停服。

## 7. 当前证据边界

离线原型的状态测试、浏览器测试和截图仅证明其模拟路径，不折算为正式后端或 Kubernetes 验收。实际业务、模型与部署记录从[实施计划](../plans/README.md)进入。

本次文档交付不运行部署、不创建数据库、不安装 HeroUI、不改业务代码；文档检查仅覆盖链接、章节、决策追踪和已知边界一致性。

实现完成时保留每阶段的代码版本、Chart / 镜像版本、测试命令、环境条件、结果与未通过门槛；不以“所有单元测试通过”替代实际部署验收。

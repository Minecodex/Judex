# 05 数据模型与文件存储

本章为逻辑数据模型方案，不是已经执行的迁移脚本。已确认使用 PostgreSQL 与 S3 对象存储；2026-09-25 修订后不再使用独立 SQLite，执行期上下文直接入 PostgreSQL。表名、索引和字段在接口评审后锁定。

## 1. 存储职责

PostgreSQL 保存正式业务事实、会话、运行事件、授权元数据、材料索引和任务调度状态。文件原件、较大产物、归档日志保存为对象存储中的不可变版本。

Q070 原确认 SQLite 承载执行期结构化上下文；harness 服务端化后于 2026-09-25 修订为：执行期上下文、会话窗口、子运行状态与检查点直接以 PostgreSQL 表承载，不再维护独立 SQLite 或第二份事实副本，每轮组装在内存工作集完成。沙箱删除不得丢失已确认成果或正式会话。

## 2. 逻辑表分组

| 分组 | 建议表 | 关键关系 |
| --- | --- | --- |
| 账号 | users、auth_identities、user_sessions、client_grants | 账号与认证来源分离，无全局业务职级字段 |
| 项目 | projects、project_members、project_invitations | project_members 在 project_id/user_id 上唯一 |
| 职位与身份 | position_templates、agent_identities、identity_bindings、personal_position_preferences、position_preference_revisions | 稳定 identity 与可替换绑定分别保存；个人偏好及修订按 project_id/user_id/position_id 独立 |
| 流程 | workflow_definitions、workflow_versions、workflow_nodes、position_node_bindings | 已发布版本不可变，规则 / 图 / 说明同源 |
| 工作 | plans、tasks、task_participants、task_requirements、plan_task_references | task.plan_id 可空；parent_task_id 不表达前置顺序 |
| 讨论 | topics、topic_work_links、messages、message_material_refs | 双向多关联，不复制讨论 |
| 提案 | proposals、proposal_versions、approval_slots、approval_decisions、proposal_dependencies | 决定绑定具体审阅版本 |
| 交接 | handoffs、handoff_sources、source_versions、source_decisions | 来源独立修订，保留未受影响决定 |
| 验收 | task_acceptances、plan_acceptances、reopen_records | 历次验收与重开保留 |
| 材料 | materials、material_versions、material_links、upload_sessions | 项目共享业务文件按 project_id 隔离，不建设逐文件读取授权表；私有配置 / 运行数据独立存储 |
| AI | agent_sessions、agent_runs、run_events、tool_calls、context_checkpoints | 身份、议题、运行和执行步骤分离 |
| 知识 | knowledge_candidates、knowledge_sources、knowledge_scopes | 未验证归纳与正式决定不混为一类 |
| 基础记录 | audit_events、outbox_events、idempotency_records、background_jobs | 事务内记录，事务外执行 |

单公司部署不需要先建设 SaaS 租户管理系统。项目数据仍必须有 project_id 约束和授权过滤，不能因单公司而省略项目隔离。

## 3. 公共字段与约束

- 正式可变对象采用 `id、project_id、version、created_at、updated_at`；时间使用 UTC，数据库建议 `timestamptz`。
- 版本字段用于条件更新，不依赖客户端显示时间比较并发。
- 审计记录包含实际 actor_user_id、代表的 identity_id、binding_version、来源渠道、对象及审阅版本。
- 稳定任职身份不删除重建来实现换人；绑定历史保存生效范围。
- 父任务必须与子任务同项目、同所属计划；新增或移动时检查父子环。
- 前置引用检查对象范围、目标有效性及循环；跨计划依赖仍引用同一个原任务。
- 状态与枚举是可校验字段；JSONB 用于版本化的提案内容、模型元数据等扩展字段，不把整个平台塞进一个大 JSON 文档。
- 已被正式决定引用的材料版本、提案版本和审批记录不能被无痕覆盖。

## 4. 审阅版本快照

建议审阅基准包含：提案版本、目标工作版本、明确引用的材料版本、相关决定和依赖版本。使用可追溯的 manifest/hash，而不是仅在前端保留一句“我看过了”。

决定提交时重算 / 核对相关基准。无关材料上传不应一律使所有审批失效；影响范围由对象关联与版本机制记录，复杂语义影响由 AI 提示并由业务规则处理，不能只让模型声称“没影响”就越过明确版本变化。

最终任务验收和计划整体验收各自有快照；计划快照引用任务验收 ID，不复制一套可独立漂移的任务状态。

## 5. 对象存储

内置 SeaweedFS 提供 S3 接口；外部 S3 兼容服务通过统一适配层接入。业务不能依赖某一家管理 API 完成核心读取。

Q073、Q074：每个项目一个逻辑共享资料区，计划仅按文件名称 / 目录和元数据关联组织，不单独划读取权限。物理上采用项目 Bucket 或外部 Bucket 的独立项目前缀属于适配方案，沙箱只能看到当前项目。

建议对象键：

```text
项目共享空间：
  plans/{planId}/{materialId}/{versionId}/{readableFileName}
  submissions/{submissionId}/{materialId}/{versionId}/...

独立平台私有空间（不在项目挂载范围）：
  private-runs/{runId}/...
```

对象键不作为权限凭证，不直接使用未经处理的文件名拼接路径。原始文件名、计划关联、用途、MIME、大小、摘要、作者、上传时间、对象键和版本存在数据库。可读名称与稳定 ID 配合，HTML 材料包内部相对文件路径保留，不因加计划前缀而破坏依赖。跨计划引用同一版本，不重复复制原件。

共享业务文件下载按项目成员 / 执行权限控制，不再检查逐文件白名单。应用下载、签名 URL、只读挂载和资料索引采用相同项目边界。退出项目后不再发放访问能力；已有签名 URL、缓存与挂载的撤销限制须在实现中明确。

## 6. 上传与一致性

设计流程：创建上传会话 → 上传临时对象 / 分段上传 → 服务端校验对象存在、大小与摘要 → 登记材料版本 → 关联议题或形成关联建议 → 异步解析。

数据库与 S3 没有共同 ACID 事务。采用 staged / ready 等上传状态、幂等完成接口和孤儿对象清理任务协调；只对 ready 版本提供正式引用。文件缺失时返回明确错误，不能显示成果可用。

原件先登记符合既有规则。AI 自动建议用途或关联仍是草稿；用户直接在某个任务或讨论上传时记录其明确选择的投递位置，不伪称 AI 已批准关联。文字和 HTML 等附件保存为同一提交关系，不能只处理文字而忽略未准备好的附件。

Q075：Agent 修改在工作区自由目录派生，调用 publish 业务工具（声明来源版本、产物路径与说明）后由平台登记新版本并成为项目共享草稿；不实时公开临时目录，也不覆盖来源原件。发布时来源版本已落后于当前最新版则报错，要求取最新版重新修改后再发布。记录来源版本、运行身份和修改说明，文件共享不自动改变任务验收状态。

## 7. 沙箱工作目录

共享资料为本项目只读视图；执行期上下文持久化在 PostgreSQL（2026-09-25 修订，不再使用独立 SQLite），临时修改与待提交产物在沙箱工作区内独立：

```text
/workspace/             本次运行整体工作区，AI 自由读写
  project/              本项目共享业务资料，只读挂载
    common/  plans/{planId}/{materialId}/v{versionId}/  submissions/{submissionId}/
  （其余任意目录）      派生副本、临时分析与待发布产物，结构由 AI 自定
```

本项目共享文件可供项目内 Agent 自主读取；其他项目、私人配置和私有运行数据不挂入共享视图。每个运行使用独立沙箱与独立工作区；执行期上下文与检查点直接持久化在 PostgreSQL。共享区只读由挂载与凭据双层落实（EROFS），派生修改在工作区自由目录进行，发布回共享区只能经 publish 工具由平台登记；路径归一化、符号链接与原件写权限由执行环境限制，不能只校验字符串前缀或只依靠提示词。

执行期表结构、项目挂载适配、缓存可见性、子结果包与压缩恢复见 [11 工作目录与动态上下文](./11-工作目录与动态上下文.md)。挂载一个可浏览目录不要求预先下载所有内容；可读、已取得和已分析分别记录。

## 8. 索引、保留与备份

常见查询按 project_id + 更新时间 / 状态建立复合索引；消息按 topic/session + seq；审计按对象 + 时间；任务领取按状态 + 可运行时间；唯一幂等键按调用主体与操作范围约束。

向量索引可评估 pgvector，尚未确认为强制依赖。中文资料检索需专门验证分词、关键词、向量和权限过滤效果，不承诺 PostgreSQL 默认全文配置即可满足中文检索。

平台事实、对象文件和 SeaweedFS 元数据都需要备份。备份时记录一致的引用清单和时间边界，恢复后校验缺失对象。保留期、归档 / 删除策略、RPO / RTO 尚未确认；不能因为 Helm 卸载默认删除数据。

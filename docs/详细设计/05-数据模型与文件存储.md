# V2 数据和文件

V2 migrations 位于 `internal/infrastructure/postgres/v2`，独立 schema 能力标记为 2。检测到旧 users 表却没有 V2 能力标记时拒绝迁移，避免直接覆盖旧业务。正式切换在现有 PostgreSQL 建立 `judex_v2`，认证导入工具保持 UUID、密码摘要、有效 Web session／CSRF 和恢复记录一致。

核心关系为 projects／project_members、positions／position_versions、workflows／workflow_versions、personal_prompts、conversations／conversation_members、groups／role_agents、messages／mentions／message_files、files／file_versions／file_grants、discussions／deliveries／role_runs、knowledge_entries／context_heads／context_snapshots。通知、事件、幂等、任务与身份基础设施同库。

schema 13 为 positions／workflows 增加可空 `preset_id`，各自以 `(project_id,preset_id)` 建立非空唯一索引。模板导入成为项目独立副本，改名不丢失来源；既有自建模板不被覆盖。个人提示词创建使用 `expectedVersion=0`，更新必须匹配现有版本，过期的创建或更新不覆盖已保存内容。

S3 使用 `v2/` 前缀。原件按不可变版本存储；分片在临时上传前缀，完成／取消／过期后回收；历史引用不随文件库移除删除。预览 PDF 用内容摘要键，ZIP 展开条目有安全路径与大小限制。来源版本显式授权到目标群；新版本不继承分享资格。

范围、版本与预览能力规则见 [V2 合同](../plans/v2/CONTRACTS.md)；对象备份命令仍为 `judex-server objects export|import`。

## 流程图与资料补充（2026-10-20）

schema 14：workflow_versions.graph 保存不可变结构化流程图；workflow_drafts 保存输入/结果/状态/usage/job_id；users.avatar_png 与 avatar_version 保存规范化账号头像和递增版本。迁移只回填与内置库原文一致的工作流原图，人工修改的文字不猜测转换。旧认证字段不变，新增字段不计入跨版本认证完整字段指纹。

## 阅读与确认补充（schema 15）

messages.confirmation_title 保存可选事项标题；confirmation_responses 以消息／人唯一，保存 choice 和唯一 response_message_id。迁移回填既有 requiresResponse 的明确人类回复，不修改历史消息或认证字段。卡片从消息／提及／回应投影，权限仍属于会话。

文件预览注册与转换由 collab/file_formats.go 归一管理。转换器使用 LibreOffice、ffmpeg、libarchive，生成 PDF、PNG、MP3、MP4 或规范 ZIP；原件不可变。派生内容及归档条目仍经过当前会话授权；不引入第三方在线文档服务或公共下载链接。前端阅读器和格式／大小边界见[实施说明](../plans/v2/WORKSPACE-READERS-20261020.md)。

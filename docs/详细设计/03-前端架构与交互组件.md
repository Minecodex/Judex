# 03 前端架构与交互组件

## 1. 技术基线

| 层 | 选择 | 状态 |
| --- | --- | --- |
| UI 应用 | React | 已确认 |
| 客户端状态 | Zustand | 已确认 |
| 服务端状态 | TanStack Query | Q064 已确认 |
| 样式 | Tailwind CSS + 统一语义 Token | 已确认方向 |
| 基础组件 | HeroUI，单一通用 UI 来源 | Q061 已确认 |
| 工程 | TypeScript + Vite SPA | 设计方案 |
| 路由 | React Router | 工程候选，未锁定版本 |
| 任务画布 | React Flow + 独立布局引擎，优先验证 ELK | 工程候选；不另引入一套视觉组件库 |
| 流程图 | Mermaid | 已有业务表达与 Demo 实现依据 |
| 表单 / 校验 / 编辑器 | 选型待实施验证 | 不默认引入多套同类能力 |

不为当前登录后的协作产品默认增加 SSR 服务。静态产物可由 Go 服务提供，后续若有公开站点需求再单独评估。

## 2. HeroUI 使用边界

所有通用按钮、表单、菜单、选择器、弹窗、抽屉、提示、标签与基础卡片统一使用 HeroUI。2026-09-27 已把现有业务的输入框、选择器、复选框、提示、状态标签和折叠区迁入共享适配层 `web/src/components/ui/FormControls.tsx`；Button / Modal 及 Tab / Popover 同样使用 HeroUI。隐藏的文件 input 仅用于浏览器文件选择，可见入口使用 HeroUI Button；语义 HTML、布局及业务 SVG 不是另一套基础 UI 库。独立 `docs/demo` 已删除。业务模块不得为少量控件再次混入 Ant Design、Mantine、Radix 或 shadcn 组件。

专业引擎与 UI 来源区分：任务图可以使用专业节点 / 连线引擎，节点内容、上下文菜单和操作按钮仍由 HeroUI 与 Judex 业务组件组合。图引擎、布局算法、请求库不被视为第二套基础视觉组件库；具体引擎尚需确认与验证。

基础动效优先使用 HeroUI 已提供的状态样式和 CSS 过渡。首版不默认增加 Motion。仅在复杂布局动画确有必要时另行评估，遵守减少动态效果偏好。

## 3. 视觉与规范

Demo 验证交互，不要求保留大标题衬线字体、纸张装饰、配色或具体圆角。正式视觉的设计方案为中性色背景、单一品牌强调色、清晰文本层级、适度留白与紧凑工作视图。

- 统一维护颜色、字体、间距、圆角、阴影、层级和动效 Token。
- 组件状态至少覆盖默认、悬停、焦点、禁用、提交中、失败和内容过期。
- 审批结果以文字和图标共同表达，不能仅靠颜色区分。
- 登录、长表单、嵌套弹窗和画布节点支持键盘操作及可读标签。
- 中英文与深浅色是正式验收范围；移动端不在当前已确认范围。

**与当前 AGENTS 的协调：** 现有规则要求统一 `.judex-*` 类名前缀。HeroUI / Tailwind 的落地方案是允许第三方组件类与 Tailwind 工具类，Judex 自定义业务类继续使用此前缀，视觉值继续来自 Token。此约定已在当前 AGENTS 和 `web/` 中执行。

## 4. 目录与依赖

```text
src/
  app/                 路由、Provider、启动与错误边界
  features/
    identity/          注册、登录、个人设置
    projects/          项目、成员、职位、邀请
    work/              计划、任务、前置与验收
    discussions/       议题、消息、Agent 执行视图
    decisions/         提案审批与交接
    materials/         原件、版本、用途与引用
    workflows/         规则编辑、节点与图
  components/ui/       HeroUI 的受控使用入口与必要适配
  components/business/ 任务卡、审批卡、交接卡、身份标签
  lib/api/             生成客户端、错误映射、事件连接
  stores/              仅客户端交互状态
  i18n/                每业务模块 zh / en
  styles/              Token、主题、页面布局
```

页面通过业务模块查询 / 命令 Hooks 访问 API，不直接读写全局存储。服务端状态不复制到 Zustand 形成第二份事实。共用组件不依赖具体项目查询结果，接受明确的数据与事件参数。

## 5. 状态分工

| 状态 | 所属 |
| --- | --- |
| 项目、任务、审批、材料版本、会话分页 | TanStack Query 缓存，由服务端决定正式结果 |
| 画布缩放、节点折叠、选中、过滤面板 | Zustand / 组件本地状态 |
| 正在编辑且未提交的表单 | 表单本地状态；可按用户和对象保存草稿 |
| 当前项目、任务详情、分享位置 | 路由参数 |
| 流式消息片段 | 对应会话的短期缓冲；最终事件合并进查询缓存 |
| 语言与主题 | 本地偏好；语言沿用 `argus.locale`，未来迁移必须显式处理 |

缓存键包含项目与对象身份。换账号、退出项目或权限撤回时清除相应缓存和未授权界面；不能仅隐藏菜单却仍保留可读取的旧详情。

审批提交不做“已批准”的提前乐观展示：先显示提交中，收到服务端决定或版本冲突后呈现实际结果。普通消息可显示本地 pending 状态，但不能混入正式状态。

## 6. 页面与入口

最新入口调整：新建讨论只从左侧进入；头像打开账户菜单，语言、主题、邀请、设置和登出统一收纳。设置采用独立全屏页，个人偏好、项目 AI、成员职位、流程和本地接入归入设置；右侧加号只保留任务、资料、待决、交接和概览等日常功能。设置返回应用保留原有聊天和工作视图，配置授权保持原规则。

最新界面细化：中央聊天与右侧功能分别采用独立的可关闭标签栏。右侧首次显示功能列表，选择即开标签，加号回到列表继续打开；任务/计划详情按对象区分，功能标签重复打开时复用。两侧标签统一紧凑尺寸，未选中也有底色与边框。标签属于前端视图状态，不复制业务事实或改变权限；关闭不删除对象，草稿按项目、人员与功能隔离保存。

## 7. 核心业务组件契约

- `TaskCard`：正式状态、AI 分析分开显示；责任人、验收人、下一步、阻塞条件、材料计数、所属计划。
- `ExecutionMap`：按前置关系从左到右排列任务，支持并行与汇合、缩放和原地详情；父子归属作为辅助信息，不暗示执行先后。图外前置及循环显式提示。
- `ProposalCard`：审阅版本、变更摘要、依赖、审批位、截止时间、本人可执行动作和过期提示。
- `HandoffCard`：发送人、接收人、流程依据、来源版本、各来源发送与接收决定、局部退回原因。
- `EvidenceReference`：来源、时间、版本与可访问原件，不把“有文件”显示成“验证通过”。
- `IdentityBadge`：稳定身份与当前关联人信息；历史操作显示发生时实际操作者。

任务图位置调整只是视图状态。增删任务、拖线改变依赖或调整分工都进入业务草稿和影响预览，不能直接通过前端拖动变成正式安排。

## 8. 异常与性能

列表分页、会话按游标加载、长列表按需要虚拟化，任务图布局放在独立任务 / Worker 中验证。流式输出合并刷新，避免每个字符触发整个项目重渲染。

网络断开保留用户草稿，重新连接后从服务端核对状态。对过期审批、权限变化、文件解析失败和沙箱中断分别说明可恢复动作。前端不自动重试不具备幂等保证的正式命令。

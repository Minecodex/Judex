# 03 前端架构与交互组件

更新：2026-10-09。当前界面由[项目协同](../plans/cooperation-ui/README.md)、[Demo4](../plans/demo4/README.md)及[共享资料](../plans/materials/README.md)共同定义。旧工作室、独立 WorkspaceApp 和全项目聊天常驻工作入口已清理。

## 1. 技术与工程边界

React＋TypeScript＋Vite；HeroUI 是唯一基础 UI 库，Tailwind 与统一语义 Token 负责样式。客户端视图与偏好由 Zustand 管理，服务端查询与失效由 TanStack Query 管理；正式与 demo 复用组件，数据 Provider 分开。

执行图以正式业务关系和现行 SVG／布局实现为准；React Flow、ELK 等早期候选不作为已采用依赖。Mermaid 用于流程展示，不是正式执行或授权引擎。当前不增加 SSR 服务。

通用按钮、表单、菜单、弹窗、抽屉、提示、标签和基础卡片直接或经 `Button`、`FormControls`、`Presentation` 适配 HeroUI。原生文件 input 仅用于 FileList，语义 HTML、布局和业务 SVG 不构成第二套基础 UI 库。

## 2. 当前目录与组件树

`web/src/app/` 承载启动、认证和路由；`features/cooperation/` 承载项目入口、协同与路线，`features/chat/` 承载会话；`features/work/` 提供领域视图、命令、详情和 Provider；认证、资料、设置分别位于 `auth/`、`materials/`、`settings/`。

`WorkspaceShell → ProjectListPage → ProjectHub → PlanRoute / ChatDiscussionView` 是当前页面结构。Chatbox 不重新承载全项目 WorkMap、NowPanel 或独立 TaskPage。账户在右上角 PortalHeader，项目卡提供邀请与完整设置。详细行为见[聊天工作区](../界面/聊天工作区.md)。

`TaskInspector` 在任务抽屉与讨论右栏共用；概览、原记录和流程参考分区一致。共享资料卡片、固定版本阅读器和用途登记也复用同一组件／用例，不另建原型领域服务。

## 3. 查询、路由与状态

| 内容 | 归属 |
| --- | --- |
| 项目、计划、任务、消息、材料、审批、交接、Agent 状态 | 服务端查询缓存，按 projectId／对象／身份隔离 |
| 当前页面范围、对象、编辑器及来源位置 | 规范化路由与视图键 |
| 中央／右侧标签、布局、草稿、阅读位置 | 用户、项目与对象隔离的本地视图；附件仅在当前页面内存 |
| 流式片段 | 当前会话短期缓冲，最终事件进入查询缓存 |
| 语言、主题 | 持久偏好，沿用 `argus.locale` 与 `judex.theme` |

页面按需加载，完整项目设置不成为普通成员进入讨论的前置。SSE 驱动查询失效，cursor 分页与断线恢复由共用层处理。加载、失败和空状态分别表达，不用示例数据填补失败。

消息工作上下文、导航范围和右栏对象分别管理。关联同一会话不复制消息，分叉历史只读；正式权限和对象事实按当前范围查询。后台刷新与侧栏过滤不自动切换会话或覆盖用户明确选择的任务上下文。

退出、切换账号或权限撤回清理相应缓存和私有界面。审批不乐观显示批准；正式结果、expectedVersion 与幂等由服务器核对。

## 4. 视觉与布局

正式规则见[界面规范](../界面/README.md)。颜色、字体、字号、间距、圆角、阴影和状态只来自共享 Token；业务样式统一 `.judex-*`。中英文及深浅色覆盖桌面体验，移动端不属于当前验收范围。

项目／计划与普通路线共用 1680px 内容上限；详情／讨论右栏默认 440px，较小桌面为 400／384px，保留合法自定义拖拽尺寸。计划右栏内部统一留白，外层不重复叠加。

分隔线支持拖拽、键盘、取消、重置和比例恢复。收起、最大化及设置返回保留当前会话和草稿。路线采用浏览器原生全屏与全视口回退，确认 Portal 在对应根内可操作；退出恢复图、选择和阅读位置。流程模板预览继续使用自己的共享全屏弹窗。

标签按对象类型＋ID＋分区去重，外层选分区后不嵌套同名导航。记录原文、AI 分析和正式决定分别呈现；状态同时使用文本／图标和颜色。

## 5. 业务与异常契约

计划、任务卡片主体进入结构／详情，独立讨论入口按需建立任务主讨论。上报不自动建会话，AI 的讨论建议由人选择。需要我决定、交付与接收和聊天卡引用同一版本的正式对象。

正式命令提交 expectedVersion 和幂等键。过期报告保留原草稿及快照，由人读取最新安排重新核对；多职责启动与交接发送显式选择身份。异步核对绑定对象和请求代次，晚到响应不能改变新任务。

网络中断保留草稿，重连后核对服务端状态；权限、过期审阅、文件预览及沙箱错误分别提供恢复入口。未保证幂等的副作用不自动重放。来源跳转按需翻页，读取旧历史不强制滚到末尾。

任务移动与增删、依赖和分工修改进入正式草稿及审阅，不由图上的拖拽直接改变安排。管理员跳过不等于验收，交接接收不等于任务或计划最终验收。

## 6. 性能与验收

列表和消息分页，页面按需查询，流式更新合并刷新。长列表、图布局、阅读器重排及加载状态按实际桌面场景验证；不把单次样本视为容量承诺。

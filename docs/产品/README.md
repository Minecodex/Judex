# Judex V2 产品主线

Judex 让人和代表岗位的 AI 在群里一起工作。人仍在本地完成实际工作，通过网页或 CLI 把文字和文件送回群；工作是否完成、是否采用建议由人决定。

登录后进入项目卡片列表。项目保留描述、已注册成员、职位、参考工作流、默认模型和讨论闭环上限。负责人／管理员直接添加成员并发送站内通知，无须邀请接受流程。

项目设置提供 20 个场景、118 个职位和 51 个参考工作流的内置库，可筛选、预览、批量添加，再独立编辑并查看版本。重复添加跳过已有来源或同名内容，不覆盖修改；导入不会自动让成员任职或启动 AI。工作流中的步骤与协作关系只是参考，具体执行和成果仍由人决定。成员列表可搜索、调整项目权限和移除；个人提示词按职位配置，仅本人可读。

参考工作流以流程图保存节点、条件分支、并行与反馈关系，并支持图形预览、节点/连线编辑和版本回看。项目管理者可用自然语言请求项目默认模型生成草稿，确认应用后再保存；生成不启动群讨论或执行流程。左下角账号设置支持昵称、头像上传/移除，团队中的显示同步更新。

项目进入后，最左侧为群聊／平台聊天等导航，左栏只列本人加入的群，中间是真实聊天，右侧并排阅读固定版本文件。群以目的组织协作，可选参考工作流。每群独立选成员和职位，同人可兼岗，同岗可多人；多个同级子群、总计最多三层，不继承父群权限，不提供移动群层级。

所有群成员可管理本群配置。加入目标群的项目负责人／管理员可级联归档或恢复其全部子孙群，归档后仍可讨论。平台私聊跨项目复用，仅两位人类参与。

普通网页消息不触发模型；明确结构化提及岗位 AI 才唤醒目标；提及人只通知。本地普通推送触发本人在群中的全部岗位，支持只记录。岗位平等、共享群公共知识，各自用项目、目的、工作流、职位和个人提示词理解职责，无协调 Agent 和业务状态机。

岗位要求人回应时，人通过消息「回复」或 CLI `--reply-to` 回答对应问题；多人分别解除自己的等待。需要岗位继续时同时明确 @AI，普通回答仍不自动触发模型。所有分支完成后讨论自然结束。

群内同一次 AI 讨论共用因果闭环计数，默认一档 10 轮；暂停后保留新内容，任何人类群成员可以补意见继续、空意见继续或终止。技术调用／Token／时间额度另行记录，未知工具副作用须核对。

文件属于群或两人私聊。消息固定引用版本；同名不合并；显式更新产生新版本；分享仅授予目标群指定内容／版本，移出库不破坏历史阅读。详情见 [V2 合同](../plans/v2/CONTRACTS.md)。计划、任务、交付、交接、审批与验收已退出正式业务。

当前实现与验收见 [V2 实施状态](../plans/v2/IMPLEMENTATION.md)。历史产品答复不覆盖 V2 明确决定。

# 职位场景模板

用户确认的交互：在“成员与职位”设置中打开“从模板添加”弹窗，先选择场景，下方展示职位卡片，勾选需要的职位后一键加入当前项目。当前内置 20 类场景、118 个共享职位预设。

## 界面规则

- 弹窗使用共享 HeroUI `UIDialog`，复杂内容宽 780px；标题与关闭按钮固定在顶部，选择数量、取消和添加按钮位于底部，内容内部滚动。
- 初始要求选择一个场景；场景卡片展示职位名称与职责简介，整个卡片可勾选，支持键盘操作、全选可添加职位及清空选择。切换场景清空选择，取消不写入项目。
- 已添加的模板及项目内中英文同名职位明确标记并禁用重复勾选。添加后修改名称和职责仍保留来源标识，跨场景或切换语言时不会再次导入同一预设。
- 提交期间锁定关闭、场景与选择控件，阻止重复提交；加载或提交失败显示重试，选择保留，成功显示服务端实际新增与跳过数量。
- 项目没有协作流程时也能添加和编辑职位职责。加入后可按项目需要配置流程节点；没有绑定的职位显示“待绑定流程节点”。流程绑定继续校验本项目已发布节点。
- 所有 UI 文案来自 `web/src/i18n/positionPresets.ts`，深浅色、字体、间距、圆角与控件采用共享 Token 和 HeroUI。生产与显式 demo 使用同一个弹窗组件。

## 数据与权限

`internal/project/catalog/position-presets.json` 是默认内容的唯一来源。场景引用稳定的职位 ID，重复出现的职位共用预设；每个预设包含中英文名称、职责简介和完整默认职责。服务端嵌入同一 JSON，demo 显式读取该文件，生产读取失败不会回退到 demo 内容。修改目录内容时递增 `version`，已有项目内容独立保存，不随默认目录更新。

- `GET /position-presets`：返回带版本的全局只读目录，需要认证；CLI 读取仍受已有 context:read 范围校验。
- `POST /projects/{projectId}/positions/import-presets`：请求包含 `catalogVersion`、`scenarioId`、`roleIds`、`locale`；只允许本项目 owner/manager 的浏览器写入，沿用 CSRF 和 Idempotency-Key。
- 服务端校验目录版本、场景所属、有效且唯一的职位选择；同一项目锁及事务内复用已有职位创建、版本、审计与事件机制，完整成功或完整回滚。
- 返回新增 `items` 和跳过 `skipped`；重复项按稳定来源 ID 或中英文同名职位匹配，不覆盖项目自定义内容。并发导入及重复请求不产生重复职位。
- Migration 19 为 `position_templates` 增加可空 `preset_id` 及项目内活跃来源唯一索引。现有职位字段不变，无批量数据清理；返回的 `Position.presetId` 是可选公开来源信息。
- 导入只复制职位名称、公开职责与简介，不创建成员或任职身份，不分配模型、流程节点、项目管理身份或审批授权。

## 职位分配与卡片操作更新

职位卡片先展示职位名称、职责、流程状态和承担成员，卡片底部放置紧凑的“编辑职责”与“分配成员”按钮。管理者从某个职位打开分配弹窗，选择已加入项目的成员后，为该职位创建独立任职身份；同岗多人分别承担，原有工作、身份记录与个人偏好保留。页面不再提供以某个人为起点勾选多个职位的独立分配栏。

生产模式的成员选择使用 `userId`，同名成员以邮件信息区分；当前绑定的 `userId` 用于识别已承担者。替换已有任职仍使用原替换接口和绑定版本，不重建身份。权限、CSRF 与幂等沿用现有 API，本轮无新增数据迁移。新增浏览器 `T03` 验证同名成员精准分配、多位成员承担、原身份保持以及普通成员不可分配。

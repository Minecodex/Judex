## 已选定方向：可调节的标签会话台

打开当前 Demo（历史地址：`http://127.0.0.1:4173/chatbox/index.html`）。原 `demo-tabs.html` 地址也继续可用；其他草图保留在 比较页（历史地址：`http://127.0.0.1:4173/chatbox/compare.html`）。

当前界面按三个区域组织：左侧是项目与讨论导航；中间是可切换的会话标签、机器人消息、人的输入和交接决定；右侧是同一项目的卡片树、交付资料与流程依据。计划和任务通过树、卡片与讨论关联，不需要离开聊天进入另一套工作台。

已实现两条可拖动分隔线，中间占用剩余空间。两侧支持独立收起和恢复，保存宽度与收起状态（`judex.chatbox.layout.v1`），刷新后保留。窗口变窄时限制实际宽度，保证三栏最小操作空间；窗口恢复后重新使用用户偏好。拖动不会重建聊天 DOM，不丢草稿或交接决定。

“布局”入口提供三个快捷状态：均衡布局恢复默认三栏；专注聊天收起两侧；展开任务图加宽右侧并显示卡片树。双击分隔线恢复该侧默认宽度；键盘方向键、Shift 加速、Home / End 也可调整；拖动中 Escape 可以取消本次调整。

后续页面组织建议：资料、成员 / 职位、流程说明继续在右侧查看或编辑；讨论和决策留在中央，各对象入口跳到同一条讨论。这里仅明确布局方向，尚未将原完整原型中的职位配置、邀请和计划整体验收界面全部搬入本 Demo。

## 本轮范围

用户认为此前“工作室 / 信箱 / 地图”只改变了入口，交互差异不够。新的明确方向是：左侧项目与会话，中间以机器人讨论、人工消息和决定卡片为主，可以同时打开多条讨论；右侧查看资料、计划任务与其他内容。先做简单 HTML 比较操作方式，暂不完善整套应用。

因此，本轮在独立的 `demo/public/chatbox` 目录制作草图，不替换现有 React 应用、不迁移业务数据、不改变 Q001～Q055 已确认的业务规则。

## 卡片树与依赖

示例树实际画出计划与任务卡片及连接线，支持点击详情、跳转相关讨论、放大查看。普通归属线表示计划 / 任务拆分，带箭头的虚线表示另行约定的前置条件，两者共处一张图，不再设置独立“依赖关系”标签。

同层任务可以并行。“任务创建功能”和“首次使用说明”两份交付被明确接收后，满足“首版体验包”的开始条件。接收不等于完成该任务，也不等于计划验收。

树在草图中使用固定示例坐标，不代表已经实现任意规模的任务图布局、拖放编辑或自动调度。复杂多层、跨计划依赖和大量节点的可读性仍待后续设计验证。

## 可操作与模拟边界

可操作：项目 / 会话切换、标签打开关闭、双栏独立输入、草稿与阅读位置保留、普通消息、逐份接收、带原因退回、侧栏内容切换、卡片树选择和放大、中英文、深浅色。

演示身份为周宁。接收卡标明发送者、接收者、版本和流程依据；退回一份不抹掉另一份接收。普通消息只进入讨论。所有 AI 消息、报告、流程说明均为内置样例，没有接入真实 AI、CLI、文件上传、权限服务、业务后端或完整补交 / 验收过程。

HTML、CSS、JS 均为本地静态文件，无 CDN 和远程资源依赖。可以通过 Vite 查看，也可以直接用浏览器打开本目录 HTML；复制时保留同目录的 sketch.css、sketch.js、layout.css、layout.js。拖拽布局模块与业务演示状态分开，草图专用样式和双语文本独立于正式 React 页面模块；正式集成时再迁入既有样式和 i18n 模块体系。

# 10 测试与验收

这里定义未来实现必须运行的验收，**不是本轮已执行的测试结果**。不能把旧前端 26 条演示 E2E 或历史挂载 PoC 计为真实全系统验收。

## 1. 测试层与命令入口

| 层 | 目录／拟实现入口 | 证明什么 |
| --- | --- | --- |
| 领域单测 | `internal/*/*_test.go`，`go test ./internal/...` | 状态规则、授权、版本和预算纯逻辑 |
| 持久集成 | `tests/integration`，真实临时 PG/S3 | SQL 约束、事务、并发、迁移和对象补偿 |
| API 合同 | `tests/contract`＋OpenAPI validation | schema、错误、scope、幂等和生成客户端一致性 |
| CLI | `tests/cli`，启动实际构建二进制 | 认证、参数、JSON/exit code、上传重试、人工意图 |
| Web E2E | `tests/e2e/business.config.ts`（新增） | production build＋真实 API、多用户真实路径 |
| Agent 受控 | `tests/agent`，受控 provider＋真实策略层 | 确定性预算、调度、故障与权限，不宣称模型质量 |
| Agent 实际 | `tests/agent/live`，真实模型＋OpenSandbox | 中文材料、工具、HTML 和实际恢复 |
| K8s 系统 | `tests/k8s/business.mjs`（新增） | 完整安装、四种存储组合、重启、故障、恢复、清理 |

P0 先实现相应脚本/配置再把它写作可用命令。不要提前在 README 声称新增命令已经运行。旧 `tests/e2e/chat.config.ts` 继续作为 UI fixture 回归，命名/报告明确 demo。

## 2. 统一真实测试数据

全部用户通过真实注册 API/UI 创建，密码使用仅存在临时环境的随机值，报告不打印。A=项目 P 创建者/统筹；B=实现岗位；C=验收岗位；D=项目 Q 创建者（无 P 权限）；E=P 同岗第二位成员；A 兼另一职位测试一人多岗。角色使用稳定 ID，不靠姓名识别。

P 至少两个 workflow（交付流程、研究流程）、三个岗位、两个 plans、独立任务 T0、主线 T1/T2/T3、并行支线、跨计划引用。资料含 UTF-8 文档、图片、带相对 CSS/JS/image 的 HTML bundle。第二项目 Q 内容带唯一 marker，用于检测越权泄露。

各测试分配 runId，创建的用户/项目/对象前缀和 namespace 带该标记，结束只清测试资源。并发用独立 DB connection／两个真实浏览器 session，不在同一单线程对象里模拟竞态。

## 3. 认证与项目（A 系列）

| ID | 操作 | 必须断言 |
| --- | --- | --- |
| A01 | A/B 自由注册、重复邮箱、不同大小写 | 唯一性生效；成功有 session；首人无全局特权；无假邮件验证 |
| A02 | 错密码、未知邮箱、限流、合法登录 | 错误不枚举账号，限流可恢复；口令不日志/存储明文 |
| A03 | 刷新、会话过期、logout、logout-all、恢复码 | 缓存与 cookie 清理正确；恢复码一次使用；旧 session/grant 失效 |
| A04 | A 建 P，D 建 Q，B 未受邀查 P | 两项目隔离；非成员列表/详情/文件/SSE 均不泄露 |
| A05 | 邀请未注册邮箱，注册后接受；错人/过期/撤销 | 只有匹配账号可接受；重试不重复成员/identity |
| A06 | 同岗多人、一人多岗、现有成员加岗、替换 | identity/历史保留；新旧 binding 权限更新；私人偏好不转移 |
| A07 | owner 转移/最后 owner 离开、manager 越权 | 无悬空 owner；manager 不能越权验收；技术运维恢复有真实审计 |
| A08 | 项目归档、恢复、个人 prompt API | 归档停止写/run；prompt 仅本人；其他项目偏好独立 |

## 4. 工作、审批与交接（B 系列）

| ID | 操作 | 必须断言 |
| --- | --- | --- |
| B01 | 草稿拆任务、并行前置、跨计划引用 | 不自动成为正式工作；父子不隐含依赖；不复制验收 |
| B02 | 非法父子/跨项目/双向依赖并发 | DB与服务层拒绝，图不会出现不可解释循环 |
| B03 | 工作提案冻结名单，同真人多身份，全体职责满足 | 一次真人同意覆盖其明确审阅的职责位，人数去重；最后满足才原子创建全部计划任务；对象 ID 映射稳定 |
| B04 | 同意、退回、修订、明确停止方向 | 退回要原因；旧票/计时不继承；AI 不反复重提已停止方向 |
| B05 | 首票、后续票、到期 worker 与服务器重启 | 首票计时不重置；无首票不自动同意；重启不丢 deadline |
| B06 | 最后批准 vs 退回；timeout vs 人工并发 | 仅一个合法终态，审批后旧拒绝返回冲突；无双重应用 |
| B07 | 代批待回应项、越权/覆盖 reject | 合法代批保留实际 actor；不能把自己记成原审批人 |
| B08 | 审批期间新报告/材料、换人、相关/无关流程更新 | 内容/硬依赖变化 stale，无关消息不作废；换人继承pending职责与deadline，旧人确认失效、旧票不改署名，不能移除反对者后通过 |
| B09 | start/accept/both 硬前置缺少；软建议不满足 | 只阻止相应阶段，blockers 正确，软建议不自动升级硬规则 |
| B10 | delivery→来源 send→分来源 reject→补交→receive | 无关 accepted source 保留；新 sourceVersion 重确认；未回应不自动接收 |
| B11 | 过期验收弹窗、同一人兼执行/验收 | 快照变更拒绝；组合操作分别写 report 和 acceptance 审计 |
| B12 | 全部任务已验收→计划 owner 验收→任务重开 | 不自动计划 accepted；重开保留历史、提示当前缺口，owner 重新判断 |
| B13 | source 已 accepted 后普通接收人拒收 | 不能越权撤验收；形成 reviewer 待处理 |
| B14 | Bug 与 release report、修复传播一个目标失败 | 源/目标分别验收；源完成不显示全部修复；上报不触发真实部署 |
| B15 | 重复 key／异载荷同 key／请求提交后断连 | 同键同结果、冲突409、无重复计划/票/报告 |
| B16 | 取消未完成工作、已验收工作取消、后继引用 | 取消必须正式变更；accepted不能直接cancel；取消不假充完成、不自动满足依赖 |

F01：注册/登录/恢复/邀请/设备/确认页全部真实路径，中英＋深浅色，表单校验/焦点/键盘/错误恢复。

F02：保留聊天/功能多标签、长标题hover、最大化、分隔条持久化、设置往返草稿，浏览器刷新/前进后退与深链接正确。

F04：批准、交接、验收三入口共享同一review，stale展示差异，pending按钮不会使正式结果提前变成功。

F05：性能基准使用10k消息分页、1k任务图/列表的工程样本，记录首屏、交互、内存和bundle体积；这是测量样本而非产品容量承诺。发现不可接受退化后优化分页/渲染/分包并复测。

## 9. K8s 与恢复（G 系列）

G01：开发全内置安装；migration/PG/S3初始化按顺序就绪，真实生产Web注册登录，server重启业务不丢。

G02：PG/S3四组合；“external”是连接另一受测试方管理的实例，不是把同一服务改变量标签就算外部验证。记录endpoint类型及兼容性限制。

G03：迁移重复/失败、API和worker滚动重启、队列lease接管、SSE恢复；版本不兼容拒启动而非读错数据。

G04：备份PG＋对象＋必要Seaweed元数据，恢复到全新隔离环境，核对材料SHA、reviewHash、验收链与待处理deadline；记录实际RPO/RTO。

G05：OpenSandbox重启/失联、两个sandbox并发只读、动态可见、TTL回收、CRD与已有Operator共存，保留D15的缓存限制测试。

G06：卸载保留数据；测试cleanup只删本run的Namespace/Release/PVC/对象前缀，集群级CRD/CSI按所有权处理；停止过的原部署逐项恢复并查健康。

## 10. 证据格式与阻塞

每次阶段验收写 `evidence/<stage>/<runId>/manifest.json`（脱敏），字段：commit/dirtyPatchHash、时间、OS/浏览器/集群、依赖版本、命令、exitCode、caseIds、测试报告路径、相关object/run/request IDs、未执行项、cleanup结果。大截图/trace/日志放忽略目录或指定制品库，仓库留摘要与可定位引用，不提交真实Token。

真实模型/集群/外部存储不可用时记录 BLOCKED＋缺少的具体条件＋已完成测试，不能删除该case、mock成功或在进度写completed。结束交付必须同时声明“实现完成”“已验证”“未验证”，三者不能混用。

# 00 范围、现状与决策

## 1. 效力与本轮新决定

规则优先级：本轮用户明确答复 → 最新详细设计及已确认 V2 决定 → 本计划工程方案 → 旧讨论／前端演示。遇到实质冲突先记录，不用旧 V1 补空白。

**本轮已确认**：内网开放注册，邮箱作为登录名＋密码；首版不依赖邮件验证服务，后续保留 SSO 适配边界。邮箱是未验证的登录标识，UI/API 不得写“已验证企业身份”。用户更正 `ctl` 为 `cli`，沿用 `cmd/judex` 和 `judex` 命令；不另造 ctl 管理协议。

本轮范围是制定完整实施计划；没有实施新后端、迁移数据、部署或宣称真实业务已通过。

## 3. V1 全量范围

包括账号会话和设备授权、项目生命周期及成员、邀请及任职替换、职位和个人提示词、模型目录与项目选择、流程版本与节点绑定、消息与提交、资料版本、计划任务依赖、通用变更提案、审批及超时／代批、来源级交接、验收重开、待办和站内提醒、项目事件、真实 Agent、CLI／Skill、生产前端、Helm／备份恢复。

研发特化能力以通用对象扩展实现：仓库地址与代码引用、Bug 任务、环境／版本发布上报及跨版本修复跟踪。**不恢复平台自动建仓／切分支／merge／测试／部署／唤醒成员电脑**。实际动作仍由成员本地工具完成；上报“完成”也不自动意味着最终验收。

首版不建设 SaaS 多租户计费、外部 A2A 服务、岗位自由互聊、邮件通知服务、手机端、自主跨项目记忆、全局业务超级管理员。SSO、向量记忆、预热池和高级图编辑引擎留适配边界，不作为拖延核心交付的前置依赖。

## 5. 未定与环境门槛

- **CLI 人工确认机制已解决**：用户本轮明确选择浏览器审阅并确认一次，CLI 接收同一笔结果，见 07。这覆盖旧 D10 的未决交互；`--yes`／`humanConfirmed=true` 仍不能当本人证明。
- **生产模型与集群参数**：需要实施环境提供模型网关地址、model ID、凭据引用、StorageClass、入口域名/TLS、镜像仓库。没有凭据也可完成适配和契约测试；真实 AI／K8s 门槛只能标 blocked，不能 mock 后写通过。
- **可用性与恢复目标**：D04/D06 仍未确定；提供单实例可恢复部署和备份演练证据，不宣称 HA。最终生产接纳时记录实际 RPO/RTO、容量和限制。
- **账号恢复／离职**：V1 采用部署运维受审计恢复命令（02），不授予全项目业务权。无邮件时不能冒充提供邮件找回。
- **归档与删除**：V1 支持项目归档与恢复；对已引用事实不提供永久删除。开发测试环境可以按明确资源清单重置，生产数据不可套用“开发期可清理”。

## 6. 易误读规则

私人提示词只有本人和其授权运行使用；项目负责人没有读取原文权。共享资料在项目内统一可读，计划目录不是第二层授权。技术运维能接触数据库的现实不应宣传为“管理员绝对不可读”。

绑定替换保留 identityId 和业务历史；未完成审批按最新 V2-Q028/Q038 随稳定职责接续，不因换人重开或重置截止；参见 03。正式报告的责任席位不可被移除以绕过反对，同一真人操作合并展示，不按兼岗数虚增人数。前端演示的 binding 变化即全体重批逻辑不得照搬。

内部 AI 分析、共享草稿发布、正式报告提交、人类接受、实际本地执行、最终验收是不同事件；一个“success”不能跨越这些边界。

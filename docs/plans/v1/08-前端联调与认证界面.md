# 08 前端联调与认证界面

## 1. 保留的交互与必须替换的底层

保留聊天为中心的 ToC 体验、项目下拉与新建、独立多聊天标签、右侧多功能标签、拖拽分区/最大化、个人账户菜单和独立设置页；不重建传统企业导航。HeroUI 是唯一基础组件库，自定义 judex-*＋tokens，中英文、深浅主题、桌面键盘完整支持。

拆 `features/work/store.tsx`：目前 currentUser=姓名、整包 WorkState 和 actions 本地 mutation 只保留到明确测试 fixture，生产采用 userId/identityId、Query resources 和 command hooks。不能只把 `if(dataMode==='demo')` 删除就当接入；无条件 initialPreview＋Infinity 必须一起删除。

新结构建议：`features/auth`、`features/projects`、`features/discussions`、`features/materials`、`features/decisions`；既有 chat/work 组件逐个以 DTO/view-model 接入，可分阶段保留文件位置，但领域数据与页面不互相写全局快照。单文件不超过 2000 行。

## 2. 路由与认证状态机

路由：`/login`、`/register`、`/recover`、`/device`、`/confirm/:intentId`、`/invite/:token`、`/`（工作区和 query navigation）、`/settings` 或兼容当前 query 设置路由。P0 选择 React Router 并锁版本，或保留有完整测试的 history adapter；不能同时两套互相覆盖导航。

AuthProvider 状态：bootstrapping → anonymous/authenticated → signingOut；GET session 失败时区分 401 和服务不可用。401 去登录，5xx 显示重试，不显示假登录态。登录成功 invalidate session、fetch projects、恢复安全 returnTo；returnTo 仅本站相对路径，拒绝协议和双斜杠开放跳转。

首次无项目：欢迎卡、新建项目、待接受邀请；已有项目恢复最后可见项目（按 userId 隔离偏好）。URL 指向无权项目时显示不存在/无权限并回可见列表，不回退到 seed leaf。退出切账号关闭 SSE、cancel queries、clear cache、清理对应私有草稿；不得在新账号显示前一人的 prompt 或附件。

## 3. 注册页面（必须真实可用）

布局为单张清晰注册卡＋Judex 简短介绍，沿用当前淡色/深色 token；不要出现仪表盘或演示标识。字段：名称、邮箱、密码、确认密码；邮箱 autocomplete=email，密码 new-password，显示/隐藏可键盘操作，错误关联 aria-describedby。

提示“仅限内部使用；邮箱用于登录，当前不发送验证邮件”。按钮状态 idle/submitting/success/error；前端长度和一致性校验，后端唯一性错误就地显示。提交中防止重复请求，不清除名称邮箱；口令仅内存，成功或离开表单清空。

成功已建立 session，进入项目空态或原邀请页；不再要求重复登录。已有账号入口保留 returnTo。禁止首个用户获得全局权限或自动加入演示项目。

## 4. 登录与恢复页面

邮箱＋密码、密码显隐、登录按钮、注册入口、恢复帮助。错误统一“账号或密码不正确”，限流显示可重试时间；网络错误显示重试并保留邮箱。可粘贴密码，Enter 提交，焦点进入第一个错误字段。

会话过期从受保护页面跳转时说明并保留安全 returnTo；原操作未成功不假装已提交。用户重新登录后审批必须重新读取 review，不能沿用过期确认。

`/recover` 输入运维一次性恢复码和新密码；无 SMTP 的“忘记密码”展示真实恢复步骤，不虚构邮件发送。密码更改、设备列表、撤销授权在账户安全设置中提供。

## 5. 设备授权、邀请和审批确认页

- `/device`：登录后输入/核对 userCode，显示站点、设备、请求 scopes 和项目范围，同意/拒绝；不要自动授予全部项目。完成后 CLI 可收到授权，页面不暴露 access/refresh token。
- `/invite/:token`：未登录保留 token 去注册/登录；登录错邮箱显示不匹配及切换账号；正确显示项目、指定职位、邀请人和期限；接受成功进入项目与个人偏好引导。
- `/confirm/:intentId`：展示当前账号、项目、请求设备、具体报告、变更清单、固定版本、审批人、截止和实际操作。只能确认该意图；已过期/改版/重复/错人有明确终态。本人点击后页面与 CLI 共用同一 resultRef。
- 确认页不让浏览器自动化 SDK 隐式代点；不能把打开链接等同同意。客户端仅显示 capability，最终权限在后端。

## 7. 查询和命令层

Query key 至少包含 userId、projectId、resourceType、id、filter/cursor；session 永不无限 stale。TanStack Query 保存服务器状态，Zustand 只管主题、标签、布局和未提交表单；messages/runs 不在两个 Store 各自猜状态。

command hooks 接受 expectedVersion/reviewHash＋稳定 idempotency key，显示 pending，服务器成功再使 affected queries 失效。正式批准/验收不乐观显示成功；聊天可以用 clientSubmissionId 临时 pending message，成功用服务端 ID 替换，重试不重复插消息。

SSE 根据 resource versions invalidate/update queries；旧版本事件不倒退，断线保留内容并显示正在重连；超过游标保留期重新拉 snapshot。移除成员/切用户即清缓存。场景草稿按 userId/projectId/objectId 隔离，过期凭据不自动重新提交。

loading/error/empty/forbidden/stale/pending/partial/missing-material 是每个业务页面必须有的状态，不允许生产错误被 try/catch 吞成空列表。需要登录的下载失败不能返回登录 HTML 让 UI 当图片。

## 8. 图、运行和长内容

执行图继续按硬/已确认前置关系排序，同列可并行；父子只做归属。图外依赖有跳转与 blocker，循环由后端拒绝。拖图/缩放/排序不写业务依赖，编辑依赖必须打开提案审阅。

长会话和任务列表分页；恢复滚动位置以 message ID 为锚，不只像素。流式消息节流渲染，代码/Markdown/URL 做安全处理，HTML 不 dangerouslySetInnerHTML 直注。大图按实际量测决定引入 ReactFlow/ELK，不为换库延迟已可用的任务路径。

AI 状态显示“排队/分析/等待岗位/缺资料/待你决定/轮次用尽/失败”；显示已消耗 rounds/max 和必要参与者缺口，不能出现聊天暂停按钮。模型为建议、真人为决定，署名和样式分别表达。

## 9. 演示退出策略

可保留显式 `VITE_DATA_MODE=demo` 作为开发测试 fixture，但生产 bundle/入口必须 API，测试核验不会加载 seed、localStorage 业务快照和模拟 AI。不从生产请求失败自动 fallback。

原本 31 条纯前端状态测试可以转化为领域行为样例；新的权威状态测试放 Go/PG。旧 E2E 501 断言删除对应部分并改为真实注册登录；保留 API 404 不回 SPA、静态资源缺失 404 等有效检查。

## 10. 完成标准

在 production build＋真实 API 上用两个独立 browser context 验证注册→邀请→协作→审批→交接→验收→退出/重登；至少中文浅色和英文深色，键盘、长标题标签、三栏拖拽、设置往返草稿仍通过。不能用 browser localStorage 注入用户/任务作为正式 E2E 前提。

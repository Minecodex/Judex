# 11 部署、发布与运维

## 1. 复用现有工程

扩展现有 `deploy/helm/judex`、`deploy/docker/server.Dockerfile`、`deploy/helm/UPSTREAM.md` 和 `tests/deploy`，不要按旧设计图另建新Chart。保留已有 `postgresql.embedded.enabled`／`objectStorage.embedded.enabled` 两个独立选择。生产默认 API mode，镜像打包当前 web/dist。

业务服务仍模块化单体，server模式可 all/api/worker；默认一个all实例不承诺HA。数据库、SeaweedFS、OpenSandbox独立基础设施组件。OpenSandbox在同集群执行namespace运行，不将它与API放一个容器。

## 2. 配置合同（实施时固定 env 名并生成文档）

| 分组 | 必须项 |
| --- | --- |
| HTTP | env/listen/webDir/publicURL/trustedProxies/bodyLimits；SSE timeout 单独设置 |
| DB | host/port/name/user/passwordSecret/sslMode/CA/maxConns/migrationLockTimeout；生产禁无意明文公网连接 |
| Auth | cookieSecure、sessionIdle/absolute、registerEnabled、password hash参数、rateLimit、recoveryTTL、allowedOrigins |
| CLI | deviceTTL/pollInterval/accessTTL/refreshTTL、supportedProtocolRange、grantScopes |
| Object | internal endpoint/region/bucket-or-prefix/pathStyle/Secret/partSize/maxFile/maxBundle、previewOrigin、temporaryTTL |
| Jobs | mode/concurrency/lease/heartbeat/retryMax/backoff、outboxPoll、eventRetention |
| Models | 版本化model catalog文件＋Secret引用、能力、部署硬预算；不能下发前端或sandbox |
| Sandbox | lifecycle endpoint/keySecret、namespace、image allowlist/digest、CPU/memory/TTL、mountDriver、egressPolicy、pause能力 |
| Observation | logLevel、metrics、trace correlation、敏感字段脱敏、审计保留期 |

环境缺必需字段启动清晰失败；可选AI依赖缺失则能力关闭并提示，不能让材料和人工协作全部不可用。生产启动若发现 VITE demo 构建标记拒绝发布。

## 3. 安装顺序和探针

preflight校验StorageClass/RWX、DNS、镜像拉取、TLS/域名、已有Operator/CRD版本、PG/S3可达与权限 → 数据依赖ready → 独立migration Job（advisory lock）→授权bucket/prefix初始化→Server/worker→OpenSandbox接入检查→真实业务冒烟。

`/healthz`只检查进程/事件循环存活；`/readyz`检查DB连接与schema兼容、必要初始化和draining，不调用外部模型完成一次推理。S3/模型/Sandbox状态在capabilities和metrics单独报告；S3故障禁止上传成功，但不应阻断只读文字和已有DB事务页面。启动探针给予迁移/依赖合理窗口。

优雅关闭先draining、停止接新job/命令，等待短事务，保存run checkpoint并释放/过期lease；SSE关闭使客户端重连。无界工具不能阻塞Pod无限退出，fencing防接管后旧回调写入。

## 4. 存储和沙箱边界

SeaweedFS现有compact单实例拓扑仅是可恢复起点，不能叫HA。Master/Volume/Filer必要元数据都持久化；真实S3 PUT/分片与每bucket collection容量实测，不能以PoC中Filer直写代替S3完整验证。

external S3遵守其API，不能调用Seaweed Filer私有操作。挂载方案独立适配（例如可信驱动层rclone只读），凭据不进入Agent容器。每项目prefix映射与PVC根在平台建立，禁止所有项目共享根再靠prompt约束。

OpenSandbox Lifecycle Server按现有锁定版本复核single-active等限制，不随意设replicaCount>1宣称HA。共享Operator/CRD按集群所有者管理；第二环境复用兼容Controller，不能安装时抢annotation或卸载共享CRD。运行namespace的RBAC、PSA、NetworkPolicy与Secret可见范围分别验收。

## 5. 生产制品

同版本发布：server镜像digest（含API和生产web）、CLI各平台压缩包＋checksums、skill压缩包＋manifest、Helm chart＋锁文件、OpenAPI和schema版本、发布说明和升级指南。构建写version/commit/protocolVersion/schemaRange；`judex doctor`检查互相兼容，不静默忽略服务端新增确认机制。

安装脚本优先只下载并核验checksum，不要求用户以管理员身份执行未审阅远程脚本。技能安装目录由实际宿主约定/用户指定决定，不在仓库偷放长期凭据。

## 6. 备份、恢复、升级

备份记录一致的cutoff和引用manifest，PG与对象都覆盖，Seaweed元数据按拓扑备份。恢复到隔离环境验证材料hash、提案审阅、审计、用户授权和未完成jobs；不能只验证PG能启动。模型私钥通过Secret管理恢复，公开业务备份不输出凭据。

升级前preflight校验schemaRange、backup、存储容量和被锁版本；migration失败不给应用ready。Helm rollback不等于DB downgrade，采用前滚修复或经过验证的恢复流程。首版开发数据允许明确清理，但生产安装不得默认reset/migrate-down。

需明确记录环境实际RPO/RTO与测试时长；D04/D06未确认时只说明已测条件和限制，不承诺可用性等级。

## 7. 可观测与维护

指标至少：HTTP请求/错误、DB池等待、job backlog/lag/retry/lease lost、event lag、approval overdue、upload failure/orphan、run状态、每批轮次/用量/未知用量、sandbox创建/挂载preparing/cleanup失败。trace关联request/project/run/job，不以user prompt作为metric label。

审计查询与普通日志分离，记录真实actor/source及版本。错误返回requestId，CLI与Web都能展示；服务端不在错误响应直接吐SQL、Secret或模型原始私有prompt。

维护runbooks必须覆盖：模型不可用、S3不可用、PG恢复、任务卡住、超时审批积压、sandbox泄漏、账号恢复、负责人转移和CLI授权泄露撤销。维护不得通过直接改状态字段绕过业务记录。

## 8. 临时K8s验收与清理

使用 `judex-v1-e2e-<runId>`（长度符合namespace限制）和唯一Release/labels。开始保存资源清单及正常Judex服务副本数；若确实需要缓解资源，可在已有授权范围停止该正常部署，必须记录恢复步骤并finally恢复。不得停止Argus/Agentx等其他项目服务。

四种存储组合按测试命名空间与外部fixture隔离。清理前核对namespace、release、PVC、bucket/prefix、集群级资源所有权；删除范围来自manifest，不使用全局prune。失败也保留足够脱敏证据并执行恢复/清理；删测试namespace不默认删共享CRD或生产数据。

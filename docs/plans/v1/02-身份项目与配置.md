# 02 身份、项目与配置

## 1. 注册与凭据

已确认的首版：内网开放注册，displayName＋email＋password；邮箱作为登录标识，无邮件验证和注册管理员审核。displayName 可重名，所有引用使用 userId。用户自行建项目，第一位注册者没有额外全局业务权。

注册请求只接收允许字段，长度边界：名称 1–80 字符，邮箱最多 254，密码 12–128 字符（允许粘贴及密码管理器，不截断、不要求固定字符类别）。规范化邮箱唯一约束必须在 DB，不能先查后写竞态。重复邮箱返回 EMAIL_IN_USE；登录错误统一 INVALID_CREDENTIALS，不区分账户不存在、密码错误或账号停用。

密码用 Argon2id、独立随机盐和带参数的编码格式；初始工程参数 memory=64MiB、iterations=3、parallelism=1，部署时做延迟与并发内存压测后可调，最低安全基线不得静默降低。登录验证旧参数成功后渐进 rehash。不得使用 SHA256(password)、可逆加密或日志记录口令。

注册成功创建账号和登录会话，返回 public user＋session expiry；独立审计注册。注册/登录/重置等匿名端点实行全局与 IP/账号维度限流，生产多副本共享状态放 PG。默认登录每账号 5 次/分钟＋IP 30 次/分钟为可调工程值；不要永久锁定账户形成拒绝服务。

## 2. Web 会话

- 随机 ≥256-bit opaque session secret；Cookie 仅存 secret，数据库存 hash。生产使用 `__Host-judex_session`、Secure、HttpOnly、SameSite=Lax、Path=/，不设置 Domain。
- 本地 HTTP 开发使用独立 cookie 名和显式 development 配置；生产配置拒绝 insecure cookie。反向代理可信地址显式配置，不信任任意 X-Forwarded-*。
- 工程默认 idle 24h、absolute 7d；更新 last_seen 节流，避免每请求写库。会话在登录/重置时轮换；过期或 revoked 一律 401。
- GET `/auth/session` 返回 user、expiresAt、csrfToken；无会话 401。CSRF token 与会话绑定，写请求必须 `X-CSRF-Token`＋验证 Origin。注册／登录也做 Origin 和 body 限制，不能用免登录绕过 login CSRF。
- Cookie 不写 localStorage，密码不存 Zustand、日志、URL 或草稿。logout 撤销本会话，logout-all 撤销其他会话与指定 grants；前端清除对应缓存、私有草稿和事件连接。
- auth_version 变更使现有 sessions/grants 失效；middleware 与每次正式事务均复核。服务端返回 401 后前端只跳登录，不回退 demo。

## 3. 账号恢复与技术运维

首版没有 SMTP，“忘记密码”展示联系部署维护者，不发送假成功邮件。提供 server 运维子命令 `judex-server account recovery-code --email ... --reason ...`：需部署凭据权限、带理由审计、生成 15 分钟一次性随机恢复码，只显示一次，不回显旧密码。用户在 `/recover` 输入恢复码设置新密码，事务中消费码、更新凭据、递增 auth_version、撤销会话和 grants，然后重新登录。

该操作是受控部署运维能力，不是全局项目审批人。禁用账号同理使用运维命令，保留历史，停止其继续调用；无业务读取或批准入口。恢复最后负责人由 `project transfer-owner` 运维命令受审计执行，仅在明确人工授权和理由下使用，不自动选第一个账号。这些恢复路径必须有文档与正反测试。

## 4. 项目创建与归档

建项目一个事务写 projects、owner membership、project_room topic、coordinator identity、默认配置与事件。**不**自动把 owner 绑定全部岗位，不自动创建强制“开发/测试”职位。可选模板只生成可编辑的流程／职位草稿，由创建者确认发布。

字段：title、description、kind、maxDiscussionRounds、approvalTimeoutSeconds、defaultModelId、sandboxProfileId。项目可先无模型进入人工协作；模型相关功能明确显示未配置。用户首次注册后展示空项目页、新建项目和待接受邀请，不注入轻笺 seed。

owner 可授予/撤回 manager；manager 可邀请、分配岗位和配置流程，不能移除/替换 owner。owner 转移给已有 active 成员需双方明确确认，事务保持恰好一个 owner。普通成员离开时校验其未交接职责；存在活动任职／待验收职责则先换人或明确停用身份，不无声制造悬空工作。

归档项目后只读，停止新运行和新正式写命令，保留资料、审计与历史；owner 可恢复。归档不是清空数据。项目列表仅本人已加入项目，邀请列表另取；对象 ID 不可绕过列表授权。

## 5. 邀请与稳定身份

邀请目标为精确已注册邮箱或尚未注册的邮箱；服务不提供全账号目录。管理者指定职位集合，生成随机邀请 token（DB hash）和 7 天可调过期时间。首版不发邮件，允许复制邀请链接；链接只用于定位邀请，接受仍要求登录，且登录邮箱与目标一致。邮箱未验证意味着不能声称防住邮箱冒用；这是已选首版身份强度，后续可接验证/SSO。

接受事务：锁 project→invite，核验 pending/未过期/邮箱/职位有效 → upsert active membership → 为未重复授予的职位建立新 identity/binding → 标 accepted → audit/event。重复接受返回原结果。同一用户已承担相同职位时默认复用现有 active identity，不能因重试复制机器人；需要多份同岗身份时使用明确的新身份操作。

拒绝/撤销/过期不建成员；邀请过期页可请求管理者重发，重发新 token，旧 token 失效。职位在等待期间被删除或节点失效时拒绝接受并提示管理者修订。

替换任职：保持 identityId，结束旧 binding，追加新 bindingVersion。目标必须 active 成员。相关任务/历史消息继续引用原 identity，历史审计实际 user 不改。停止旧绑定 run 与能力；新人的个人提示词独立加载。待决审批处理见 03 的绑定变化规则。

## 6. 职位和个人提示词

职位公开字段：name、publicSummary、职责 prompt、workflow/node bindings、model override。职责可由项目 owner/manager 修改，产生版本；节点必须属于该项目已发布 workflow。同岗多人实例各自采用稳定 identity＋当前 binding，不把 templateId 当人。

个人提示词 `/projects/{id}/me/preferences` 只返回本人；owner/manager 和主 Agent 目录只能见公开职责。岗位子 Agent 的 ContextBuilder 在受限运行中注入该人的偏好。每轮模型调用固定引用的 preferenceRevision，不在流式中途改 prompt；下一次调用按当前版本重建 manifest 并记录变化。

不得把输入提示词当 RBAC 规则。公共职责优先于个人方法偏好，系统权限高于二者。更换绑定不转移偏好。个人配置复制到另一个项目使用明确“复制我的配置”动作，随后各自维护，不建立跨项目共享指针。

## 7. 流程编辑与发布

流程由结构化 nodes、advisoryEdges、hardRules、approvalPolicies 和 instructions 作为权威数据，Mermaid 由这些字段生成，禁止把任意 Mermaid 字符串解析成权限。

节点至少有 id、name、responsibility、allowedPositionIds、defaultApprovalPolicy。hardRule 类型只能是经过实现的白名单结构（task_acceptance / handoff_receipt / material_ready）；任意自然语言规则由 AI 提议后人工确认是否纳入结构化硬条件，不能执行任意表达式或 SQL。

管理者编辑 draft，发布时校验唯一 nodeId、引用、绑定、模式与硬依赖无环；原版本 immutable。AI 可以创建新草稿和差异摘要，不能调用 publish workflow 直接生效。规则、图、环节说明同版本。

新版在后续模型调用生效，但不能全量作废不相关审批。服务端比较规范化约束 hash 与审阅 manifest：相关节点/职责/硬条件/人员改变标 affected；文字风格改动仅提示。无法确定的语义影响标 needs_review，由有权人确认受影响内容，不能让模型自行判“没影响”跳过。

## 8. 模型配置与配额页面

部署提供模型目录、端点、Secret 引用、支持工具/图像/上下文长度/流式等能力。项目选择 defaultModel，职位可 override；API/CLI 只获得 ID、公开能力与可用状态。凭据轮换不改变 model ID，运行记录版本引用。

项目配置 discussionMaxRounds=3（1–100），单批模型调用/Token/并行子运行/运行时长/沙箱资源设部署上限；项目只能降低，不得突破部署限制。缺能力（如图像不可用）返回明确限制，不静默丢附件。无模型时用户仍可注册登录、看工作和人工操作。

## 9. 本模块完成标准

真 PG 下两个账号可注册、登录、各自创建项目；重复邮箱和超限请求失败；项目外查询/下载/SSE 不可见。邀请接受、撤销、过期、同岗多人、多岗、替换、退出与 owner 转移均有独立事务测试。UI 覆盖所有失败状态，不仅 happy path。

参考：[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) 用于密码哈希方法依据；上述数值为本计划工程初值，必须做部署容量测量，不将文档示例当作已经实测。

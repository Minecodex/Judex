# 04 讨论、材料与事件

## 1. 消息、提交包和议题

正式入口为项目总览，project_room 保留为项目级讨论对象，不再收拢全部任务更新。计划拥有稳定的 mainTopicId；从讨论形成的计划冻结来源消息位置，建立独立主讨论分支。手工议题命名属于人的明确动作，AI 新议题建议先持久化，人工选择后建立或续接会话。议题与计划/任务是多对多引用，链接不改变状态。交接聊天绑定 handoffId，不能与普通 topic ID 混用。完整规则见 [会话任务协作与分叉](../../会话任务协作与分叉.md)。

Web 和 CLI 共用 submission：文字＋所有材料版本＋原始 clientSubmissionId＋可选 topic/task/identity。目的 purpose=message/progress/delivery/material；用户不指定目标时进入项目材料收件区，平台 AI 可生成关联建议，由人接受后生效。

同一个提交中的附件未 ready 前，不触发正式分析，也不把仅有文字标为“已检查全部”。流程：staging upload → ready material versions → finalize submission（DB 事务）→ committed message/report＋outbox＋discussion batch。前端可先显示本地上传进度，但服务器最终 record 只引用完整清单。

message 的作者类型 human/agent/system、authorUserId、identityId、source(web/cli/platform)、submissionId/runId 均服务端推导；普通人不能伪造 ai 或另一个人身份。UI 对内部岗位分析、协调摘要、正式提交报告、决定事件分别标记，禁止用同样“已批准”样式显示建议。

避免双写报告：带 taskId、purpose=progress/delivery 的 submission 必须携带 expectedTaskVersion；finalize 时在同一事务调用 work.Report，唯一生成 work_report＋message，返回 reportId。`/tasks/{id}/reports` 是同一应用用例的入口，引用已处理 submission 时只返回已有 reportId，不再建第二份报告/讨论批次。两个入口采用同一领域唯一约束，不能仅依赖不同 URL 的幂等键。

V1 最终消息追加保存；不做无审计原位编辑。纠正用新消息并引用旧消息，删除敏感内容的运维流程独立审计。聊天无暂停/恢复开关；取消的是某次 AI run，不关闭用户输入。

任务 progress/delivery 沿用 work.Report 的任职、任务状态、版本与附件门禁。question/reply 使用 purpose=message、discussionIntent 与 taskId；reply 必须明确指定 topicId，任务通信不构成交付贡献。任务时间线以 report 为规范来源，同一 report 与 backing submission 不重复显示；cursor 分页保留完整历史。无任务引用的普通讨论仍使用议题分析。

分叉端点 POST /topics/{topicId}/fork 冻结 forkAfterSeq。共享历史解析器根据各级父链与截断位置读取原消息，不复制消息、材料、提案、审批、投票或运行上下文；分页返回 inherited、originTopicId、原 ID 与固定版本。子分支的新 seq 从截断点之后继续。中央按任务汇总最新活动与记录数量，完整记录留在任务时间线。

task.activity.changed、analysis.changed、discussion_suggestion.changed 与 topic.forked 失效 apiWs 查询；前端保留当前会话、筛选、草稿、标签与阅读位置。后台分析或成员的外部更新不会主动跳转路由。

## 2. 上传合同与状态

默认工程限制：单文件 100MiB、HTML 包 200MiB、每次提交 20 文件、文字 64KiB；均部署配置化并通过 `/capabilities` 返回。浏览器/CLI 前置提示不替代服务端限制。

1. POST uploads 提交 name、size、sha256、mime、project、kind，获得 uploadId 与分片方案。
2. 首版由 API 鉴权流式代理至 S3（避免浏览器无法访问内部 S3 地址）。分片推荐 8MiB，服务端按编号记录校验；接口不能把整文件读内存。将来签名直传可替换传输，不改变 complete 语义。
3. complete 检查全部分片、实际大小、摘要与 MIME/文件格式；S3 multipart ETag 不可当完整 SHA256。初始版本先处 staged。
4. finalize material 在 DB 锁下分配不可变 version，并登记 manifest/entries；只成功一次。网络丢响应后同键 complete 返回同 versionId。
5. 解析和索引异步，失败保留原件。material ready 表示原件可读，不表示 AI 已理解/测试通过。

上传会话过期默认 24h；清理孤儿对象前核验 DB 无正式引用且超出宽限时间。不要在失败请求中直接删除一个可能已被另一个重试登记的对象。

## 3. 文件版本、路径和授权

对象键由服务端分配，保留原始展示名但不据用户文件名拼服务器路径。每个项目映射独立 bucket/prefix；上传主体仅可操作本项目会话。下载经成员资格检查，支持范围请求、Content-Disposition 和 MIME 防嗅探。

项目成员统一可读项目共享资料，不再加逐材料读白名单；私人 prompt、模型 Secret、run 私有上下文用独立表/对象前缀，任何公共 list/export/publish 都不自动带出。

同名文件不覆盖：materialId 固定，new version＋source manifest；旧审批永远引用旧 versionId。针对已有材料派生发布要求 expectedSourceVersion=currentVersion；落后返回 SOURCE_VERSION_CONFLICT，保留产物以便重新适配。版本 content 缺失标 unavailable，不能提供空内容装成功。

下载链接默认走鉴权代理。若优化为签名 URL，默认有效 60s 并记录“短期无法撤销已发 URL”的限制；退出成员立即阻止再签发。不能把永久公开 URL 当项目授权。

## 4. HTML/CSS/JavaScript 包

材料包必须有 entrypoint、relativePath/sha256/size 清单，保持相对依赖路径。拒绝绝对路径、`..`、Windows drive/UNC、空字节、重复路径、大小写冲突和 symlink；解压限制文件数、总解压大小、压缩比，不能只比较字符串前缀。

Web 预览必须与应用鉴权 origin 隔离：独立 preview origin＋iframe sandbox，只按需要 allow-scripts，**不授予同源应用权限**。预览 origin 不接收 session cookie，不共享 localStorage；CSP 禁止顶级导航、表单提交、未授权外网和弹窗。短时材料 capability 只授予这一版本，禁止在主应用 origin 原样执行上传 HTML。没有隔离 origin 配置时只提供源码/下载并提示不可交互预览，正式“完整网页包”验收不得将其算通过。

沙箱浏览器从只读挂载固定版本路径或本次运行 localhost 服务加载，禁外网；缺外部后端/认证/资源则明确列出限制。区分 source_read、rendered、interaction_checked，模型一句“看过”不能代替工具证据。

完整应用由成员本地部署到项目环境，Judex 关联 environment URL＋准确版本；HTML 材料预览不承担任意全栈应用托管。

## 5. SSE 与缓存一致性

每个已加入项目订阅 `GET /projects/{id}/events?after={seq}`。持久业务事件 ID 使用项目 seq；同事务分配，见 01。event payload 最小化：eventId、projectId、seq、type、objectType/id/version、occurredAt、changedFields/refs，不发送私人 prompt 或全数据库快照。

事件种类：message.committed、proposal.changed、task.changed、plan.changed、handoff.changed、material.ready/unavailable、workflow.published、membership.changed、run.changed、notification.created。流式增量使用 `/runs/{id}/events` 独立序列，和最终消息版本分开；丢片可从 committed 消息恢复。

客户端 bootstrap 获取 resource snapshot＋eventCursor；连接 after=cursor，按 eventId 去重/按 version 拒绝倒退。事件缺口导致重新查询，不靠 last-write-wins 合并所有 WorkState。长会话用游标分页，消息回填不重置用户当前滚动锚点。

持久事件保留默认 7 天；过旧 cursor 连接前返回 409 EVENT_CURSOR_EXPIRED，前端重新 bootstrap；不能静默从最新开始。15s heartbeat；SSE 单独 write deadline/flush，Ingress 禁缓冲、配置长连接；断线指数退避 1–30s 并附 Last-Event-ID 或 after。

鉴权在建连接时及周期性心跳复核；成员撤销 event 促使关闭连接。前端收到 401/403/404 清掉该项目缓存/私有草稿，不继续展示来自其他用户缓存的内容。不能把 SSE 当消息持久化通道。

## 6. 站内提醒和待办

`/me/actions` 查询正式未完成动作：待我提交、审批、接收、验收、修订／重开处理，依据当前 binding 计算；notification 是提醒，不是第二份决定对象。待办卡和聊天卡使用同 objectId/reviewId。

到期提醒按 eventId/type/recipient 去重；点击已处理事项展示实际结果而非再次批准。手动提醒有冷却时间，不无限轰炸。首版站内通知/未读计数必做，邮件/企业 IM 非阻塞扩展。

## 7. 完成标准

双浏览器真实会话同步；断连期间多事件不漏；过期游标恢复；上传中断续传和 complete 重试只登记一次；跨项目读取被拒；HTML 包在隔离预览可交互但无法取得应用 cookie；模型解析失败原件仍可下载。任何 localStorage data URL 的生产依赖必须清除。

## 2026-09-29 材料读取补充

新增项目下 material-versions/{versionId} 的元数据及 content 入口，供 CLI 固定版本下载。未指定 entry 时返回原始文件/ZIP 字节，指定 entry 时读取包内条目。下载设置 Content-Length，CLI 再比对长度和 SHA256；不会覆盖已有输出文件。Agent 产物通过与上传同样的材料版本和独立预览机制访问。

## R7：加载早期记录后，切换分区会丢失浏览状态

优先级 P2。路线抽屉和讨论右侧标签使用同一 TaskTimeline，均可复现：

1. 打开任务记录，不带 activity 来源参数；加载早期记录至 41 条。
2. 滚动到 900px，再切换至概览。
3. 返回同一任务的记录分区。

| 位置 | 切换前 | 返回后 |
| --- | --- | --- |
| 路线抽屉 | 41 条，scrollTop=900，scrollHeight=9547 | 3 条，scrollTop=135，scrollHeight=838 |
| 讨论右栏 | 41 条，scrollTop=900，scrollHeight=9184 | 3 条，scrollTop=137，scrollHeight=811 |

根因位于 `web/src/features/chat/TaskSurface.tsx` 的 TaskTimeline：历史展开标志 older 只保存在组件内。分区切换后组件重新挂载，标志回到 false，渲染重新收缩为最新 3 条；useReadingPosition 虽保留目标偏移，短内容无法恢复 900px。历史报告仍在数据源中，丢失的是浏览状态。

计划要求右栏标签和任务分区恢复阅读位置。现有全屏用例带 activityId，会自动展开历史，因此没有覆盖此普通浏览场景。新增用例保留期望行为断言，两处均失败，未放宽断言。

修复应在共用任务阅读状态中按项目、用户、任务、分区和查看器范围保存历史展开状态，并在相应内容恢复后恢复偏移。应继续保持对象隔离、来源定位、历史分页和全屏退出时的原位置；需要补充真实 API 多页记录的同类验收。

证据：

- [复现用例](../../../tests/e2e/demo4-reading-audit.spec.ts)
- [执行日志](../../../.cache/demo4-review3/reading.log)与该目录下的 reading-results trace
- 当时实际结果记录在上表和原始 reading.log，初始输出目录中的图与 JSON 在后续调试中更新。
- 最终修复使用独立 `repair-reading/` 的图与 JSON，见第三次修复记录；原始失败断言未放宽。

本轮长记录用例使用正式组件树和等价预览数据，验证浏览状态，不将其表述为真实 API／数据库验收。

## R5：外部任务的详情入口没有可靠加载／导航

真实 API 场景：同项目有两个计划，当前计划草稿任务以另一计划的正式任务为开始前置。服务器返回正确外部边，单项任务 API 可读取该前置。

从冷启动项目列表打开当前计划的全屏预览，点击任务卡的外部依赖按钮，界面显示“任务不存在或已不可访问”，任务 Inspector 没有出现。原因是 PlanCanvas.onExternal 在找不到缓存任务时只设置本地 selected id；随后 task 仅从 state.tasks 与当前路线 tasks 查找，没有按该外部 id 查询。TaskInspectorData 需要先拿到 task 才执行，不能补此路径。

点击概览前置条件旁的详情按钮，在预览及普通路线中都可能没有反应：传入的 onTask 同样只查已加载数组，查不到就结束。流程参考分区的任务来源按钮具有自己的单项查询／objectNavigation，因此该入口通过不能替代卡片及概览入口的验收。

复现用例 `tests/e2e/business.demo4-audit.spec.ts`；使用真实 PostgreSQL／对象存储及生产构建。问题复现成功，不等于目标行为通过。证据 `.cache/e2e/judex-e2e-5752-1791507127509/business-results/` 中 `external-task-unavailable.png`、`prerequisite-click-no-action.png` 和 external-link-reproduction 附件。场景清理与备份恢复完成，未触及常用业务数据。

应统一按对象 ID 查询和选中／来源导航，缓存命中只优化读取，不能决定入口是否可用；保留预览只读、中央讨论范围及返回位置。

## R6：阻塞任务在对应区域的状态表达未统一

同一等价样本中，“功能开发”依赖仍 working 的“交互评审”。路线卡片显示 blocked／等待前置，抽屉标题和讨论计划任务列表却显示 ready／待开展。实际开始按钮仍禁用，所以没有错误放行，但读者看到的状态不一致。

Demo4 的 TaskHeader 与 PlanPanel 都使用 taskStage(state, task)，与路线相同地显示阻塞。正式路线另行计算 blockers，而 TaskSurface 和 PlanContext 使用只返回原阶段／跳过／丢弃的 taskDisplayStatus，未表达前置阻塞。这是界面一致性和信息呈现遗漏；业务原阶段应继续保存，不能为修改徽标而把数据库阶段改成 blocked。

复现 `tests/e2e/demo4-status-audit.spec.ts`，以实际参与人身份验证；`.cache/demo4-review2/blocked-status.json`、`blocked-card-ready-inspector.png` 保存卡片 blocked、详情／上下文 ready、开始禁用的事实。该用例断言问题现状，不能计为修复验收。

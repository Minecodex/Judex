# 草稿修订与任务运行例外

本轮扩展工作领域，沿用成员本地执行、AI 分析、人工批准的边界。任务阶段继续是 draft／ready／working／delivered／accepted／rework／cancelled；阻塞、丢弃、跳过分别投影。

## 草稿与正式安排

PUT `plans/{id}/draft`、`tasks/{id}/draft`（项目 API 前缀）接收 expectedVersion 和 fields，复用范围、有效任职、流程及前置校验，只接受已有可修订字段。作者、当前计划负责人、本项目管理员可保存。作者缺失时仅按负责人／管理员处理。

保存是一笔项目事务：锁对象、核对版本和权限、修订内容、实体版本递增一次、撤回受影响当前审阅并保留旧名单／决定，登记操作与事件。前端输入按对象／用户保存；冲突保留输入，重新对照最新内容再提交。正式修改继续 work_change 提案及职责会签，生效前使用原安排。

成员通过 work_change 会签修订草稿时，也使用同一撤回规则。工作变更应用完毕后，在同一事务撤回涉及已修订草稿的其他当前提案，只排除正在合法提交的冻结 reviewId；不排除同一作者的其他提案。旧冻结内容、同意和职责名单保留，旧计时任务只作幂等空操作。变更组或事务提交失败时，内容、撤回与事件一起回滚。

GET `.../discard-review` 冻结所属草稿和有效引用；POST `.../discard` 绑定 expectedVersion、reviewHash。所属正式任务、外部前置／父子引用、跨计划成果引用、报告／验收／交接正式依据阻止删除。整计划可同时丢弃内部关联的未生效任务。返回 id、status、version、discarded。

删除使用 discarded_at 标记，默认查询和路线移除；单项历史查询、话题、共享资料、报告、审计保留。

## 跳过与恢复

GET `tasks/{id}/execution-review?operation=skip|restore` 返回目标版本、当前例外、受影响后继、直接条件指纹、已开展信息、引用计划和审阅哈希。POST `tasks/{id}/skip|restore` 接收 expectedVersion、reviewHash、reason、明确的 waivers 及 acknowledgeStarted。服务端在事务内重新核对状态、权限、依赖和流程。

仅当前项目 owner／manager 能操作已生效且未最终验收任务，包含 delivered。管理员仍不自动取得 reviewer 权。Web 命令要求人工渠道；CLI 准备 typed confirmation intent，浏览器确认一次后读取同一 resultRef。

例外保存原阶段、操作者、时间、原因及具体 waiver（后继 taskId、requirementId、原定义 fingerprint）。不改原阶段、流程模板、报告、交接或验收历史。只有明确列出的任务验收条件被豁免；定义变化后旧指纹失效，没有选择的条件继续阻塞。

有效条件沿豁免的任务条件向上展开，传递全部硬前序、材料和交接条件，在实际消费任务的开始／验收阶段分别检查。连续跳过保留最近有效前序，多前置单独核对；循环不能放行。图保留灰色节点、原虚线及绕行线，命令始终按同一有效条件检查。

恢复撤销当前例外／豁免，保留已发生工作。后继已有 working／delivered／accepted／rework 事实时要求明确核对影响，不自动回滚。跳过不自动启动后继或完成计划。

所属跳过任务不计入已验收或正式必需任务分母；引用计划仍核对其原成果。负责人整体验收快照包含例外、任务版本和历史 acceptanceId。

## 数据、查询与失效

迁移 25 在 plans／tasks 增加 discarded_at，新增 task_execution_exceptions、work_change_records，原业务行和验收历史不重写。操作记录支持 web／cli 来源，与报告一起分页。

Plan、Task、ExecutionMap 返回权限、丢弃及例外事实；统计分开 required／draft／skipped／accepted。Task 单项与列表均投影有效条件及 satisfied 状态，材料和交接使用服务器事实，不由前端猜测。跳过的既有交付可读取，待决定列表不冒充待验收。事件刷新任务、路线、统计、记录与待决定事项。Agent query_work、当前工作上下文读取同一有效条件和阻塞；AI 只能分析，不能直接跳过、恢复或批准。

OpenAPI、生成类型及 CLI 同步。`task skip TASK` 无 reason 时只读预览；`--reason` 准备确认，重复 `--waive TASK:REQUIREMENT` 明确范围；restore 对已开展后继使用 `--acknowledge-started`。context get 返回独立例外及原任务状态。

成员可先保存本职责 delivery，贡献未齐时整体仍为 working。当前约定必需贡献齐备且有人明确提交 delivery 后进入 delivered；验收快照核对全部当前贡献。progress 不自动交付整个任务，各报告、固定材料和原始来源保持可追溯。

## 详情与来源导航

流程参考分别展示当前已发布环节的职责、全局说明和适用硬规则。任务规则读取任务，材料规则读取指定 materialVersionId 的元信息，交接规则读取指定来源的实际版本、发送／接收人及来源任务。检查阶段独立展示；依据缺失或无权读取时保留明确提示，不显示空标题或猜测版本。定位计划使用共用路线查看器，选中当前任务；同一全屏查看器内定位复用当前画布。

列表预览保持外层路由不变，由 TaskInspectorData 按当前任务补齐职位、任职与已发布流程的只读数据，复用 apiWorkspaceQueries、mapSeat、mapPosition 和 mapFlow。加载中／失败独立呈现，不以轻量列表的缺失数据推断“未关联流程”或伪造人员。来源任务没有所属计划时仍进入共用任务详情，讨论内的任务来源只切换右栏对象。

记录讨论、流程设置、材料关联及使用记录通过共用 SurfaceNavigation 退出查看器再导航，不覆盖目标会话、不回写进入前路由。退出／Esc 仍恢复原图、分区、来源筛选及阅读位置。交接来源链接使用页面参数 source 定位原贡献，离开交接时清除该定位；这不改变业务依据版本。抽屉保存实际打开来源，关闭后恢复该控件焦点，来源移除时使用仍可见的合法画布入口。

资料使用历史复用统一 paging.Query 和 HTTP 分页入口，限制与游标同时生效；资料总量单独返回 totalCount，不作为分页游标。所有来源读取继续核对当前项目成员权限。

路线、外部依赖和概览前置入口统一按任务 ID 选中，TaskDrawer 通过 useTaskDetail 读取同一项目／用户的单项任务查询。缓存只提供加载中的已知内容，不决定入口是否能打开；预览中的外部任务继续只读，保留原画布、选中与来源焦点。查询失败不冒用上一任务内容，区分暂时网络错误与不可访问，并提供对同一 ID 重试。外部任务所属计划按实际单项查询补齐，不使用当前画布计划代替。

阻塞是显示投影。taskDisplayStatus 统一用于路线、任务标题和计划上下文，先区分丢弃／跳过，再在 ready 阶段核对开始前的硬条件；验收阶段条件、软参考条件和已经满足／豁免的条件不造成开始阻塞。路线可使用同一服务端执行节点阻塞事实，详情和上下文使用条件的 satisfied 投影。数据库阶段、安排版本、统计及服务端命令校验均不由显示徽标修改。

任务记录的浏览状态统一由 useTaskRecordReading 保存，按运行模式／项目／用户／任务／查看器范围隔离历史展开、已读页数、来源及原文展开。切换分区和刷新后补取已读页，useReadingPosition 以最后观察到的偏移恢复；旧分区清理不读取已被新内容缩短的容器位置。全屏复制当前浏览状态，退出不回写查看器内变化；记录来源只定位当前任务。浏览偏好保存在当前用户会话，不改变业务查询权限、任务阶段或审批依据。

工作区右栏对自带内容间距的 PlanContext 使用零外层 padding，计划内容沿用 24px spacing token；溢出规则独立于间距规则，计划长列表继续由 body 滚动并恢复阅读位置。任务详情保持自身内部滚动，其他右栏工具继续使用通用容器约定。

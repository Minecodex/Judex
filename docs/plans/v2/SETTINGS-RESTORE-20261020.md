# 项目设置与内置库恢复

用户反馈项目设置过于简化，旧版内置职位／工作流消失，成员及其他管理界面需要重新设计。本轮以旧版设置的信息组织与库的使用体验为依据，继续使用当前 HeroUI／统一 token；已在 v2.16 完成并升级本机；[实际验收记录](records/SETTINGS-RESTORE-20261020.md)和[机器记录](records/settings-restore-acceptance-20261020.json)保留本轮范围。

## 已确认的问题与实现边界

V2 清理旧领域时一并删除了内置库和导入接口，仅剩手动编辑模板。旧版 Git 基线有 20 个场景、118 个职位、51 个工作流。本轮恢复全部库内容和按场景挑选／预览／批量添加体验，替换提示词中的旧任务／审批状态机要求。

引入 `internal/collab/catalog` 作为服务端内置参考模板来源，新增 `GET /template-presets` 和 `POST /projects/{projectId}/template-presets`。后者仅允许项目管理者操作，使用现有事务、幂等、授权和个人配置事件机制；客户端不能用自行提交的提示词冒充内置模板。schema 13 为职位和工作流增加来源标识及项目内唯一索引，导入后可自由改名和编辑；重复导入跳过，不覆盖用户内容。并发导入按项目串行，批次失败整体回滚。

工作流导入为包含步骤、职责和建议协作关系的可编辑参考文本，不恢复旧审批、验收、交接或任务引擎。职位在群里任职后才形成岗位 AI，导入不会自动创建身份、成员或模型运行。

## 界面

- 项目设置为宽面板，左侧一般设置、成员、职位、参考工作流、个人提示词，右侧各自完整内容。
- 一般设置分项目信息与模型／讨论配置；保留草稿原版本与显式冲突恢复。
- 成员列表使用头像、姓名／邮箱、权限标识和行菜单；搜索添加已注册用户，移除前说明影响并确认。
- 职位和工作流为卡片列表；支持搜索、新建、编辑、预览和版本历史。内置库按场景筛选、选择、批量导入和已添加去重；工作流预览展示全部步骤、协作关系及建议职位。
- 个人提示词按职位切换，明确私有范围和提示词组合方式。
- 群设置拆分信息、成员任职、参考工作流；成员选中后展示其岗位选项，保留独立成员与多岗。
- 通知、账号、客户端连接共用相同层级、留白和卡片。客户端下载显示真实发行包。

中文／英文、深色／浅色、加载／失败／空态、权限和版本冲突均在正式产品上验证。旧版内容只恢复其仍适用的协作指引，历史领域不回归。

实际验收发现并修复个人提示词初始版本合同不一致：新建版本 0 可提交，已有内容只接受当前版本更新，过期创建／更新返回冲突。16 项服务新增检查和 11 项浏览器新增检查已纳入整体测试入口。

# V2 领域、接口与执行合同

更新：2026-10-20。本文是正式 V2 合同，覆盖实施过程中明确的边界。历史 V1 计划、任务、交接、审批、验收、协调批次及 `call_agent` 不属于正式服务。

## 领域与事务

| 聚合／记录 | 不变量 |
| --- | --- |
| Project | 项目负责人／管理员维护项目描述、默认模型、闭环上限（1～100）、直接添加的已注册成员及模板 |
| Position／WorkflowVersion | 稳定模板 ID；每次修改新增不可变修订；岗位可覆盖项目默认模型；个人提示词按项目／人／职位复用 |
| Conversation | `group` 或 `dm`；各自持久递增 messageSeq、eventSeq 和每人 readSeq |
| Group | projectId、固定 parentId、depth 1～3、目的和参考工作流；多同级子群；不提供移动接口 |
| GroupMembership | 有效项目成员的独立群成员资格；不继承父群；创建与修改时保留操作者，至少两位人类成员 |
| RoleAgent | 群／人／职位唯一稳定身份；移除停用，再加入复用该身份；同人多岗、同岗多人独立 |
| Message | 真实人类作者、可选岗位身份、web／cli／agent／system 来源、回复、结构化提及、固定文件版本、显式分享的原作者信息 |
| File／FileVersion | 同名不合并；显式更新检查文件 version 并增加 revision；原件键只属于一个不可变版本 |
| Discussion／Delivery／RoleRun | 每群最多一个 active／paused 讨论；因果路径、共享闭环计数、投递去重、岗位串行租约、运行 fence、检查点和工具日志 |
| ContextSnapshot | 每群共享版本、知识 sourceSeq、摘要 coveredThrough、近期原文索引与原始引用 |

消息、固定附件引用、知识登记、提及通知、个人事件、会话事件和岗位投递／数据库任务在同一 PostgreSQL 事务完成。数据库队列使用 `FOR UPDATE SKIP LOCKED`；不引入消息中间件。

所有业务写操作要求 UUID `Idempotency-Key`。同键同内容重放原结果，同键异内容冲突；重放前重新检查当前资源权限，撤权后不能重放旧成功响应。配置修改、归档、文件更新与讨论控制检查 `expectedVersion`。作者和消息来源由 Web session／CLI grant／服务端 Publication 解析，客户端不能指定。

Web 公共请求层只有在读完并验证成功 `{data,meta}`、204 或明确的 4xx 错误后才确认本次写入。网络中断、正文截断／无效成功封装和 5xx 保留会话内原动作的幂等键；同一内容重试核对原结果，确认成功后的再次提交使用新键。上传保留所属用户、会话、文件摘要与分片进度；完成响应不确定时重试同一 upload，不能先取消再创建副本。

网页一次多选对应一个批次，当前登录工作区按会话保留每项的创建／分片／完成键及已确认版本。单项失败不丢弃整批结果，重新选择整批、子集或「继续本批上传」只确认未完成项；恢复卡片列出已确认／待确认项。全部确认后再次上传为新意图；明确结束未完成批次也允许新意图，但不删除已经提交的文件。文件字节只保留在当前页面内存，不写入浏览器持久存储。

未加入祖先的名字和 ID 不出现在群列表。群内可见同群作者、岗位关联人及成员，不因此获得父群资料。移除项目成员同步撤销本项目全部群成员、岗位与运行；单群移除只影响本群。历史作者、文件版本和既有分享继续保留。

平台私聊由无序两人组唯一标识，跨项目复用，仅双方可读；不存在岗位 AI、公共知识或模型触发。

CLI 还受 grant scope 与 projectScope 限制；不能修改群配置、成员或控制讨论。统一鉴权覆盖 HTTP、分页搜索、SSE 补收、预览能力、下载、CLI、公共上下文和沙箱。长连接和预览能力持续核验原会话／grant 与当前成员资格。

非空 `projectScope` 必须在项目列表查询层过滤，范围外项目的 ID、名称和描述均不返回。空 scope 仅允许发现本人项目，具体资源仍须取得对应项目授权。

CLI `message send` 需要 `messages:write`，包含结构化岗位 AI 提及时额外需要 `agent:request`；普通文字、@人和显式回复不会因保存而唤醒 AI。`push` 接口需要 `agent:request`，包括 `--record-only`；后者仍保存内容但禁止全部 AI 投递。`recordOnly` 不能用于普通消息接口绕过 AI 授权。服务端领域入口与幂等缓存读取前共用效果鉴权，较宽 grant 的旧响应不能赋权给较窄 grant。

## API、事件和 CLI

唯一可执行资源规范是 [OpenAPI](../../../api/openapi.yaml)，由 `api/openapi.header.yaml`、`api/paths/*.yaml`、`api/components/*.yaml` 生成。当前 74 个路径、82 个操作全部注册；前缀沿用 `/api/v1`，协议能力为 **2**。Web／Server／CLI 必须同版。旧业务路径返回不存在，不保留兼容领域。

| 资源族 | 路径 |
| --- | --- |
| 身份 | `/auth/*`、`/me/*`、`/users`、`/models`、`/system`、`/capabilities` |
| 项目与指导配置 | `/projects`、`/projects/:id/members`、`positions`、`workflows`、各模板 `versions`、`personal-prompts` |
| 内置参考库 | `GET /template-presets`、`POST /projects/:id/template-presets` |
| 群 | `/projects/:id/groups`、`/projects/:id/groups/:groupId`、`/groups/:id/archive` |
| 消息与私聊 | `/direct-conversations`、`/conversations/:id/messages`、`read`、`events` |
| 文件 | `/conversations/:id/uploads`、分片、complete／cancel、`files`、`file-versions`、content／preview／entries／copy／retry-preview／preview-session |
| 分享与知识 | `/groups/:id/shares`、`context`、`context/reference`、`snapshots` |
| 岗位与讨论 | `/groups/:id/push`、`runs`、本人 tools／reconcile、`discussions`、`discussions/:id/control` |
| 个人事件 | `/me/events`、`/me/notifications`、通知 read |

成功为 `{data,meta}`，错误为 `{error,requestId}`。消息按 before／after 序号、知识按 after 序号分页。SSE `id` 为持久事件序号，支持 `Last-Event-ID` 或 `after`；个人与会话序号独立。消息、成员、归档、讨论、文件就绪、阅读、通知、撤权等事件使真实查询缓存失效。断线后补收；撤权关闭连接。

内置库为 20 场景／118 职位／51 工作流的双语参考内容，登录后可读。导入限人类项目负责人／管理员，提交目录版本、语言及至多 200 项唯一模板 ID；内容由服务端目录解析。批次事务原子提交，项目内按来源 ID 或双语同名跳过已有项，保留改名和编辑；schema 13 的 `preset_id` 唯一索引确保来源身份。导入复用模板修订和项目配置事件，不创建群、任职或模型投递，不恢复旧业务状态机。

个人提示词的新记录使用版本 0（省略按 0 处理），已有记录更新必须提交现有版本；重复创建及过期更新返回版本冲突。列表与变更事件只返回本人数据，提示词不进入公共知识。

项目创建／修改、项目成员变更、职位及工作流创建／修订在事务内向有效项目成员发布 `project.changed` 个人事件，载荷仅含 `projectId/resource/resourceId`；不依赖聊天、不要求加入某个群，不携带群名称或 ID。`personal-prompt.changed` 仅发给本人，含 `projectId/positionId`，不含提示词正文。补收时重新核验项目范围及成员资格。事件只刷新查询，不唤醒岗位 AI。Web 配置 409 无论是否收到事件都会主动重取服务端版本；本地草稿及编辑基准保留，明确重新载入或关闭重开后使用最新版本。

CLI：`auth login/logout/status`；`project list/use`；`group list/use/show`；`message list/send`；`context read`；`file list/upload/download`；`push --text --file [--record-only]`；`run list`；`workflow list`；`inbox`；`watch`；`skill install/uninstall`。精确语法以 `judex help` 为准。设备授权保留，旧 grant 不导入，岗位目标由服务端解析。

带附件的 `push`／`message send` 在首次上传前按账号、服务端和整次命令保存恢复记录；附件完成回执持续保留至最终消息确认。跨 CLI 进程重跑相同参数与文件内容复用阶段键、固定版本和最终 wire body；最终响应未知时不重新上传已完成附件。`pending` 显示组合操作；同意图并发执行由本地跨进程锁串行保护。默认操作确认后退役，之后再执行是新意图；显式 `--request-id` 在确认后仍重放原意图，相同 ID 的不同内容拒绝。每次最终重放重新经过服务端授权，不能从本地回执直接返回成功。

`message send` 和 `push` 支持 `--reply-to MESSAGE_ID`，对应消息合同的 `replyTo`。网页从消息的「回复」操作选择原消息，草稿保存并展示引用，可取消；回复关系与结构化提及独立。AI 明确请求人回应时，`Discussion.waitingFor` 返回未解决的消息／人／岗位关联；只有对应人回复该问题才解除其等待，其他等待分支保留。回复本身不唤醒岗位，仍需明确 @AI；没有其他待处理分支时自然结束。

## 文件、预览与分享

上传按 8 MiB 分片、总计不超过 100 MiB，每片和整件校验 SHA256。文件库显示本群可读的最新版；消息永远打开引用版本。来源群更新不会扩张其他群已获的版本范围。目标群只能另存副本；移出文件库不删除消息引用或既有授权。

保留 Markdown、文本／源码、图片、PDF、Office 和 HTML 资源包；扩展 CSV/TSV 真表格、XLSX/XLS/ODS 工作表、DOC/ODT/RTF/PPT/ODP 转 PDF、静态 SVG 与 BMP/AVIF、音视频统一转换、Mermaid、TAR/GZ/TGZ/7Z 安全归档。具体格式及限制见[阅读器说明](WORKSPACE-READERS-20261020.md)。PDF／图片验证实际原件；归档拒绝穿越、符号链接、重复路径和超限展开。交互 HTML 用短期、固定版本、绑定原登录主体的能力 URL，CSP sandbox 禁止同源、外连和表单；会话失效或成员撤销立即失效。预览任务以队列 fence 防止迟到处理覆盖状态，派生内容用内容摘要键，原件始终不可变。

沙箱按岗位运行建立独立群文件投影，只有当前获准公共快照的固定版本，路径 `/workspace/group/versions/<versionId>/original`，只读挂载。不存在项目全量目录。沙箱不携带 S3 凭据和 Kubernetes service account token；签名原件 URL 只供可信准备任务读取。终止／完成后回收沙箱和所属 PVC，暂停保留工作目录供核对。

## 触发、闭环与恢复算法

普通网页消息零触发；结构化提及人只通知，提及岗位只投递该稳定身份；自我提及不投递。本地普通推送投递本人本群全部有效岗位，只记录不投递；无岗位仍保存并返回提示。公共知识更新不触发，不重置闭环。

每条投递保存不含重复闭合段的岗位因果路径。发送者提及路径中已有目标时，闭环计数加一，路径截到该目标；`A→B→A` 与 `A→B→C→A` 都算一轮。投递以讨论／目标岗位／触发消息唯一去重。会话锁使多分支共享计数和暂停原子化；重试／重启不会重复计数。

同一公开发言同时关闭多条因果路径时，也不得超过当前额度。先计入的闭环若恰好耗尽额度，其余闭环以 `Delivery.closure_pending` 持久保存；人工继续后，先在新增额度中逐条、且仅一次结算这些闭环，再恢复投递。新增额度被待结算闭环用尽时再次暂停。V2 migration 12 增加此字段，不改动账号、文件和历史发言。

当前档额度冻结；达到上限原子暂停后续投递、保留队列／检查点并向涉及岗位关联人去重通知。暂停期间新推送与提及并入原讨论，不能绕过额度。任何人类群成员可带意见／空意见继续，按项目最新上限再加一档；控制有版本冲突检查。终止取消未完成投递／运行、增加 fence，拒绝旧结果发表。全部分支结束自然收束；明确请求人回应只等待该分支，普通人类补充不自动唤醒 AI。

同岗位串行、不同岗位初始并行 2。每个岗位有独立工具协议日志、租约、fence、检查点与取消。模型请求前预留估算输入＋最大输出的技术成本；未知结果保留预留，已知 usage 结算。单档技术上限：30 次模型调用、300000 Token、30 分钟；与闭环次数分开。继续增加新技术档，不清除累计调用记录。 执行 Context 的绝对期限为持久 `budget_started_at + 30 分钟`，覆盖模型建连、流接收、共享摘要、投影及工具 I/O；无 finish 或长时间无事件的流也会到期取消。过期统一暂停为 `technical_budget`，发布入口再次以数据库时钟检查期限。重启、租约重领与模型回退均不补时间；人工继续建立新档。未知调用成本及工具副作用记录保留，继续不等于允许重放。

数据库发言／发布与工具完成日志同事务；文件写入通过摘要核对恢复。未知 shell 副作用明确暂停，只允许岗位本人通过私人日志核对结果，登记理由、确认完成或允许一次重试；仍需另行继续讨论。不能因进程重启盲目重放。

## 公共上下文与提示词

每次调用组合：平台执行约束＋项目描述＋群目的＋关联工作流＋职位提示词＋本人该职位个人提示词＋群公共快照。配置下一次调用生效，各岗位共享相同版本公共知识，私人执行工具协议分别保存。

群聊天、可读文件、显式分享和公开工具业务结果进入公共知识，含作者、版本和原文引用。私人提示词、隐藏推理和执行控制不写入公共知识。`read_context` 可按引用分页回读压缩前原文。

公共上下文预算按有效岗位模型的最小窗口，并预留提示词和执行容量。达 70% 统一压缩较早内容，目标降到 50%；保留近期原文、未回答问题、分歧、提及及文件依据。超大文件／工具条目以明确标识的索引节选进入快照，原件可回读，不假装未提供的部分不存在。摘要为空、失败或仍超预算均明确暂停，不丢弃原始资料。摘要服务不协调岗位。

公共预算同时纳入启用的额度备用模型窗口及其输出预留；每次实际调用再校验完整提示词、工具协议与当前目标容量。模型／提示词配置变化后，即使没有新原文也允许重新压缩旧摘要，覆盖序号不退回，原文引用继续可读；并发岗位共用 PostgreSQL 压缩租约和完成后的同一快照。

明确 `ErrorQuota` 才按已配置 `quotaFallbackIds` 逐个尝试可用目标，普通 429 限流、认证错误和未知错误暂停。已有文字或工具协议片段后不自动回退。摘要与岗位调用共用逐次持久日志和技术预算，每个真实请求先预留成本；已报告成本按实际结算，未报告的失败／中断保留预留，不把额度拒绝当作零消耗。回退不改变闭环计数或重新发放技术额度。

撤销成员或仅撤销任职均取消对应投递和运行、递增发布 fence，并在事务内重新判断讨论收束；保留其他有效分支。最后分支取消后，即使此前暂停或等待人工也自然结束，后续触发建立新讨论。

七工具：`read`、`bash`、`edit`、`write`、`read_context`、`send_message`、`publish_file`。不提供群管理、成员变更、跨群分享或旧委派工具。

岗位执行保留 2 个并发槽；文件预览使用独立的 1 个 worker。两者按 kind 从同一 PostgreSQL 持久任务表领取，避免长模型调用阻塞文件阅读，不增加消息基础设施。完整工具日志持久保留，过长的已完成工具协议转为公共原文引用，未配对副作用不压缩。

## 流程图草稿与个人资料（schema 14）

工作流修订同时保存 `content` 与 `graph.nodes/edges`，校验节点身份、连线引用、重复、自连、大小和数量；支持分支、并行、反馈。更新图与文字原子新增修订，省略 graph 时保留原图。不可变修订中的图进入岗位提示词，不增加状态机。

`POST /projects/{projectId}/workflow-drafts` 接受自然语言、locale 和可选当前草稿；`GET .../{draftId}` 返回 queued/running/ready/failed。仅人类 Web 项目管理者创建且仅作者读取；重放和结果读取仍重新授权。复用持久任务队列及项目默认模型，共用两个模型并发槽；每人一分钟最多 5 个新请求，最多 5 个未完请求，单次两分钟、8192 输出 token。进程中断后的未知调用不会自动重放，返回明确失败；生成成功仅保存草稿，应用及保存由用户决定。不调用协作工具、不创建群讨论。

`PATCH /me` 的 `displayName`、可选 `avatarData` 与 `expectedVersion` 原子修改个人资料。省略头像保留，空字符串移除；只接受有界 PNG/JPEG，服务端规范化为 256×256 PNG。`GET /users/{userId}/avatar` 仅登录用户读取，独立于群文件权限，private/no-store。公开用户投影带 avatarVersion，无头像时为 0。个人事件 `profile.changed` 只带用户 ID，通知本人和共享项目/会话的成员，刷新相关查询，不创建消息、公共知识或 AI 触发。新头像字段不会改变密码、会话和恢复凭据。

## 结构化确认（schema 15）

MessageInput 可含 `confirmation:{title}`，必须同时具有本群有效人的 `requiresResponse:true` 提及；不允许私聊或纯岗位接收人。消息读取返回 `confirmation:{title,version:1,closed,responses}`。指定人提交 `replyTo` 与 `decision:{choice:agree|changes|comment,expectedVersion:1}`；每消息／人唯一，普通明确引用回复记录 comment。回复投影保留 decision 的请求引用和选择。

服务端从已认证主体核验接收资格；不能指定回应作者。确认创建、回复、公共知识、通知与投递仍同事务，复用会话串行锁和幂等机制。只关闭对应人的等待分支；默认无 AI 投递，显式角色提及仍需 agent:request。暂停不重置额度，终止讨论拒绝迟到选择。此模型表达意见，不赋予外部动作执行权限，不构成业务审批。


### 2026-10-21 文件展示补充

`V2FileVersion` 增加 `authorName`、`authorAvatarVersion`，对应当前可读的固定版本的 `authorUserId`。昵称／头像反映账户当前公开资料；`createdAt` 仍是不可变版本的提交时间，不以分享时间替代。不返回邮箱、来源群信息或未授权的版本。文件列表与版本列表沿用现有会话权限校验。无需数据库迁移，协议能力仍为 2。

群 `members` 数组固定按 `conversation_members.joined_at, user_id` 排序，前端取前四位用于组合头像；列表与详情共用投影，继续过滤隐藏父群及无权限群。

## 交付内容

项目卡片与项目配置保留，正式产品改为独立群成员、三级子群、平台两人私聊和不可变文件版本。左侧群聊／私聊，中间真实消息与文件，右侧固定版本阅读；HeroUI、统一 token、TanStack Query、Zustand、中英文与深浅主题接入正式 API。加载、错误、权限失效、配置冲突、预览处理中与 SSE 恢复均有对应处理。

对等岗位身份为「群＋人＋职位」。群公共知识与摘要统一，岗位配置在每次模型调用重组。网页普通消息零触发，精准提及按目标触发，CLI 推送由服务端解析本人全部岗位。持久队列、租约、检查点、闭环额度、人工继续／终止及未知工具副作用核对落实在服务端。七个工具实际接入 OpenSandbox，文件只投影当前群获准快照至 `/workspace/group`。

旧计划、任务、交付、交接、审批、验收及协调／子 Agent 委派领域已从正式代码、路由、CLI、页面和生成合同移除。认证、模型、解析、存储与沙箱基础设施保留。OpenAPI 共 77 操作，路径前缀仍为 `/api/v1`，不实现旧领域兼容接口。

## 本机切换与账号

在 `docker-desktop` 的正常 `judex` 部署中暂停旧 Server 写入，先备份旧 PostgreSQL 和对象清单，再建立 `judex_v2`。11 份 V2 migration 初始化干净业务结构，认证导入器核对完整行内容。

| 导入表 | 行数 | 结果 |
| --- | --- | --- |
| users | 2 | UUID 及完整行一致；包含 1 位原用户和 1 个专用 V1 合成验收账号 |
| password_credentials | 2 | 密码摘要和字段一致 |
| user_sessions | 2 | 有效 Web 会话、CSRF 与字段一致 |
| recovery_tokens | 0 | 清单一致；隔离数据库测试另覆盖非空恢复记录 |

同版 Helm Chart、Server、Web、下载清单和原生 CLI 完成切换。迁移前合成账号的旧 Cookie、旧密码实际验证通过。原用户密码未知，未重置或索取；原用户的凭据完整行一致、原有效会话保持。旧 CLI 授权不导入，客户端须重新执行设备登录。

`judex-model-catalog`、`judex-model-keys`、`judex-opensandbox-auth`、`judex-postgresql` 和 `judex-storage-auth` 的 UID 与内容摘要均未变化。真实模型、存储和沙箱继续使用原配置；文档和镜像不包含 Secret 值。

正常入口完成 CLI 推送与真实模型原件读取后，旧 `judex` 业务数据库已删除，保留本机受限权限的私有备份。旧库有 1 个项目，未导入；旧对象 0 个、旧群投影 0 个。新文件原件使用 `v2/` 前缀。两个合成验收账号已停用、会话和 CLI grant 已撤销；验收群归档并保留审计。原用户仍为 active，原有效 Web 会话仍为 1 个，原用户不会看到合成验收项目。

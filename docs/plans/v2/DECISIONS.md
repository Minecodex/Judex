## 对设计的直接约束

本节结合七轮 Q1～Q55 整理，所有编号问题均已回答。较新答复覆盖旧规则：Q45 替换 Q28 广播，Q51 唤醒本人全部岗位，Q53 取消群模式，Q54 工具知识自动共享，Q55 多人闭环累计计数。整体理解等待最终核对。

1. 不将旧计划 / 任务换名为群；不在群树背后继续维护旧工作对象、业务状态或依赖门禁。
2. 取消由旧计划 / 任务派生的正式分工变更、交付 / 接收 / 拒收、验收及重开等业务状态链。不把 AI 对工作进展的判断变成需要人解锁的业务门禁。
3. 职位和流程只帮助 AI 理解职责和协作背景，不由职位名称授予群管理、私聊读取、文件访问或部署权限；应用操作授权仍须服务端校验。
4. 上传是否完成、消息是否送达、Agent 是否运行 / 失败等属于技术可靠性记录，不承担人的工作完成状态；具体技术实现后续由设计合同明确。
5. 父子群独立从项目成员中选人，不要求子群成员加入父群。群层级不自动授予其他群读取资格；新成员可见加入群的完整历史与仍保留文件。业务对话与 AI 记忆按群隔离，跨群信息须经明确分享。
6. 群文件隔离需要贯穿 API、搜索、文件读取与预览、事件、CLI、Agent 检索及沙箱投影；不能只过滤前端列表。
7. 私聊与项目群共用哪些消息 / 附件设施属于工程设计；平台级私聊不能被默认登记进项目共享文件或提供给项目机器人。
8. 同人在同群可兼任多岗，每份群成员 + 职位有独立 AI 身份与组合提示词。岗位 AI 可直接 @ 其他 AI 或人；@ 人只通知本人。所有本群 AI 共享群聊天历史、对应内容和业务知识，岗位之间不维护相互隔离的长期业务记忆。
9. 取消群级自动辅助 / 仅 @ 模式。网页普通消息未 @ 不触发；本地推送默认唤醒提交人在本群的全部有效岗位 AI，各自判断是否属于自己职责，再决定发言、总结和 @ 协作者。本地只记录能力保留。
10. 所有人类群成员均可维护成员、群简介、职位及流程关联；直接拉项目人员入群并通知，无须受邀人接受。AI 仅在本群发言、读文件、发布产物和 @，不自主修改群配置、成员或跨群分享。
11. 提示词由群目的 + 项目描述 + 关联工作流 + 职位 + 个人提示词组合，当前配置直接使用新版。群目的、项目与关联流程对同群 Agent 公共，职位与个人提示词对应具体身份；公共聊天和知识上下文一致。
12. 个人提示词按项目 + 本人 + 职位复用；群知识、历史和公共压缩摘要按群隔离。同群全部 AI 共用知识，父子群或不同群仍须显式分享。
13. 项目设置 AI 协作循环上限 10 轮，A @ B → B @ A 一次完整往返计 1 轮，不按普通发言或模型调用计。达到后全体人类群成员可用卡片给意见 / 继续 / 终止，并通知相关岗位 AI 对应人；多人完整闭环同样计一轮，全部分支共享上限。
14. 只显示本人已加入的群；不因项目成员身份显示未加入群的目录。
15. 同一文件支持明确新增版本，同名普通上传不合并。历史消息固定当时版本，群文件列表默认最新并可切历史。任意人类群成员可维护文件；从群文件移除后，历史和明确分享到其他群的版本仍可读。
16. 已加入目标群的项目 owner / manager 可将群归档；归档父群时全部子孙群一起归档，仍可讨论。不因级联操作授予未加入子群的内容读取权；归档不是禁言或冻结 AI。
17. 登录后先显示项目卡片，点击卡片进入参考图式群工作区。右侧文件区默认收起，点击文件后展开。平台私聊仍从独立入口进入。
18. 本地工具可读取有权限的指定群消息 / 文件，并推送内容。人可把消息、总结和文件明确分享到自己已加入的父群或子群。
19. Go 执行底座参考 Pi，四基础工具加少量群协作工具。岗位独立执行，同群公共上下文与摘要共用；@ 请求、公开意见和结果在群中显示，工具细节收起。本群工具取得的内容和结果自动进入公共知识（Q54 B）。

## 本轮新增的 Agent 执行方向

用户原文：

> 然后整体聊天 agent 可能应该是多 agent 模式，而不是以前的单 agent 然后 subagent 模式，这里也得考虑，多个 agent 也就是 pi agent 4个工具+上下文压缩，各个 agent 提示词就是根据群+项目描述 + 工作流 + 职位 + 个人提示词来组合而成，这个得注意对应

## 已确认的执行架构变化与核查

V1 的 Q068 及当前实现采用“协调 AI 独占委派，岗位结果返回协调 AI”；V2 的 Q13 B 改为岗位 AI 自主选择 @ 机器人或人。该产品决定已经确认，实际代码尚未实施。

- 当前 `call_agent` 在工具注册与实际执行两处限制为 `CoordinatorOnly`，岗位运行也不注册该工具。V2 需要新的群内岗位消息能力及运行关系，不能只给旧子 Agent 解除一处限制。
- 当前尚无结构化 @ 人 / @ AI 的目标和投递链；已有站内通知存储及已读能力可以作为基础。目标类型与可信 ID、所属群资格和投递去重属于新设计。
- 技术调度与协调 AI 是两个层次。服务端队列、身份校验、消息持久化、租约、去重和预算可以继续承担可靠投递，不替岗位 AI 决定参与者。
- 当前只对部分报告 / submission 自动建批次，AI 最终消息不会再次 enqueue；旧轮次配置不能直接等同岗位互 @ 的链路计数。V2 已取消群模式，应按来源、明确 @ 和完整往返重新设计投递与停止语义。

核查依据：`internal/agent/tools/call_agent.go`、`internal/agent/tools/tools.go`、`internal/agent/batch/batch.go`、`internal/agent/batch/positions.go`、`internal/collaboration/enqueue.go`、`internal/discussion/service.go`、`internal/transport/http/events.go`。

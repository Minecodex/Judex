# 多 Codex 会话与合成公司业务联测

用户授权使用本机已有 APIMart `glm-5.3-flash`，建立多个本地 Codex 会话模拟员工工作，通过正式同版 CLI 把文件回流到 Judex。模型 Key 仅留在 Kubernetes Secret，不进入提示词、仓库或证据。Codex 会话使用用户默认模型，项目内岗位 AI 使用 APIMart。

三个独立模拟项目为软件研发、品牌设计和公司运营。所有人员、需求、数据和文件均为合成内容，不操作真实外部联系人、支付、人事或生产系统。每项目有两位合成员工、三个岗位 AI、内置参考流程、三级独立群，并加入当前用户供查看。模拟项目和成果保留，账号权限与已有业务分离；现有真实项目不修改。

- 软件研发：会议室预约服务，时间/冲突校验、自动化测试、文档与复核。
- 品牌设计：虚构品牌桌面网页、原创 SVG 与设计规范，检查可读性与反馈修订。
- 公司运营：新人清单、20 人活动预算和合成报销对账，预算上限 5000 元，算术验证与修订。

每个 Codex 会话仅修改自己的 `.cache/company-simulation-20261020/<scenario>`，通过独立设备 grant 和 projectScope 使用正式 CLI，先读取群消息和上下文，再推送明确选定文件。岗位身份由服务端解析，不能冒充其他人。普通消息/只记录零触发、岗位公开工具/结构化提及、文件固定版本、人类明确回复与自然收束分别留证。

另建立有明确归属的争议演练群，用真实模型验证闭环限额、暂停期间合并、人工继续和终止；不得无限轮询或反复续额度。所有实际执行次数、Token、失败和限制写入验收记录，不用模型自述代替证据。

当前状态：三个主讨论均已自然收束，13 次岗位运行完成，40 项独立检查通过；设计和运营各经一次技术预算人工恢复，设计保留一次模型中断及一条未知请求记录。实际结果已在 [验收记录](records/COMPANY-SIMULATION-20261020.md) 和 [机器记录](records/company-simulation-acceptance-20261020.json) 归档；私有授权状态与账号密码仅保存在权限受限的 `.cache/company-simulation-20261020/private`，报告不包含凭据。

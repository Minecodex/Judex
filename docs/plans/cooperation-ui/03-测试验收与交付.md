# 测试、验收与交付

本文件规定实施完成需要留下的证据。本次编制没有运行这些未来验收，也不将原 demo 的六项测试当作正式改造通过。

## 3. 固定数据与视觉标准

使用一个包含草稿／进行／已验收／已取消计划、并行／汇合／图外依赖任务、跨两个计划多个任务的话题、待审批／接收／验收／补交、私有职位偏好和资料历史的 fixture。

另建超过各列表默认页大小的数据集，必须验证匹配对象位于后续页时仍可搜到，过滤结果没有重复或漏项，消息／活动来源深链可以到更旧页。规模检查记录请求数量和 payload；不能只在五个示例任务上通过后宣称完成。

视觉覆盖 1120、1440、1920 桌面宽度，zh-CN／en，light／dark，100%／125% 显示缩放。截图核对项目列表、计划列表、待决、交付接收、资料、路线、预览、计划／任务 Chatbox、新建／关联／分叉弹窗、原记录、完整设置与关键异常状态。

原型中的字体、间距、圆角、三栏比例、卡片、按钮、表单和状态层级为参考；中央／右侧完整标签已保留。正式权限和真实来源信息增加、现有完整设置代替原型简化设置属于明确差异，必须登记，不声称整张截图绝对一致。

## 4. 推荐验证顺序与命令

实施过程中先跑触及的目标检查，再完成阶段出口；全部通过后只在新变化或未解决问题出现时重复。以下命令是未来执行清单，不是本次编制已执行：

```powershell
go test ./...
go vet ./...
npm run gen:api
npm run typecheck --workspace @judex/web
npm run test:web
npm run build
npm run build:demo --workspace @judex/web
node tests/client-downloads.mjs
npx playwright test --config tests/e2e/chat.config.ts
```

正式构建的 postbuild 会生成 CLI／Skill 制品，使用项目要求的 Go 和 Python。契约生成产生真实源码变更，执行前核对既有改动并检验生成差异。Go 集成检查若缺少真实 PostgreSQL条件，必须通过隔离环境补证据，不能以 skipped 当作通过。

构建、导入当前源码唯一标签镜像及受控模型网关后，使用既有 runner；将新 business 用例的稳定编号加入 grep，防止空选择或只跑旧用例：

```powershell
$env:JUDEX_TEST_IMAGE = 'judex/server:<本轮唯一标签>'
$env:JUDEX_TEST_GATEWAY_IMAGE = 'judex/test-gateway:<本轮唯一标签>'
$env:JUDEX_K8S_GREP = 'COOP-|本轮必须保留的业务回归编号'
node tests/k8s/ui.mjs
```

镜像名是占位示例，不能原样执行。runner 中必须记录实际匹配场景数，并拒绝 0 场景；正式与 demo 的构建日志、镜像内容与浏览器访问必须对应同一份当前源码。真实模型另外使用当前配置，Secret 不写入仓库或日志。

## 5. 隔离环境与清理

使用唯一临时 namespace，记录 namespace UID、`judex.dev/test-run` 标签、镜像 digest、Helm 配置和来源构建。生产命名空间和数据默认保持。

资源不足时可以按用户给定约束暂停正常命名空间的服务；先记录控制器、原副本数及正在运行的业务批次，避免中断正在写入的任务，测试结束恢复原数量并验证健康。不能删除原 PVC、Secret 或业务记录来释放空间，也不能缩放未确认属于本项目的共享服务。

finally 中先校验 namespace UID 和所属标签，再删除本轮资源；超时或清理失败保留诊断并明确未完成，不误报已清理。核对原服务健康、业务数据与配置，清理本轮 port-forward 和进程，不关闭用户预览或其他任务的服务。

## 6. 证据与完成门槛

证据统一放 `.cache/cooperation-ui/<runId>/`，至少包含 baseline、文件／构建校验值、命令与退出码、HTTP／CLI 脱敏结果、数据库事实、浏览器 trace／截图、视觉比较、受控／真实模型各自结果和 namespace 清理 manifest。

验收报告列明每个矩阵编号对应的证据和结果。必需完成条件：

1. 新流程所有正式入口可用，现有完整设置与认证能力没有缺项。
2. 主讨论并发唯一，范围分页与版本化关联正确，多关联和分叉边界清楚。
3. 报告／问题／建议／会签／接收／任务验收／计划验收使用真实共享用例，有双用户和 CLI 证据。
4. 草稿、阅读位置、完整标签、拖拽／最大化、返回／刷新、事件更新及用户隔离回归通过。
5. 两种语言／主题和桌面视觉通过；单文件限制、类型、构建、相关 Go 和前端检查通过。
6. 受控模型可复现；真实最小分析若未完成，必须明确列为未满足的 AI-04 门槛，不能把模拟结果补作真实证明。
7. 临时环境所属校验和清理完成；代码、文档、启动方式及限制可独立交接。

既有通用多流程路由未关闭项单独说明，既不伪造关闭，也不扩大本轮为一套新路由引擎。原部署升级不属于本轮隔离验收；需要后续明确发布任务。

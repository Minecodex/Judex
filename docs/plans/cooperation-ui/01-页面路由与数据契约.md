# 页面、路由与数据契约

本文件将用户确认的入口转成实施契约。路由、接口命名和文件拆分是工程默认；未实现项不能按本文接口示例宣称已经可调用。下文 HTTP 路径省略 `/api/v1`。

## 1. 页面与点击语义

| 页面 | 必须展示 | 点击与返回 |
| --- | --- | --- |
| 项目列表 | 真实项目卡、本人项目角色、成员摘要、搜索／归属筛选、最近讨论 | 卡片主体进入协同；邀请和设置有独立命中区；最近讨论保留原 topicId |
| 项目协同 | 项目目标与权限；计划／需要我决定／交付与接收／共享资料四个标签 | 默认计划；刷新与返回恢复标签、筛选、分页和阅读位置 |
| 计划列表 | 标题、目标摘要、正式状态、负责人、任务验收统计、本人工作提示 | 主体进入路线；右下角进入主讨论；预览路线只开弹窗 |
| 需要我决定 | 类型清楚的提案、交接接收、任务验收、计划验收卡片 | 打开真实冻结审阅；多人或多职责显示全部必需审批位 |
| 交付与接收 | 任务交付卡和成果交接卡；全部／待我接收／等待对方／需我补充筛选 | 接收、拒收、补交和任务验收调用各自原用例 |
| 共享资料 | 项目共享文件、版本、来源、上传和原件入口 | 复用现有资料能力；计划关联不创造私有资料分区 |
| 计划路线 | 当前计划目标、状态、完成条件、流程版本、从左向右的任务图 | 本人任务高亮；外部依赖可定位；返回协同原计划卡 |
| 任务详情 | 正式状态、身份职责、条件、材料、任务记录／流程参考 | 上报和验收保留门禁；原记录分页读取；讨论进入任务主讨论 |
| 计划／任务 Chatbox | 顶部路径与范围；左侧相关会话；中央完整标签和讨论；右侧详情标签 | 左侧搜索／过滤不切会话；明确选关联对象；返回进入讨论前的位置 |
| 项目设置 | 现有完整设置页、分类与配置功能 | 从项目卡或协同页进入；返回恢复原上下文和草稿 |

卡片主体和角落按钮必须有清晰的键盘／指针操作区。避免嵌套可点击按钮，邀请、设置、预览和讨论不能同时触发卡片主体导航。加载、空状态、无权限、已取消、失败与重试均有明确状态。

计划正式状态保留 `draft/active/accepted/cancelled`；任务保留 `draft/ready/working/delivered/accepted/rework/cancelled`。阻塞、待决定和 AI 分析状态为独立事实，不能压入另一个近似正式状态。验收进度按正式任务与有效贡献统计，不由聊天数量或上传次数计算。

“我负责”按本人当前稳定任职绑定取得计划负责人／任务参与职责；待审阅事项由“需要我决定”承接。草稿卡明确说明尚未生效，并显示已登记主讨论和继续配置入口。

## 2. 对象范围与主讨论

`ConversationScope = project | plan(planId) | task(taskId)`，与当前 `topicId`、本次输入 `taskContextId` 分别存储。

- 计划范围包含直接关联该计划的 topic，以及关联该计划所属任务的 topic。任务范围包含直接关联该任务的 topic。
- 关联任务隐含其所属计划的可见性；前端与后端共用这条规则。引用外部任务的路线节点不会无条件扩大聊天范围；如需纳入另一计划，明确关联该计划。
- 同一范围的 topic 按 ID 去重。主讨论固定在前，其他讨论为平级列表；显示关联对象标签，不构建跨计划专区或深层分叉树。
- 同一会话可以出现在多个计划和任务中；消息、AI 会话及标签对象不随入口复制。手动分叉创建新 topic，并拥有独立 AI session、运行、草稿与后续历史。
- Plan.mainTopicId 保持现有事务规则。Task.mainTopicId 默认为空，点击任务讨论后服务端原子创建；两个用户、重试或多个窗口均得到同一个结果。
- 从讨论形成计划时冻结来源消息位置，原话题保留；一次形成多个计划时各建独立主讨论分支，草稿状态不提前生效。
- 任务存在关联专项时仍先进入固定任务主讨论；专项由左侧或明确选择打开，不将“第一条相关会话”当成任务默认会话。
- 创建专项默认带当前范围，可关联本项目其他计划／任务。编辑关联不能移除计划／任务主讨论的必需归属；关联不授予跨项目权限。
- 共有会话打开后选择本次任务上下文；普通发言可不带 taskId。正式上报必须明确任务和身份，并遵守状态／材料校验，不将一份报告计入全部关联任务。
- 搜索先由服务端在范围内匹配再分页，不要求读完整项目才能找到末页话题。后台新消息／建议更新只刷新数据，不替用户切换 topic 或打开标签。

项目级历史和未关联讨论从协同页次要“项目讨论记录”入口访问；空项目可新建计划草稿或先发起项目讨论形成安排。这是访问已有记录与启动计划的工程默认，不恢复聊天左侧全项目混合列表。旧项目主会场记录仍可读。

## 3. 路由与状态生命周期

| 规范路径 | 含义 |
| --- | --- |
| `/` | 项目列表 |
| `/projects/:projectId?tab=plans` | 项目协同；tab 可为 plans/decisions/deliveries/materials |
| `/projects/:projectId/plans/:planId/route` | 当前计划任务路线；`task` 可定位详情，`focus` 可定位节点 |
| `/projects/:projectId/plans/:planId/chat/:topicId` | 计划范围 Chatbox |
| `/projects/:projectId/tasks/:taskId/chat/:topicId` | 任务范围 Chatbox |
| `/projects/:projectId/chat/:topicId` | 项目历史／未关联讨论或直接 topic 深链 |
| `/projects/:projectId/settings/:section` | 完整项目设置；允许定位具体流程／职位 |
| `/login`、`/register`、`/recover`、`/device`、`/invite/:token`、`/confirm/:intentId` | 现有认证与单次确认入口继续工作 |

`message`、`activity` 用于固定消息或记录定位。表格中的 hub 标签不是浏览器中的聊天标签。源页面、筛选与滚动通过统一导航恢复状态承载，不把凭据和私有草稿放进 URL。直接打开页面、刷新、前进后退和登录后的返回使用同一解析器。

保留一个小的旧链接规范化器：`?project` 进入协同；显式 `chat` 进入同一 topic；旧 `view=plan/task/resources/decisions/handoff` 定位相应路线、任务、资料、待决或交接详情；设置链接进入完整设置。无法唯一判断计划范围的多关联话题使用项目深链，不任选第一条计划。只转换路由，不复制旧 UI。更新 CLI、分享链接和浏览器确认的链接生成器。

| 状态 | 键与规则 |
| --- | --- |
| 会话草稿与阅读位置 | `(mode,userId,projectId,topicId)`；同一 topic 跨入口复用；不同用户严格隔离 |
| 中央讨论标签 | 每项目／用户保存，topicId 唯一；标签记录最近明确进入的 scope；再次打开同一 topic 复用标签 |
| 右侧对象标签 | 每项目／用户保存，对象类型＋ID 去重；关标签不删业务对象 |
| 讨论选择 taskContextId | 标签上下文，选择不改变关联对象；对象已取消／关联已变化时提示重新选定 |
| 分栏与最大化 | 浏览器视图偏好；对象变化不重置；按桌面最小可用宽度约束 |
| 协同 tab、筛选、分页、滚动 | 每项目／用户保存；返回定位原卡；搜索更新游标，不切正在打开的聊天 |
| 图的位置、缩放、本人高亮 | 每计划／用户保存；筛选不隐藏必要前置关系 |
| 配置与报告未提交草稿 | 复用原隔离键，补页面生命周期保存；刷新后的附件能力按现有约定明确说明 |

任务详情的局部状态由统一 TaskInspector 按 mode／项目／用户／taskId 隔离，不能依赖请求 loading 偶然卸载。报告附件保存在同作用域的浏览器内存草稿，关闭／返回原对象可恢复，刷新重新选择；提交成功只清理该草稿。最新核对请求同时绑定对象和请求代次，切换对象取消旧请求，确认必须匹配项目、任务、作用域与版本。

退出和换人取消旧用户请求并隔离查询缓存，不把姓名当唯一身份键。已保存业务记录继续存在；不对所有 sessionStorage/localStorage 执行清空。来源跳转先检查当前范围是否可承载，不能承载时使用项目深链并说明来源；按游标定位完整公开历史。

## 4. 组件与数据装配

新增 `features/cooperation` 承载项目协同页面、卡片和范围查询；路由解析集中在 app／现有 storeBase 的统一适配层。复用 `components/ui`、`Conversation`、`TaskInspector`、`ExecutionMap`、业务审阅弹窗及 settings/work 配置组件。

将 WorkProvider 提升到项目页面外壳，ChatWorkspace 成为其中的讨论页面。正式和 demo 挂载同一项目协同、路线、聊天和设置组件；数据源注入查询／命令适配，不把 `web/cooperation-preview/actions.ts` 或示例领域模型复制成新的生产业务逻辑。

TanStack Query 管理服务端事实，Zustand／视图状态 hooks 管理客户端偏好。统一 key helper 至少包含用户、项目、对象范围及筛选；命令通过共享应用用例、幂等键和预期版本执行。原 WorkStore 的只读映射可为已有组件提供上下文，但不能同时维护另一个可写业务状态仓库。

项目协同的首屏只等待项目／本人权限和当前标签摘要。任务详情、流程版本、提案冻结审阅、成员管理、资料正文和会话历史按进入时读取。失败限于对应区域；普通成员缺管理权限不阻塞协同或聊天。计划卡片采用批量投影，不能逐卡发起任务详情、验收或分析请求。

任务路线和预览共用一个图组件，复用当前布局算法并接实际 execution-map 节点／边／外部依赖。卡片内容与操作按 token 调整；不以本轮导航变化为由更换图引擎。父子拆分只表示归属，真实依赖决定从左到右顺序。

新业务文案按模块登记 zh/en；样式在 `web/src/styles/`；布局 token 与主题 token 统一维护。`cooperation-preview` 只作视觉与固定交互参考，不作为第二套正式功能树。

## 5. 既有接口复用与必要补充

| 能力 | 处理 |
| --- | --- |
| 项目列表／摘要、最近讨论、bootstrap | 复用现有查询；卡片权限来自真实角色 |
| 计划、任务、execution-map、任务活动、discussion-summary | 复用；补计划卡投影和必要范围筛选，不截断事实 |
| Topic 创建、分页历史、固定点 fork | 复用共享历史解析器，保持 sourceRefs 和 inherited |
| 提交、progress/delivery 报告、问题／回复 | 复用现有正式／通信用例，不复制 report/submission |
| 分析／讨论建议／处理／重试 | 复用持久化、版本、幂等及当前运行预算 |
| 提案、交接、任务与计划冻结审阅及正式决定 | 复用现有授权与命令；列表卡片只引用这些事实 |
| 职位、任职、模板、流程、偏好、下载、认证 | 原能力完整保留 |

### 5.1 任务主讨论

工程默认：新增 `POST /projects/{projectId}/tasks/{taskId}/main-topic`，返回稳定 mainTopicId 与 Topic；创建返回 201，已有返回 200。Task DTO 增加可空 mainTopicId。

应用用例锁定当前项目和任务，校验成员与项目可写状态；已有指针直接返回，否则同事务创建 topic、必需任务关联、主讨论指针和事件。非空指针使用同项目外键／唯一约束；任务并发请求不能生成孤儿或重复主讨论。历史专项不猜测、不自动升级为主讨论。讨论已完成或草稿任务可用于解释与协商，不能绕过正式操作状态门禁；已取消对象按服务端可操作状态展示。

点击失败保留原页面，允许重试；只接受显式点击触发，预取和组件挂载不得写入。通用 CLI 链接可定位任务，浏览器在有明确动作时创建主讨论；后端操作若通过 CLI 发起且需人确认，则复用当前 intent 一次确认契约。

### 5.2 会话范围与关联版本

扩展 `GET /projects/{projectId}/topics` 支持 planId 或 taskId、q 和 cursor，限定同项目，scope 过滤先于分页，关联主讨论在查询语义中稳定可达。返回 main 标记／来源／linksVersion 与必要关联标签，统计按唯一 topicId。

新增 `PUT /projects/{projectId}/topics/{topicId}/links`，携带 expectedLinksVersion 和完整 targetRefs；校验同项目、有效对象、必需主关联及当前版本，同事务替换并递增版本。旧追加接口复用同一验证用例并递增版本，不能绕过新版本规则。并发冲突显示最新关联供重新确认；不得静默覆盖。

已有会话的所有追加和替换由 collaboration.ChangeTopicLinks 共用事务逻辑，包括人确认的 AI main/link 建议和已批准安排中的 link_topic；变更发出 topic.links.changed。完整替换推进版本，无变化追加保持当前版本。编辑深链接等待真实话题后初始化，捕获版本不会随后台刷新自动更新。

有效范围包含任务所属计划，可由投影计算，不将隐含可见性重复写成多份业务关系。明确增加的计划关联与隐含关联在编辑器中分开表达，避免取消一个勾选导致错误退出当前范围。

### 5.3 计划卡、需要我决定与交付接收投影

扩展 plans 列表的 summary／q／status／mine 查询，投影 mainTopicId、真实任务验收统计、本人执行事项、待决计数和最新更新时间。批量获取，避免 N+1；正式取消状态和必要引用任务不被近似前端映射吞掉。

复用 `GET /me/actions?projectId=...`。实现已有 kind 筛选，补 category=decision/execution 或等价服务端过滤，均先于分页。decision 至少涵盖 approve、receive、task accept、plan accept；现有其他提案类型保留具体 subtype。计数和卡片共用过滤语义，不从当前一页推算总数；如展示总数则服务端提供。

卡片引用 actionId、objectType、objectId、reviewId 与必要来源版本；审批详情仍重新读取冻结审阅及当前绑定。多条来源的 handoff 可以一张卡聚合，但每个来源固定版本独立处理，不省略必需审批职责。

工程默认：新增 `GET /projects/{projectId}/deliveries` 作为只读混合投影，支持类型、本人收／发关系、业务状态与 cursor。task delivery 与 handoff 分别使用 `(objectType,objectId)` 身份和真实来源摘要，补交显示新版本及历史入口。受控模型与真实 API 测试验证“待我接收／等待对方／需我补充”均服务端筛选先于分页。此列表不创建新的交付业务表。

个人等待／补交以本人来源的当前版本状态判断，不以整个交接的聚合状态与任意本人来源相与。多来源交接仍合为一张卡，卡片打开后各来源分别处理。一个交接可以因本人不同来源而出现在不同个人筛选中。

创建交接时明确显示每条来源的发送职责和当前任职者，本人唯一参与职责可默认，多职责歧义由人选择。协调者可以明确指定其他合法项目任职，发送仍由那个职责的当前任职者本人确认。带附件补交的正式报告贡献身份独立明确选择，并在前端写入前读取当前发送任职和来源版本；后端继续执行原正式报告、发送和验收权限。

### 5.4 SSE 与 Agent 上下文

新增或细化主讨论创建、关联变化事件；扩展当前 `eventMap` 与 query key helper，覆盖 topics 范围、计划卡、actions、deliveries、图及记录。scope membership 改变时只刷新列表，当前 topic 保持可访问或展示权限变化。断线后游标恢复／轮询核对共用既有机制，不对每个事件重建页面。

Agent 继续使用共享历史解析器。任务分析使用独立任务上下文；议题分析读取关联对象的当前正式事实，显式输入的 taskContextId 必须属于合法关联／范围。历史分叉里的旧判断不是当前状态；用户隐私、其他人的提示词、原工具运行和审批票不进入公开上下文或被重放。

已定位任务读取任务及计划的正式流程依据。没有明确关联或候选不足时显示需要补充业务事实、模型未配置、失败或预算耗尽的真实状态。新入口不自行选择或改写流程绑定，也不将通用多流程路由旧缺口算作本轮已解决。

OpenAPI、生成类型、CLI／Skill 深链接、事件失效规则和设计文档在同一阶段同步；不能只修改手写前端类型冒充正式契约。

## 实现

1. TaskInspector 在统一组件入口按 mode／项目／用户／taskId 重新建立 TaskRecords，所有路线、协同和 Chatbox 入口遵守同一生命周期。切换任务关闭旧操作、原记录和上报弹窗。新增 useWorkspaceAttachments 保存浏览器内的临时附件，键包含 mode、项目、用户及任务报告；返回原任务恢复自己的正文与附件，成功提交清除该草稿附件，刷新仍按提示重新选择。
2. useScopedRequest 为任务核对绑定作用域、请求代次及 AbortController。选择任务、内容类型、用户／项目变化或卸载后旧请求失效；过期成功、失败和 finally 不再改变新对象状态。核对结果还必须匹配项目、任务 ID、作用域及版本才能确认，不以两个对象版本号相同判断正确性。
3. HandoffDialog 对每条来源显示发送职责及任职人，由 ResponsibilityPicker 与任务职责选择共用基础控件。本人唯一参与职责可默认选择；本人多职责或多个候选有歧义时必须明确选择。协调者仍可明确指定本项目其他合法任职，由那名当前任职者本人确认发送。创建后定位协同页该交接记录，不停在无对应详情的路线页。
4. proposeHandoff 命令传递明确 senderIdentityIds，不再取参与者数组第一项；没有选择时只从本人唯一参与身份解析，歧义直接拒绝。demo 使用同一默认与合法候选规则。带附件补交显式选择正式报告贡献身份，默认优先对应本人持有的来源发送职责；实际报告与交接发送仍分别遵守原权限。
5. 补交在任何上传／正式报告写入前核对来源版本和真实当前任职者，避免任职替换后旧发送人继续执行；后端原发送授权和验收门禁继续保留。本轮未改变 SourceSender 与 TaskContributor 的业务边界，也未另建报告或审批用例。

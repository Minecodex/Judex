日期：2026-10-08。针对 REVIEW-20261008.md 中重开的 9 项继续实施，并检查用户指出的旧 Chatbox 界面与流程。以下记录区分正式代码、demo 浏览器、真实 API、受控模型和真实模型。

## 改造结果

- 项目内右侧不再回退到全项目 WorkMap／NowPanel、待办概览或交接列表。默认提供当前计划信息或任务记录；全局决定、交付接收和资料从协同页进入。旧工具标签迁移到新上下文，关闭标签不会被焦点事件重新打开。
- 任务详情统一由 TaskRecords 承载。移除“完整详情再打开旧 TaskPage”的重复页面；保留启动、报告、问题、原记录、完成条件、流程参考、验收、重开、交接和本地工作说明。
- 会话标题、关联对象、来源及操作菜单按新原型收敛。消息分叉改为消息菜单，新建／编辑关联／分叉复用 LinkedObjectPicker；关联对象可分页读取，分叉可选多个计划、任务，仍只引用固定公开历史。
- 计划主讨论显示任务摘要，任务主讨论显示最新记录和三种人工讨论建议。继续主讨论明确切到对应计划范围，不留在不匹配的任务范围。
- API／demo 的项目列表复用 ProjectListPage，保留最近讨论、搜索、归属筛选、邀请和设置。项目内完整设置继续复用原页面。
- 待决与交付详情由路由驱动，刷新和切换任务保持正确对象。路线缩放、图位置及外部依赖入口补齐；异步数据和后续分页恢复阅读位置。
- 正式上报的正文、类型、任务、身份、回复目标和预期版本保存为隔离草稿；刷新附件按提示重新选择。多职责上报由本人明确选择，API 身份匹配采用稳定 userId，避免同名误选。
- 发送期间防止重复按键。查询失败保留输入并提供重试；关联冲突显式读取最新会话再确认，当前消息与草稿保持。
- 交接页面按需读取目标任务、来源任务及流程，修复真实 API 下缺少数据而崩溃的问题。普通报告、通信、交接和验收仍执行既有应用用例。

## 交接边界

沿用既有后端规则：拒收尚未验收的来源会使该来源任务进入 rework；已经 accepted 的任务不被交接自动撤销。返工后由发送者重新正式交付，再补交新来源版本。接收来源只更新 receipt，不把任务或计划改为 accepted；任务、计划仍分别由有权人验收。原报告、来源版本及决定保留。

本轮没有通过前端改写正式状态，也没有调整通用多流程自动路由或实际成员在本地工作的边界。

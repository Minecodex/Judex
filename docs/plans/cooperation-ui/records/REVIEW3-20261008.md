## R3-03：多人任务的交接发送职责仍由第一位参与者决定

正式 proposeHandoff 对每个来源任务直接取 task.participants[0].identityId，HandoffDialog 只有来源任务和接收职责选择，没有发送职责选择。

复现结果：当前用户 member-b 只持有 identity-b；同一任务的参与者按 identity-a、identity-b 排列，正式命令仍把 identity-a 填入 senderIdentityId。后端 Create 允许成员登记同项目合法发送职责，而 SendSource 明确要求当前发送职责的任职者本人发送；因此 B 创建的交接会依赖 A 发送，界面没有让 B 明确选择或确认这个责任安排。该问题与两名发送者各自拥有一个来源任务的既有通过测试不同。

位置：web/src/features/work/apiActions.ts 的 proposeHandoff；web/src/features/work/CompositionDialogs.tsx 的 HandoffDialog。补交带附件时 reviseSource 仍调用无明确身份参数的 actingIdentity，也需要与发送职责一并核对。

证据：browser-results.json 的 handoff-picks-other-participant；正式命令以拦截响应捕获请求，没有真实创建交接。后端发送人限制沿 internal/handoff/service.go 核查。未声称后端允许 B 越权发送。

影响 P3-03、P4-04、P7-06；验收 BIZ-01／BIZ-02／TASK-03。应显示并明确选择每条来源的发送职责，同一人多个身份、不同成员和职责替换都按现有权限核验，不能只修启动／报告的身份选择。

## 恢复访问与部署配置

Docker Desktop 的 Kubernetes 启动后，检查并恢复本地转发：

```sh
kubectl --context docker-desktop -n judex get pods
kubectl --context docker-desktop -n judex port-forward service/judex 18097:8080 --address=127.0.0.1
```

已有转发占用 18097 时直接访问即可；Pod 更换或本机重启后需重新运行转发。交互预览使用 `http://localhost:18097`，与主入口的 `127.0.0.1` 分开 origin。

本次公开模型目录和部署 values 位于本机忽略目录 `.cache/local-run/20261019/`。已安装的配置也可通过 `helm get values judex --kube-context docker-desktop -n judex` 查看，密钥仍由 Secret 引用。

后端使用宿主 Go 交叉编译为 `linux/arm64`，再通过 `deploy/docker/server.release.Dockerfile` 打包；前端生产构建和 Windows / macOS 下载包均已生成。现有 `scripts/deploy/load-local-image.mjs` 仍限定 AMD64，本次 ARM64 镜像使用以下原生管道导入实际节点：

```sh
set -o pipefail
docker image save --platform linux/arm64 judex/server:0.1.0-local.20261019 |
  docker exec -i desktop-control-plane ctr --namespace k8s.io images import --platform linux/arm64 -
```

解析、转换和固定上游依赖镜像使用同样的平台检查及导入方式。首次拉取的短暂网络错误经重试恢复；Office 镜像完成标准 Dockerfile 中的依赖与中文字体安装后才通过预览验收。

# 前端生产就绪审计

审计日期：2026-09-27。范围为 `web/`、前端测试及相关设计文档；本轮未阅读、修改或验证 Go 后端，不据此判断另一个 AI 正在实现的后端完成度。

当前前端**尚未形成完整生产业务**（2026-09-27 审计时点结论；2026-10 统一前端重构后已不成立，见 §3 末「2026-10 缺口复核」）。聊天工作区、项目与职位设置、任务依赖、交接和验收已经有可交互的演示路径；但生产模式的认证入口、正式业务读写、多人同步、文件和 AI 运行还没有连通。即使后端接口已经实现，现有前端也不能直接完成真实多人项目协作。

## 1. 本轮已完成的工程收敛

- 删除独立 `docs/demo` 源码、依赖、构建产物和运行日志，停止其 4173 预览服务。前端统一在 `web/` 开发，历史设计文档保留并标识旧入口已失效。
- 基础 UI 统一使用 HeroUI。现有按钮、弹窗、标签页、菜单以及本轮迁移的输入、选择、复选、卡片、状态标签、提示和折叠区均直接或通过共享适配层使用 HeroUI。
- `web/src/components/ui/FormControls.tsx` 集中处理字段标签、选项、受控值和通用外观；样式位于 `web/src/styles/controls.css`，沿用统一 Token。
- `FilePicker.tsx` 仅保留隐藏的原生 `input[type=file]` 获取浏览器 FileList，可见按钮使用 HeroUI。语义 HTML、业务 SVG 和布局不是第二套基础 UI 库。
- React Router、React Flow / ELK 在设计中仍是候选，不能把未安装这些候选依赖等同于违背既定组件库约束。当前执行图使用业务布局算法和 SVG。

## 2. 按用户业务链路检查

| 业务环节 | 当前前端能力 | 生产闭环结论 |
| --- | --- | --- |
| 内网用户注册、登录 | 有表单，提交 `/auth/register`、`/auth/login` | 缺登录成功状态、会话恢复和进入工作区的处理 |
| 新建项目、邀请加入、同岗多人 | 演示中可创建、邀请和任职；设置支持职责提示词 | 数据与权限基于本地演示状态，缺真实邀请与成员命令接入 |
| 项目和个人工作提示词 | 有设置页、保存和权限提示 | 保存仍为演示数据，缺服务端版本、权限和运行配置接入 |
| 协作流程、节点与职位绑定 | 有流程图、规则版本、节点绑定和重确认交互 | 新流程与 AI 草稿生成是本地逻辑，没有真实运行配置发布 |
| 聊天、提案、审批生成工作 | 有多标签、独立草稿、审批名单及版本校验 | 缺服务端消息、决定命令、事件更新和并发冲突处理 |
| 计划、任务、执行先后 | 有依赖布局、阻塞提示、上报、交接和验收 | 本地模型可演示；无法跨设备共享正式状态 |
| 文件、图片、网页等资料 | 可本地选择、预览并关联材料 | 没有真实上传、服务端版本或完整网页包管理 |
| 本地 AI / CLI 上报 | 有说明入口、手工模拟上报与材料分析文案 | 缺接入状态、真实上报事件、失败与重试反馈 |
| 平台 AI 讨论与运行次数 | 有按提交计次、项目上限、待人工判断状态 | 本地固定文案，无真实模型运行、流式事件或消耗计量 |
| 发布与运营成果汇报 | 可以通过通用工作和材料对象表达 | 没有完成真实环境、版本与上报事件联调；不能据此宣称发布闭环已验收 |

实际代码修改、测试和部署仍遵循当前设计：成员在本地工具执行，平台接收报告、分析、提醒和审批。本次审计没有把平台远程操作成员电脑、自动测试或自动部署列为必补功能。

## 3. 阻止生产使用的前端缺口

> 2026-10 复核：下表为 2026-09-27 审计快照。统一前端重构（P1–P4）后，P0 各项均已关闭，逐条现状见表后「2026-10 缺口复核」。

| 优先级 | 代码证据 | 可观察的影响 | 完成标准 |
| --- | --- | --- | --- |
| P0 | `web/src/app/App.tsx`：仅 `dataMode === 'demo' && !screen` 返回工作区；AuthForm mutation 只有 `onSettled` 清密码 | 即使登录接口成功，生产模式也不会进入协作工作区 | 真实登录、刷新恢复、退出、会话过期形成完整路径；未经授权无法显示旧项目数据 |
| P0 | `web/src/features/work/store.tsx`：`act()` 在非 demo 模式直接返回；`commit()` 调用 `persistPreview()` | 计划、任务、配置、交接与审批没有真实写接口 | 按领域命令接入 API，成功以服务器返回为准；失败不能显示完成 |
| P0 | 同一 store 的 Query 无条件使用 `initialData: initialPreview`、`staleTime: Infinity` | 将来仅放开 API 工作区入口，会把预览快照当作长期有效初始状态，可能不触发首次服务端加载 | demo/API 查询初始化严格隔离，API 无 seed 回退，具备加载、失败、空态及权限状态 |
| P0 | `web/src/lib/api/workspace.ts` 只有整体 `/workspace` 读取和预览持久化；`client.ts` 只有基础 fetch 封装 | 当前没有按项目/任务/决定读写、版本冲突、幂等命令及权限过期处理 | 与后端确认真实契约，建立查询/命令 Hooks 与错误映射；禁止依靠前端投票计算正式结果 |
| P0 | `store.tsx` 仅监听浏览器 `storage`；前端无 SSE/WebSocket 或业务轮询订阅 | 一个浏览器内的变化不等于团队其他电脑已收到，审批状态无法及时同步 | 订阅项目事件，支持断线重连、游标补齐、重复事件去重与缓存失效 |
| P0 | `web/src/features/work/ui.tsx` Upload 使用 FileReader/data URL，并限制 1 MB | 附件存储在演示快照中，不能作为团队正式材料库 | 接入上传、下载权限、材料版本、失败重试；网页包使用隔离预览与版本关联 |
| P0 | `web/src/features/chat/discussionPolicy.ts` 拼接角色意见与固定总结；`FlowPage.tsx` 生成本地规则草稿 | 当前“AI 讨论”没有真实模型运行，配置次数不是服务端资源约束 | 接入运行 ID、状态、消息和结果；上限由服务端执行，新提交与重试可追踪 |
| P1 | `features/work/selectors.ts`、`proposalModel.ts` 等依赖可变的浏览器 WorkState | 演示权限与审批版本规则不能证明生产授权、并发决定与最终状态一致 | 使用服务端身份和授权结果；覆盖双用户审批、反对、改版、权限撤回及重复提交 |

## 4. 生产接入后的验收重点

1. 真实会话与工作区：注册 → 登录 → 进入项目 → 刷新恢复 → 退出；会话过期或权限撤回后清除旧缓存。
2. 真实多人协作：A 建项目邀请 B，B 在另一个浏览器会话接收；A/B 共同讨论、审批后，双方看到同一个服务器版本。
3. 正式事务：提案改版重收同意，拒绝不创建工作；网络中断重试不产生重复计划、任务或决定。
4. 交接与验收：逐来源拒收/补交、过期证据拒绝、前置阻塞、任务验收与计划验收都以服务端判定为准。
5. 材料和本地工作：真实上传、CLI 上报、关联任务和来源版本；另一台电脑可访问同一获授权材料，重复上报不重复产生工作。
6. AI 运行：实际运行事件、轮次、缺资料/待人工/失败等状态；达到上限不禁止用户继续提交，也不自动制造审批成功。
7. 规模与性能：长会话分页、较大任务图、重连、上传失败和大材料；当前整数组筛选与渲染不能证明生产规模下可用。构建仍提示 Mermaid / ELK 等大分包，需要后续按实际入口做加载性能测量。

## 5. 实施顺序与验证边界

建议依次完成：认证与会话 → 真实查询/命令层 → 项目成员与正式工作事务 → 实时事件/文件/CLI 上报 → 平台 AI 运行 → 真实多用户端到端与部署验收。UI 可以继续复用，演示状态机不能作为正式服务器事实源。（2026-10：前五项已按统一架构落地，demo 状态机仅作只读视图装配来源；AI 运行入口已接通，待模型配置联调。）

本轮使用隔离的纯前端配置 `tests/e2e/chat.config.ts` 验证交互，不启动后端或 Kubernetes。`tests/e2e/foundation.spec.ts` 中历史 501 断言只用于当时的接口壳层边界，不能作为完整生产业务验收。

构建与 31 条前端模型测试已通过。26 条浏览器场景均已通过：全量运行通过 25 条，剩余提案审批场景在修正 HeroUI 复选框定位后单独复测通过。另检查了中文浅色项目表单、英文深色设置与下拉列表、深色任务工作区的截图，未发现页面脚本异常或整页横向溢出。该验证范围不包含真实登录、数据库、对象存储、多人服务端并发、真实模型和 CLI 联调。

## 1. 现有 Demo 主路径（计划、任务分层待调整）

项目 → 议题 → 确认方向 → 本地工作 → 回传成果 → 独立验收 → 正式完成。

方向提议通过只解锁后续工作，不算完成。提交成果创建新的验收问题，审批位重新等待、计时重新开始；全部满足同意后才记录完成时间。首页与项目页只将已验收议题计入正式完成数量。

议题保留讨论、工作约定、资料、决定四个视图。顶部显示阶段和下一步，底部输入框始终可以补充讨论；Web 普通文字中的“同意”仍不触发正式决定。

## 2. 页面与动作

| 位置 | 可操作内容 | 结果与边界 |
| --- | --- | --- |
| 工作室首页 | 项目入口、待决事项、可继续的工作、搜索 | 当前阶段动态汇总，不用固定假进度 |
| 创建项目 | 目标、文字流程 | 创建后进入机器人配置；不复用其他项目的机器人，不自动承接岗位或生成业务议题 |
| 项目页 | 议题列表、状态筛选、新议题、项目机器人、我的提示词、项目资料、协作约定 | 不同问题独立审批；新议题不会沿用其他议题的同意 |
| 机器人管理 | 创建机器人、岗位职责提示词、组合预览 | 项目创建人或管理员维护；创建时不选人，先等待邀请分配 |
| 成员与邀请 | 指定受邀人和多个机器人、撤销邀请、调整已加入成员的承接岗位 | 邀请固定承接范围；已占用或在邀请中预留的机器人不能重复安排 |
| 接受项目邀请 | 查看管理员指定的机器人、接受并加入 | 一次承接全部指定岗位，不自行重选，不增加二次入项审批；随后配置自己的提示词 |
| 成员工作台 | 本人负责或需本人审批的议题、我的机器人、我的提示词、团队资料 | 不提供成员管理或岗位职责编辑入口 |
| 我的提示词 | 本人在当前项目中的偏好、保存或留空清除、查看应用的机器人 | 按项目与本人保存；不跟随机器人换人，不向其他人的预览与导出泄露 |
| 项目资料 | 文件与用途先登记，再确认建议关联 | 未确认前不进入议题资料；确认动作、来源与用途留痕 |
| 议题 Chat | 消息、附件、阶段提示、审批卡片 | 消息及未发送文字草稿保留；正式动作使用对应卡片 |
| 工作约定 | 负责机器人、完成条件、工作简报、成果提交 | 简报可复制交给本地 AI，平台不启动成员电脑 |
| 成果验收 | 成果说明、证据引用、交付版本、验收条件 | 独立形成验收审批，通过后才正式完成 |
| 决定与历史 | 当前提议、原方向批准、已取消/已替代提议及原因 | 保存明确问题、版本、实际操作者及同意来源 |
| 待我决定 | 本人待批、项目负责人可代批的事项、上下文跳转 | 本人可快捷同意；代批必须到卡片明确勾选范围 |

## 3. 退回、变更与资料更新

- 退回必须填写原因，当前审批立即取消，停止计时；未回应位不再补记超时同意。
- 方向被退回后，可以编辑新提议及修改说明，再发起新轮次。
- 验收被退回后，保留原交付记录；补充新的成果说明或文件后提交下一交付版本，再单独验收。
- 明确“不再推进这个方向”时停止，不自动重提。
- 新附件或确认关联的资料使待审提议的依据版本变旧时，暂停其通过与超时结算；核对并提交修订后重新审批。
- 当前演示对资料版本使用确定性的检查，尚无真实 AI 判断普通文本是否构成实质依据变化。
- 第一位同意开始计时，后续同意不延期。同一审批结束前，参与人可以明确撤回同意并带原因退回；不覆盖其他人的历史操作。
- 项目负责人代批只处理明确勾选的未回应职责，保留实际操作者及代批来源。

## 4. 机器人与现有数据

继续使用原浏览器数据键，载入为 schema 3。旧演示在多个项目共用的机器人按项目分开，消息中的机器人引用、负责机器人及审批席位同步映射；消息内容、文件、绑定人、实际审批人和截止时间保留。旧的“方向已通过”映射到可继续工作，不会直接升级成已验收。

更换绑定人保持同一机器人的工作、会话与计时，旧审批保留旧操作者，现任按当前职责操作。岗位提示词保留在项目与机器人下，个人提示词按项目与实际本人保存；换人后使用继任者自己的配置，没有配置则为空。

**2026-09-25 用户纠正并确认**：机器人由项目创建；加入均由管理员邀请，邀请时可指定多个机器人；受邀人加入后配置本人的项目工作提示词。此前“成员加入时自行挑选机器人”的提议未采纳，“创建机器人时直接填绑定人”的 Demo 已替换。

机器人、项目成员身份和项目管理角色分开保存。机器人归属单一项目；创建时填写名称、岗位、职责提示词，可暂时无人承接。邀请指定受邀人与一个或多个机器人，受邀人接受后直接加入并全部承接。原有议题与审批席位不会因为加入成员自动扩大；给新议题安排负责人或审批位时，需要选已有人承接的机器人。

创建人和管理员能创建机器人、编辑岗位职责、管理邀请和在已加入成员间调整承接关系；普通成员查看自己承接的机器人并编辑自己的个人提示词。项目创建人可设置或取消成员的管理角色，管理员不能自行扩张管理角色。职责编辑记录版本、更新时间与编辑人，不改变历史决定或其他项目。具体服务端权限仍未实现。

项目首页菜单按视角生成：管理者默认进入项目议题，有「机器人管理」「成员与邀请」等入口；普通成员默认进入「我的工作台」，有「我的机器人」「我的提示词」「团队议题」等入口。等待接受邀请时仅显示邀请介绍和管理员指定的岗位；搜索、议题直达与资料入口也检查成员身份。单纯管理权限不自动授予业务审批权，已有项目负责人的明确代批规则继续保留。

邀请期间，机器人被该邀请预留；已有人承接或已在另一有效邀请中的岗位不能重复分配。撤销邀请保留取消状态并释放预留；重复接受或接受已撤销、已变化的邀请不会修改成员或部分承接岗位。岗位调整仅在现有项目成员之间进行，不借调整入口绕过邀请加入。这些是当前 Demo 的交互细节，后端需补齐事务与并发保障。

组合预览按「平台边界 → 项目协作约定 → 机器人职责 → 本人项目偏好」展示；本地工作简报再加入当前议题与交付条件。预览与简报只导出当前查看人拥有且适用于该机器人的个人偏好；项目负责人也不能借此看到其他人的私人设置。提示词编辑不会新增审批权或改变历史决定。

此处演示界面与导出范围隔离；所有 Demo 数据仍存储在同一浏览器，切换身份是测试能力，不构成服务端保密或生产身份认证。真实运行层需要以稳定用户 ID、项目 ID 与机器人 ID 装配权限允许的配置，并记录本次调用使用的版本。模拟聊天没有使用真实模型，保存提示词不会声称已改变真实 Agent 的行为。

## 5. 软件研发项目示例

首页「体验软件研发项目」创建「轻笺 · 团队任务工具」，包含产品、开发、测试、运维四个既有岗位，以及邀请中新增加的前端「小端」与文档「小记」。采用追加方式，不重置其他项目；再次进入保留该示例的修改与决定。已有示例一次性补充管理成员和邀请，不重置原业务历史。

顶部「对比身份」提供：林然（项目创建人）、沈言（管理员）、周宁（测试成员）、赵可（待接受邀请）。管理员不需要承接机器人即可管理；测试成员有自己的工作台；赵可的邀请指定「小端＋小记」，接受后切换为成员菜单并进入个人提示词配置。普通身份切换不改变成员真实角色。若示例由其他演示身份创建，创建人按该身份显示。

| 议题 | 初始状态 | 可体验内容 |
| --- | --- | --- |
| 下一轮：要不要支持任务标签？ | 待确认方向 | 产品与开发共同确认一个范围问题 |
| 任务 API 与列表界面 | 可继续本地工作 | 读取约定与工作简报、回传成果、发起独立验收 |

## 6. 验证范围

本轮增加状态机测试与工作室浏览器 E2E，检查方向/验收分离、资料人工关联、过期依据阻止批准、审批角色与代批范围、退回重提、普通消息不批准、交付版本、换人保持历史，以及项目进度联动。

新增验证覆盖项目创建机器人、管理员指定多个机器人邀请、接受后原子承接、撤销释放预留、成员直接访问与搜索范围、角色菜单、管理不自动获得审批权、项目职责与个人偏好进入简报、跨项目与跨人员隔离、换人保留历史，以及中英文和深浅色桌面布局。

这是浏览器本地原型，AI 回复和草稿仍为模拟。真实 CLI、主/子 Agent、记忆后端、服务端鉴权、跨设备事务一致性和后台调度没有接入。浏览器打开时会按当前时间结算到期的示例审批；体验设置也提供模拟到期，不代表存在生产调度服务。

文字流程可编辑和保存，本轮执行使用表单中明确的机器人、审批职责与完成条件，不声称已经实现自然语言规则编译器。完整文字流程的校验与运行需要真实后端。

测试数量与执行结果见 [Demo 工程说明](../web/README.md)，不以模拟前端通过代替真实业务端到端验证。

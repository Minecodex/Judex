# 聊天协作前端重构（2026-09-27）

## 已确认的方向

用户明确：“任意用户”指内网任意用户；计划任务从左向右表达执行先后。用户要求重构正式前端，使项目与聊天成为主要入口，面向个人使用的轻松体验优先，不再使用工作室模块菜单作为主结构。可直接替换旧布局，不要求兼容。

本轮只修改 web/、前端测试及相关文档，没有读取或修改正在由其他工作推进的后端实现。后端实际能力以该实现工作自己的验证为准。

## 页面组织

- 左侧：顶部新建项目按钮及 HeroUI 项目下拉，下面是聊天、交接会话、搜索、“新建讨论”和待决定入口。中央标签栏不再重复提供新建讨论加号。左下角头像与名称打开账户菜单，包含邀请用户、设置、退出登录、语言和主题；体验身份切换收在菜单的演示专用区域。
- 中间：当前聊天、岗位 AI 的分析示例、材料、工作提案和逐人确认；交接会话直接呈现各来源的发送、接收、退回、修订操作。
- 右侧：可收起或最大化的独立多标签工作区。先显示日常功能列表，选择后打开标签，加号回到列表继续选择；保留任务路线、共享资料、需要我决定、交接信箱和待办概览。配置类功能集中到独立设置页，不再作为右侧功能标签。
- 打开右侧对象不会丢失当前聊天。路由携带 chat 和工作对象参数；草稿按项目、真人与会话分别保存于当前浏览器会话，刷新后可恢复。
- 新项目空状态引导配置流程、创建并绑定职位、邀请或分配已有成员、设置个人提示词。没有任职身份时不能生成可发送的正式安排提案。

统一使用 HeroUI 基础组件及现有适配层，新页面颜色、字号、间距与圆角由 Token 提供。暖灰底、低饱和项目色、轻量卡片与阅读空间替代企业仪表盘；中英文和深浅主题均保留。

### 三栏拖拽与侧栏细化

依用户截图反馈，两条分隔线均可自由拖拽分配屏幕空间。布局按比例保存于 judex.chat.layout.v1，刷新保留；窗口缩小时限制实际宽度以保留可用的聊天和设置区，恢复窗口后重新使用保存比例。展开、收起工作区不丢失自定义宽度，拖动不会重建聊天或清空草稿。

最大化工作区会隐藏中央会话的显示，占满左侧项目栏以外的全部空间；左侧栏保持不变，中央会话组件与草稿继续保留。最大化不改写原来的三栏比例，再点“恢复三栏布局”恢复原尺寸；在最大化状态关闭工作区，也会回到聊天。点击左侧聊天会恢复可见的聊天区。

按用户要求，移除页面最顶部的预览提示条和会话标签上方的 AI 提示行；右侧“工作与资料”独立标题行也移除。两边标签栏直接顶齐屏幕上沿。中央标签栏仅保留右侧开关，新建讨论统一从左侧进入；右侧最大化/恢复与关闭按钮放在右侧标签栏内。真实 API/预览数据源边界不变，演示说明仍在会话欢迎内容、相关功能页和文档中保留。

分隔线支持键盘方向键微调、Shift 加速、Home / End 到边界、双击或 Enter 恢复该侧默认比例，Escape 取消当前拖动。最小宽度由统一布局 Token 管理，仅约束桌面可操作性。

侧栏参考用户提供的紧凑会话列表：浅紫灰背景、清晰分组、整行选中与悬停、长标题省略，列表不产生横向滚动。项目切换使用统一下拉组件与实际项目访问范围。

新建项目弹窗使用 780px 宽尺寸（受视口留白限制），通用弹窗标题与关闭按钮共用一个布局，关闭始终在右上角；内容超出窗口时在弹窗内部滚动。

### 多会话标签与工作区入口

中央使用 HeroUI 浏览器式标签栏，点击左侧聊天或交接会话会打开对应标签，重复点击复用已有标签。项目主会场固定保留；关闭当前标签切到邻近标签，关闭非当前标签不切换当前聊天。关闭标签不暂停议题、不删除消息，也不改变任务、交接或审批状态。

标签清单按当前项目和体验身份分开保存在浏览器会话中；刷新保留已打开的标签，路由指定当前项。各会话分别保存文字草稿与阅读位置，未发送附件在当前页面切换/关闭再打开时保留，不承诺刷新后保留附件。任务或设置等右侧入口保持当前聊天，包括交接会话；不是打开工具就回到另一场聊天。

用户随后明确移除“暂停讨论／恢复讨论”。聊天始终可以补充内容，标签关闭只是界面操作；旧 closed 标记不再阻断输入、分析或提案。AI 的某次分析结束与聊天可否发言分开处理。

右侧“打开功能”列表现仅保留任务路线、共享资料、需要我决定、交接信箱、待办概览。每项功能可独立打开和关闭，重复打开复用已有标签；不同任务/计划的详情分别占用标签。关闭最后一项回到功能列表，不删除业务对象。原配置入口统一进入下述设置页。

右侧标签按项目和当前人员独立保存，刷新恢复；切换项目不串用另一个项目的详情。切换标签保留个人提示词、项目轮次配置、流程编辑等未保存草稿，并恢复各功能阅读位置。前端通过视图上下文承载当前标签，不复制项目、任务或审批事实；后台状态仍共用同一套数据。多窗口预览只同步业务记录，各窗口保留自己的体验身份，以免另一窗口切换身份导致当前审阅被重建。

中央和右侧统一使用紧凑标签：内容自适应宽度、最长 180px、高 34px，过长标题省略并可查看完整标题。未选中也有明确底色和边框，选中与悬停分别强调；标签多时在自身区域横向滚动，不拉宽页面。

聊天内容区不再重复展示项目名称和会话标题。会话标题仅在标签中呈现，超过最大宽度时以省略号截断，悬停标签可查看完整标题；标签的可访问名称仍保留完整文本。

这些功能当前仍使用预览状态；本地 AI 接入是说明页，不能误认为已经连接 CLI/Skill。

### 账户菜单与独立设置页

点击左下角头像弹出账户菜单。邀请作用于当前项目，沿用创建者/管理者权限；普通成员看到禁用状态及说明，不因为新增菜单就增加邀请权。邀请表单复用原有多职位选择与成员邀请规则，当前只记录演示邀请，不发送真实邀请消息。

“设置”打开独立的全屏页面：左侧返回应用、搜索与分类；右侧显示对应设置内容。分组如下：

- 个人：常规（语言、深浅主题）、当前项目的工作偏好。
- 当前项目：项目 AI（每次提交的轮次上限）、成员与职位、协作流程。
- 连接：本地 AI 接入说明。

设置页面保留各项已有授权与个人提示词可见性。旧配置链接直接打开相应设置分类，不再产生工作标签。返回应用恢复原聊天、标签、布局和未提交草稿；设置页可刷新或通过浏览器历史导航。设置配置与日常工作引用相同项目数据，不复制一份业务状态。

退出入口在当前显式演示模式中离开工作区、清空界面查询缓存并进入“已退出交互预览”页，刷新不会自动回到工作区；本机项目示例不被删除，可通过明确的“返回交互预览”再次进入。这不是模拟真实认证成功或撤销服务器会话；真实模式登出需实际接口成功后处理。本轮未检查或修改后端认证实现。

### 每次新提交的最大讨论轮次

新建项目和“账户菜单 → 设置 → 项目 AI”提供上限配置，项目创建者或管理者可修改，普通成员只读。当前默认 3 轮，允许 1–100 的整数；默认值和输入范围是本轮前端实现选择。

一轮包括参与岗位的分析和协调汇总，不按消息数或工具调用数计。每次新的文字、文件或工作上报生成独立讨论批次，保存来源 ID、触发类型、当时的上限、已完成轮数与停止原因。新内容重新计数；AI 自己的回复不产生新批次，反复点击继续分析也不能重置额度。设置变更只影响之后的新提交，不追溯扩大当前批次。

形成结论、缺资料或等待人的决定时可提前结束，不要求跑满上限。达到上限仅结束本次自动讨论，仍可发消息、补充材料、处理提案与审批。界面显示“本次提交 X / Y 轮”。演示分析每次完成一轮并等人判断，可在当前剩余额度内再次分析；不是用同步循环伪造后台自动多轮执行。

当前聊天上传、共享资料登记、本地工作上报表单与补交表单都接入同一计数规则；同一报告来源 ID 重放不重复创建批次。真实 CLI 推送和后端 Agent 调度尚未在本轮联调，需要遵循同样的提交 ID、配置快照及计数规则。已有任务/计划状态与审批不受轮次上限替代。

## 聊天到工作的演示闭环

1. 人提交文字或资料，前端生成一次明确标为模拟的岗位分析与协调总结；也可手工请求下一轮。不会后台无限讨论。
2. 从聊天打开工作提案，编辑计划目标、验收条件、流程、负责人及任务。
3. 每项任务指定流程节点、该节点的执行身份、验收身份；可选择前序任务，默认没有前置的事项可并行。前序选项只能引用本提案中较早列出的事项，避免生成循环。
4. 确认发送时保存报告版本、流程版本、身份与关联人、任务清单、依赖和实际审批名单。当前演示对计划负责人、所列执行/验收人的去重集合收集同意；这是当前 UI 的审批名单生成规则，不冒充已经实现生产系统的任意节点审批策略配置。
5. 同一真人只需确认一次。全部列明的人同意后，在同一次本地状态更新中生成正式计划和任务，并关联回原聊天。重复确认不会重复创建。
6. 任意有效退回终止当前提案，说明原因；发送人可修改并重新发送新版本，旧票不继承。流程版本、任职绑定或节点关系变化时不能继续批准旧依据。
7. 后续沿用本人上报、各来源确认发送、接收人明确接收/退回、补交、任务人工验收和计划负责人整体验收。批准工作安排不等于实际执行、交付或验收完成。

普通消息和 AI 发言不改变正式安排。进入聊天中的工作提案与“需要我决定”看到的是同一份提案，操作依据也是同一版本。

## 执行路线图

按任务的真实前置关系计算列位置：前序在左，依赖它的工作在右；独立任务同列，可并行，多来源可汇合。任务完成状态不会自行改变依赖布局。计划是筛选与阶段目标，不作为一个需要执行的前序任务。

父子任务关系继续保存，仅作为拆分归属展示，不产生隐含的执行顺序。任务详情保留开始/验收条件；图中注明开始前置或验收前置，不能把只限制验收的条件误称为禁止开始。硬条件与建议关系使用不同线型。跨当前图范围的前置有提示，异常循环显式提示，不虚构可执行顺序。

支持任务原地详情、缩放、横向滚动、大图查看。新增提案可配置任务依赖；已生效任务的任意依赖拖线编辑、复杂跨计划修改与撤销尚未在本轮实现。

## 工程与验证边界

- src/features/chat/：聊天布局、提案编辑/审批、只读执行图布局与工作区。
- src/features/work/：继续共用项目、成员、流程、交接、资料和验收规则。旧工作室主入口与按父子层级布局的图代码已移除。
- src/styles/chat-tokens.css、chat-workspace.css 与 src/i18n/chat.ts：统一视觉及中英文。
- tests/e2e/chat.config.ts：只启动隔离的前端演示服务，不启动、读取或测试后端；保留已有交接/验收回归，并增加聊天提案、执行顺序、草稿保持、新项目设置和英文深色测试。

运行：在仓库根目录执行 npm run dev；开发预览默认 5173。前端检查执行 npm run test:web、npm run build，独立浏览器检查执行 npm exec -- playwright test --config tests/e2e/chat.config.ts。

当前业务操作仍通过显式预览数据运行，不能将它视为生产业务已联调。真实模型、CLI/Skill、认证后的工作区读写、多端事件、生产会签的超时/代批策略尚未在此 UI 与后端完成联调。生产构建仍使用真实 API 模式，不自动回退演示数据。登录/注册沿用实际请求接口，不伪造注册成功。

## 2026-09-28 Chatbox 三栏迁移（生产 API 模式）

三栏聊天工作区从演示树迁移为生产（API 模式）主界面：在 `web/src/features/workspace/` 新建独立模块，复用演示树的 `judex-chat-*` 布局体系与三栏拖拽逻辑（`useSplitLayoutBase` 与数据源解耦），数据全部来自真实契约。

- **左侧栏**：项目标题与返回、新议题（createTopic + Idempotency-Key）、会话搜索、议题/交接列表（交接显示待处理来源角标）、待定决定入口、实时连接状态点、账户行（语言/主题/登出）。

## 实现

- 对象导航由 `cooperation/objectNavigation.ts` 统一：资料库打开任务抽屉／计划路线；讨论中打开现有右栏对象页，保留会话和草稿。
- 登记表单按固定任务详情解析所属计划，当前对象不在首个分页时仍补取并展示。计划搜索、计划与任务继续加载使用统一集合组件。
- 文件弹窗“发送到讨论”选择既有讨论及明确工作上下文，通过同一草稿缓存加入固定版本附件；用户发送才产生使用记录，不自动创建讨论或修改正式归属。
- 资料库、会话和选择器共用文件封面：真实 PDF／图片、原始文本与源码、真实 ZIP 目录摘要。已删除会话附件保留紧凑引用与详情。右栏按卡片最低阅读宽度调整列数。
- 卡片和弹窗分别显示原件状态与预览状态；损坏／不支持的预览有一致提示，原件仍可下载。使用记录中的缺失人物、说明和时间统一显示“未记录”。
- 资料分页返回与搜索／格式／工作过滤完全相同的 totalCount；界面区分资料总数与当前加载数量。
- Markdown 使用词法 token 转 React 节点，支持强调、链接、引用、列表、代码及表格。HTML 为文字，图片不发起外部读取，仅允许用户点击 http／https／mailto 链接。
- PDF.js 的 CMap、标准字体、WASM 解码资源按版本随包提供，开发和生产使用相同资源，补充非嵌入中文字体 PDF 验证。

## 预览契约

FilePreview 在 ready 时返回鉴权 `contentUrl` 与 `thumbnail` 描述。缩略图描述包含 kind、url、page：PDF.js 使用同版本 PDF 第 1 页；图片使用同版本图像；源码和目录封面安全读取同版本内容。它不是对象存储公开链接，也不把 PDF 输入伪称为服务器生成的图片。

原件状态来自实际 material_versions.state。无可读预览时 contentUrl／thumbnail 为 null；删除条目仍能读取既有固定版本。

预览完成使用独立 `material.preview.changed` 事件，仅失效同版本预览相关查询；用途、删除和正式版本变更仍使用材料业务事件。批量预览不会刷新整个资料库并取消正在加载的下一页。OpenAPI、生成类型与事件映射同步。

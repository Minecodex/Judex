# 职位工作提示词（2026-10-07）

一个人在同一项目可以承担多个职位。设置页的“工作偏好”按本人当前承担的职位提供下拉选择，每个职位独立编辑、保存和清除工作提示词。选择范围由当前有效任职确定，项目创建者也须实际任职；没有职位时显示空状态，不能预存一条项目通用提示词。

## 个人配置与任职

配置键是 `projectId + userId + positionId`，不使用显示名称判断归属。同一个人承担相同职位的多个任职身份共用该人的该职位偏好；不同人、不同职位、不同项目相互独立。替换任职保持业务身份和历史，新任职者读取自己的职位偏好，原任职者的文字不会转交。失去最后一份有效任职后，该职位退出选择列表，服务端拒绝继续修改其提示词。

职位公开职责仍由项目管理者维护。个人工作提示词属于本人，只补充对应职位的工作方法和表达偏好，不改变审批、资料读取权限或正式安排。成员列表的组合提示词预览按所查看身份的职位读取本人配置；任务简报只包含本人在该任务相关职位的偏好。

## 接口与存储

- `GET /projects/{projectId}/me/preferences` 返回 `data.items`。本人每个当前有效职位各有一项 `{positionId, revision, prompt}`；未保存时 revision 为 0、prompt 为空，无任职时返回空数组。
- `PUT` 同一路径接收 `{positionId, expectedRevision, prompt}`，返回该职位更新后的配置。首次保存由 0 变为 1，后续只增加该职位的 revision；保存空字符串清除该职位偏好。
- 仅允许修改本人当前有效任职的本项目职位。跨项目、未任职、失效任职由后端校验。写入使用编辑时的版本，旧页面返回 `VERSION_CONFLICT`，不能在保存前读取新版本再覆盖。
- 提示词上限为 20000 字符，当前值与不可变历史分别存入 `personal_position_preferences`、`position_preference_revisions`，主键包含项目、本人和职位，历史另包含 revision。

Migration 22 将旧项目通用偏好复制到该用户当前实际承担的每个职位，保留这些职位对应的原修订历史，随后移除旧表。复制后的记录分别维护；以后新增任职不会自动继承旧通用提示词。此迁移只调整个人配置，不改变成员、职位、任务和历史消息。

## 草稿与 AI 上下文

职位选择和未提交草稿保存在当前浏览器会话，草稿按项目、userId 和职位隔离；切换职位、返回应用、重新进入设置及刷新可恢复。保存期间禁用选择和编辑，失败保留输入；每个草稿携带读取时的 revision，防止无声覆盖其他页面的更新。

岗位 Agent 每次模型调用按当前 identity 的 `templateId` 与绑定人的 `userId` 精确读取配置，固定该次调用的 preferenceRevision 和 hash。下一次调用重新读取；另一个职位的偏好不能进入该上下文。主 Agent 的目录和共享运行记录不包含私有提示词原文。中英文与深浅色沿用共享 HeroUI 选择、输入和按钮控件。

2026-10-08 的协同界面从“成员与职位”卡片打开本人职位偏好弹窗。弹窗只显示一次标题，职位选择和编辑区占满内容宽度，隐私说明排在表单下方；组件自身持有布局样式，Portal 渲染不依赖设置页的祖先选择器。职位草稿、保存版本与个人可见边界继续按上述规则执行。
